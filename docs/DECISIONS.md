# 技术决策记录（DECISIONS / ADR）

## ADR-001 独立新仓库，参考旧项目只读

**状态**：已采纳
**背景**：`bili-gift-drop` 已有 Bilibili 登录、WebSocket、礼物与多语言实现，但产品目标不同（礼物特效 vs 长期记忆），且不能破坏旧项目。
**决定**：新建 `LiveMemory` 仓库；旧项目克隆到 `.ref/bili-gift-drop`（gitignore），只读参考，不修改、不复制其业务规则。
**后果**：协议实现可借鉴，但必须重新用真实直播验证；文案与 UI 完全独立。

## ADR-002 使用 Node 内置 `node:sqlite`

**状态**：已采纳
**背景**：SQLite 原生模块（better-sqlite3）需要 node-gyp/预编译二进制，会显著增加 Windows 打包与用户机器兼容风险。
**决定**：使用 Node 22.5+ 自带的 `node:sqlite`（同步 API、WAL）。
**后果**：
- 运行时零原生依赖，SEA 打包可直接复用官方 node.exe；
- 仍标记为实验特性，Node 版本必须 ≥ 22.5，启动器显式检查；
- 无 `db.backup()`，M5 用 `VACUUM INTO` 做一致快照。

## ADR-003 Windows EXE 使用 Node SEA + postject

**状态**：已采纳（本机验证）
**背景**：electron-builder 体积大；pkg/nexe 对 ESM 与内置模块支持不稳；原生模块打包复杂。
**决定**：SEA 注入应用资源，bootstrap 解压后调用现有启动器。
**后果**：
- 产物约 90 MB（含完整 Node 运行时）；
- 首次运行需解压 64 个资源文件；
- 需要构建期 postject，固定版本并校验 SHA-256；
- 必须把 PE 子系统改为 Console 才能满足可见命令行需求。

## ADR-004 运行时零依赖、前端无构建

**状态**：已采纳
**背景**：面向长期维护与打包稳定性，避免供应链与构建工具腐烂。
**决定**：不使用 npm 运行时依赖；前端原生 ES Modules + CSS 变量，无打包器。
**后果**：需要自己实现 ZIP、图表、i18n、路由等小工具；换来可审计、可打包、无构建步骤。

## ADR-005 设置存 JSON，业务数据存 SQLite

**状态**：已采纳
**背景**：启动器需要在数据库打开前知道语言偏好；数据库损坏时仍应能显示本地化错误。
**决定**：`config/settings.json`（原子写、校验、损坏备份）保存语言/主题/存储模式/端口；其余全部入库。
**后果**：两处状态源，但职责清晰；语言偏好不会被数据库故障阻塞。

## ADR-006 单一事件写入管线

**状态**：已采纳
**背景**：去重、金额、观众聚合若分散在路由/适配器，极易重复计数。
**决定**：所有事件经 `EventIngest.record()`，单事务内完成插入、身份、聚合、计数。
**后果**：平台适配器只产事件；重复投递天然被唯一键拦截；测试集中在一个入口。

## ADR-007 金额使用整数 minor units + currency + value_kind

**状态**：已采纳
**背景**：浮点会累积误差；礼物“展示价值”与“实际支付”可能不同；多币种不能相加。
**决定**：`amount_minor`、`unit_amount_minor` 为整数；`currency` 为 ISO-4217；`value_kind` 区分 actual/display/unknown；合计表以 `(currency, value_kind)` 为主键。
**后果**：UI 必须分开展示；未知金额不参与合计；未来跨币种展示需要明确换算来源。

## ADR-008 图表使用 Canvas 2D

**状态**：已采纳
**背景**：不引入图表库；需要主题切换即时重绘与 DPR 适配。
**决定**：`src/web/js/chart.js` 自绘面积图，读取 CSS token 颜色，监听主题事件。
**后果**：交互能力有限（无缩放、无多序列）；关键数值同时以文本呈现。

## ADR-009 实时更新使用 SSE 而非 WebSocket

**状态**：已采纳
**背景**：控制台只需要服务器 → 浏览器的单向推送；聚合仍走 HTTP。
**决定**：`/api/events/stream`，事件 `event` 与 `status`，15s 心跳。
**后果**：浏览器断线自动重连；服务端无状态回放，重连后靠 HTTP 重新取摘要。

## ADR-010 前端使用 hash 路由

**状态**：已采纳
**背景**：本地静态服务无服务端路由；刷新不能 404。
**决定**：`#/live`、`#/history/:id` 等；`app.js` 解析并渲染页面模块。
**后果**：URL 不可 SEO（无需）；可直接分享到本机页面；刷新行为稳定。

## ADR-011 自研 STORE ZIP 读写

**状态**：已采纳
**背景**：分析包需要单文件；不想引入 zip 库；备份也需要归档。
**决定**：`src/shared/zip.mjs` 实现 STORE 方法写入与索引/读取，含 CRC32 与路径穿越防护。
**后果**：无压缩（包体积略大）；读取仅支持 STORE（分析包与未来备份均使用 STORE）；需要更多自测（已覆盖）。

## ADR-012 不接入 AI API

**状态**：已采纳（产品原则）
**决定**：只做文件往返，不做任何 AI 网络调用。
**后果**：用户需要手动操作；分析包必须自包含（提示词 + Schema）；导入端必须做严格校验。

## ADR-013 EXE 资源解压到数据目录（失败回退临时目录）

**状态**：已采纳
**背景**：ESM 与静态资源需要从磁盘加载；安装目录可能只读。
**决定**：解压到 `<数据目录>\app\<hash>\`，不可写时回退到用户临时目录。
**后果**：数据目录含应用副本；升级产生新 hash 目录；需在 M8 增加旧目录清理。

## ADR-014 端口动态选择但不回写设置

**状态**：已采纳（可调整）
**背景**：固定端口易冲突；但用户偏好应稳定。
**决定**：优先 `preferredPort`，冲突时 +1…+9，最后系统分配；本轮不回写实际端口。
**后果**：每次启动可能变化；`runtime.json` 与“已在运行”提示使用实际端口。M8 可考虑记住上次成功端口。

## ADR-015 二维码登录在应用内本地渲染（vendored MIT 库）

**状态**：已采纳

**背景**：Bilibili 扫码登录需要把 `qrcode_key` 对应的 URL 编码成二维码展示给手机扫描。初版把该 URL 交给 Bilibili 的外部页面打开，结果在桌面浏览器中跳转并触发下载，登录不可用。

**决定**：
- 采用与参考项目相同的做法：在页面内生成二维码。
- 使用参考项目自带的 `qrcode.js`（MIT，Kazuhiko Arase），复制到 `src/web/js/vendor/` 并保留 `qrcode.LICENSE.txt`。
- 用 `<canvas>` 自行绘制矩阵，不使用 `innerHTML`；不引入 npm 依赖、不调用任何二维码云服务。
- 服务端只提供二维码内容（`/api/bilibili/login/qrcode`）与轮询（`/api/bilibili/login/poll`），不再打开外部页面。

**后果**：
- 前端多一个约 58 KB 的第三方单文件（MIT，已在仓库内），构建时随 `src/` 一起嵌入 EXE；不需要 `npm install`。
- 二维码生成完全离线，符合「本地优先」与 CSP `script-src 'self'`。
- 若未来升级该库，必须保留版权头与许可证文件，并重跑 `tests/unit/bilibili-qr.test.mjs`。

## ADR-016 YouTube 免登录网页聊天只作为显式实验模式

**状态**：已采纳

> **v0.5.0 备注**：本 ADR 的“官方 API 默认 + 匿名 opt-in”部分已被 **ADR-022** 取代。以下保留为历史决策，不代表当前实现；当前只有公开网页路径。

**背景**：

- 普通用户没有 API Key / Google Cloud / OAuth 客户端，官方路径在默认构建中不可用。
- 公开直播网页有一个无需登录的聊天接口，技术上可行；但它是未公开接口，YouTube ToS 禁止自动化访问与收集可识别个人信息。
- 参考项目 `ytmemchat_wails` 采用“空 Key 用无 Key 客户端、填 Key 只用官方”的模式，但它使用 GPL-3.0，不能复制代码。

**决定**：

1. 保留官方 Data API / OAuth 为默认与推荐路径（`youtubeCaptureMode=official`）。
2. 自行实现 Node ESM 匿名适配器，不复制 GPL/AGPL 代码，不引入 Python/新依赖。
3. 匿名路径必须显式 opt-in；UI 显示“非官方接口、可能与 YouTube 服务条款冲突、可能随时失效”。
4. 不发送 Cookie/OAuth/用户 API Key；不绕过登录、验证码、年龄墙、地区限制。
5. 匿名失败时显示真实原因，不静默切换、不伪造成功。
6. 所有事件仍走 EventIngest；匿名 gift 无 Channel ID 时不建档案。

**后果**：

- 技术目标“用户无需配置 Key 即可读取”在点击一次实验模式后成立；
- 但产品不能声称完全合规，正式发布前需要法律/平台评估；
- 匿名接口变化会导致功能失效，必须保留官方路径作为合规替代。

## ADR-017 YouTube 保留上限收紧为 30 天

**状态**：已采纳

**背景**：旧设置允许 3650 天，但文档同时声称遵守 30 天政策；只删除 `content`/`emotes` 也忽略了 badges、金额显示文本与昵称历史。

**决定**：

- `youtubeRawRetentionDays` 只允许 1–30 天，默认 30。
- 清理 `content`、`emotes`、`badges`、`amount_display` 与过期 YouTube 昵称历史/当前昵称。
- 计数、稳定 Channel ID、金额合计保留；明确这不等同于完全删除个人数据。

**后果**：

- 设置值 31–3650 会被拒绝或钳制到 30；
- 旧库升级后首次启动即按新上限清理；
- 长期观众记忆与严格隐私删除之间仍有取舍，后续需要独立的“严格删除/去标识化”功能。

## ADR-018 启动位置记录与 staging 迁移

**状态**：已采纳（v0.4.0）

**背景**：数据目录可移动到其他磁盘，但启动器必须先找到数据库；把路径存在数据库里不可行。Windows 上 SQLite WAL 直接跨目录复制或就地覆盖有数据一致性风险。

**决定**：

1. 使用独立于数据库的 `data-location.json`（`%LOCALAPPDATA%\LiveMemory`，镜像 `%APPDATA%`），只存路径。
2. 启动时位置记录目标必须已存在且含数据库；否则硬错误，不创建空库。
3. 迁移在目标卷的 staging 目录完成复制与验证（WAL checkpoint、integrity_check、表计数、schema、文件 SHA-256），验证通过后才移入目标、更新位置记录、切换运行时。
4. 原目录永不自动删除；失败回滚目录、位置记录与旧运行时。
5. 单实例锁随数据目录转移（`beginLockMove`）。

**后果**：

- 迁移较慢但可验证、可回滚；需要复制空间（源数据 + 50 MB 余量）。
- 目标必须为空（就 LiveMemory 受管目录而言），不支持合并已有数据空间。
- 映射网络盘只能人工判断；UNC 直接拒绝，OneDrive 等云同步目录需要确认。

## ADR-019 平台全局观众身份 + 主播维度互动档案

**状态**：已采纳（v0.4.0，schema v5）

**背景**：同一平台账号可能出现在多个主播直播间；若把聊天/金额/画像无条件合并，会混淆主播上下文；若复制成多个身份，又会错误拆分同一账号。

**决定**：

- 观众主键仍是 `platform:stable_uid`，昵称不参与身份。
- 主播是独立稳定身份（YouTube channelId；Bilibili anchor uid/room fallback；无法确定则 unresolved）。
- 新增 `(viewer_id, broadcaster_id)` 关系与按主播的币种合计；全局 `viewers` 统计保留为 lifetime。
- UI/API 默认以当前主播为范围；跨主播只显式提供概览；AI 包只导出当前主播的 `broadcaster_context`，其他主播仅给数量。

**后果**：

- 统计需要 scope 参数，不能直接把全局 lifetime 当主播画像。
- 旧 YouTube 场次无法确定主播时保留 unresolved，不猜测；需要未来手动归属 UI。
- 关系表增加跨主播链接性风险；保留/删除策略必须与来源政策一致，不能因新增索引绕过 30 天清理。

## ADR-020 两种删除模式、确认文字与数据库快照

**状态**：已采纳（v0.4.0）

**背景**：用户需要清空记录但保留偏好/登录，也需要真正恢复出厂；不可逆操作必须有明确范围与防误触。

**决定**：

- `data`：删业务表 + 导出 + 缓存；保留设置、凭据、位置记录、`backups/`、日志、根目录无关文件。
- `factory`：额外删偏好/凭据/日志/缓存并重置默认设置；仍保留位置记录、`backups/`、无关文件。
- 必须输入 `DELETE` / `RESET`；记录中禁止；服务端二次校验。
- 删除前可选（默认勾选）数据库应急快照：`VACUUM INTO` 到数据目录之外的 `%LOCALAPPDATA%\LiveMemory-Backups`；明确不是 M5 `.livememory`。
- 数据库在事务中删除后 `VACUUM` + checkpoint，再重建运行时。

**后果**：

- 文件删除是尽力而为；极端中断可能留下部分导出/日志，但数据库为空。
- “清空数据”不会退出平台登录；需要清除授权时用“恢复出厂设置”或平台退出。
- 未来 M5 备份必须使用不同格式，不能把应急快照当作可移植备份。

## ADR-021 原生文件夹选择器使用无管道子进程 + 临时结果文件

**状态**：已采纳（v0.5.0）

**背景**：浏览器无法把任意本地绝对路径交给本地服务；旧实现用 `execFile` 捕获 PowerShell stdout，在受限权限/打包环境中因管道创建失败而 `spawn EPERM`，点击「浏览」直接报错。

**决定**：

- 使用 `spawn(powershell, ['-NoProfile','-STA','-EncodedCommand', base64(script)], {stdio:'ignore', windowsHide:true})`。
- 选择结果写入 `<数据目录>/cache/picker-*.txt`，Node 读取后删除；不使用 stdout/stderr 管道。
- 路径与初始目录用 Base64 嵌入脚本，避免中文、空格、引号与命令注入。
- 取消返回 `null`；脚本错误写 `ERROR:`；超时/spawn 失败分别返回稳定错误码，不吞掉。
- 不做浏览器伪选择器，不要求管理员；手动输入保持。

**后果**：选择器不再依赖管道，兼容受限环境；需要临时目录可写与 PowerShell（Windows 自带）。真实人工点击仍需在有桌面环境验证。

## ADR-022 YouTube 只保留公开网页聊天

**状态**：已采纳（v0.5.0，产品决定）

**背景**：官方 Data API/OAuth 需要开发者配置、配额与登录，且与用户“像 Bilibili 一样直接粘贴链接”的目标冲突；双轨实现增加 UI、测试与维护成本。

**决定**：

- 删除官方 Data API 客户端、OAuth/令牌存储、API Key 配置、官方适配器、`capture-mode` 与相关路由/UI/测试。
- 唯一路径为 `src/platforms/youtube/anonymous/` 公开网页聊天；无需 Cookie/OAuth/API Key。
- 不在正常连接界面显示模式选择或大段实验警告；在设置/隐私说明保留简短、真实的“非官方稳定 API、可能失效、无官方授权”说明。
- 不绕过登录/验证码/年龄墙/地区限制；失败不静默切换。
- schema v5、历史数据、稳定身份与 30 天保留不变。

**后果**：YouTube 接入更简单，但依赖未公开页面结构，可能随时失效；合规风险仍需评估。不得偷偷恢复官方双轨。

## ADR-023 发布 EXE 使用 requireAdministrator Manifest

**状态**：已采纳（v0.5.0，产品决定）

**背景**：用户决定 EXE 默认以管理员权限运行，双击时由 Windows 自动 UAC，而不是要求右键“以管理员身份运行”。

**决定**：

- 构建时直接改写 node.exe 的 PE RT_MANIFEST 为 `requireAdministrator`，不依赖外部 mt.exe/rcedit；新 Manifest 必须放入 `.rsrc` 现有 padding，否则构建失败。
- 开发模式 `node` 不请求管理员；启动器只对打包 EXE 做防御性管理员检查。
- UAC 拒绝发生在程序启动前，Windows 直接终止，EXE 无法捕获；文档不得声称能显示拒绝提示。
- 管理员权限不放宽数据目录校验、迁移 staging/回滚、删除范围。
- 打包启动且当前默认目录无数据库时扫描本地用户配置：恰好一个现有库则使用，多个则拒绝猜测并要求 `--data-dir`。

**后果**：同账号 UAC 通常保持 `%LOCALAPPDATA%`；跨管理员账号的 UAC 会切换用户配置，profile 扫描只是防新建空库的兜底。真实 UAC 批准后的完整流程仍需人工验证。
