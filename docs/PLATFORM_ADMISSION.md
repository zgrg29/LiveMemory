# 直播平台准入与验收规范

状态：**长期开发规范（2026-11-16 制定）**。本文是新增平台的唯一准入依据；
任何「已支持某平台」的说法都必须能在此处逐条给出证据。未经验证一律标「待验证」。

相关文档：`AGENTS.md` §6.12、§10；`docs/PLATFORM_INTEGRATIONS.md` §4–§6、§10；
`docs/PLATFORM_EXPANSION_RESEARCH.md`（候选平台调查记录）；
`docs/PLATFORM_RESEARCH_TIKTOK_TWITCH_DOUYIN.md`（历史深度调研）；
`docs/DATA_MODEL.md`（事件与身份模型）；`docs/PRIVACY_SECURITY.md`。

---

## 1. 三个核心准入条件

新增平台必须**同时**满足以下三条。缺一条即不满足准入，不得进入开发，更不得进入发布。

### 条件一：免登录公开采集优先

普通用户只需提供**公开直播间链接 / 房间号 / 主播用户名**即可开始采集。

- ✅ 允许：匿名访客即可获得的公开数据；任何访客都会自动获得的设备 Cookie（例如 TikTok 的匿名 `ttwid`）。
- ❌ 不允许作为必要条件：让用户自己申请开发者应用、配置 Client ID/Secret、购买采集服务、
  签订付费第三方协议、导入账号 Cookie、扫码登录、浏览器中继。
- 若免登录确实不可行，才可评估「用户友好的二维码登录或官方授权」，且必须同时满足 §3 的优先序。
- **不得绕过访问控制**：不破解验证码、不伪造登录态、不规避地区/年龄/权限限制；平台明确拒绝时
  必须停止该路径并如实报告。

### 条件二：必须能取到用户名，尽量取到稳定用户 ID

- **硬性**：每条聊天消息必须能关联到平台实际展示的用户名或昵称。
- **强期望**：能取到平台级稳定用户 ID，用于 `platform:stable_uid` 跨场次长期画像。
- 如果只能取到昵称：
  - 必须在文档与界面中写明「昵称不是身份」；
  - 必须评估昵称变更、重名、身份误判风险；
  - **不得伪造稳定 ID**（不得用昵称 hash 冒充稳定 ID，不得把不同人合并）。
- 参考现有实现：Twitch `user-id`、TikTok `user.id`、抖音 `user.id`、Bilibili UID
  （`buildViewerId()` 已把空值与 `'0'` 视为「无身份」，见 `src/shared/events.mjs:67-74`）。
- **质量门槛**：真实样本中「有稳定 ID 的聊天消息占比」必须测量并记录；
  低于 100% 时必须在文档中给出具体比例，不允许只写「支持稳定 ID」。

### 条件三：必须能实时取得公开聊天消息

- 必须能获取**实际正在进行的直播间**的公开聊天，并尽量保留：
  消息内容、用户名、稳定用户 ID（可得时）、时间信息、消息 ID（可得时）、平台与直播间标识。
- 必须调查并给出结论：断线重连能力、去重依据、多直播间并行采集能力。
- **只接直播**：不得抓取普通视频、视频评论、字幕或历史回放；非直播输入必须明确拒绝。

### 礼物不是准入条件

礼物、打赏、订阅与付费互动属于**可选增强**。

- 能取到更好；取不到**不得**因此否决一个能满足「用户名 + 实时聊天」的平台。
- 取到但没有本币金额时：`amount_minor = null`、`value_kind = unknown`，
  只保存数量/档位/展示文本，**不得换算成主播收入**。
- 未观测到真实礼物事件时，必须标 `NOT-OBSERVED`，不得因为解析代码存在就宣称支持。

> LiveMemory 的核心价值是观众记忆、长期画像、聊天分析与跨场次互动理解，不是礼物流水统计。

## 2. 字段最低要求（canonical event 映射）

新增适配器至少要把下列字段映射进 `src/shared/events.mjs` 的 canonical 事件；
缺失的字段必须显式写 `null` 并在文档中说明，不得用占位值冒充。

| canonical 字段 | 要求 | 缺失时 |
| --- | --- | --- |
| `platform` | 必填，匹配 `/^[a-z0-9][a-z0-9_-]{0,31}$/` | 阻断 |
| `event_type` | `chat` 至少可用 | 阻断 |
| `content` | 原文，**永不翻译** | 阻断 |
| `nickname` | 平台展示名 | 阻断 |
| `platform_uid` | 稳定 ID | 允许缺失 → 该消息 `source_quality=unknown`，不建长期档案 |
| `occurred_at` | epoch 毫秒 | 允许用接收时间但要标注 |
| `platform_message_id` | 消息 ID | 缺失时去重只能退化为「内容+用户+时间」指纹，必须记录风险 |
| `room` / `platform_room_id` | 直播间标识 | 阻断 |
| `emotes` / `badges` | 可靠元数据 | 可缺失 |
| 金额相关 | 见条件「礼物不是准入条件」 | 可缺失 |

其余不可协商的既有纪律（不得为新平台放宽）：

1. 所有事件**只经** `src/platforms/shared/ingest.mjs` 写入；去重靠 `UNIQUE(session_id, dedupe_key)`。
2. 观众主键 `platform:stable_uid`；**昵称不是身份**；不同平台同名不合并。
3. 金额用整数最小货币单位 + `currency` + `value_kind`；不混币种、不混 `value_kind`。
4. 时间统一存 epoch 毫秒。
5. 多直播间隔离：每场独立 adapter/连接状态/session；同一 `platform + room` 不得重复启动。
6. 数据保留：原文按窗口清理（默认/上限 30 天），保留计数、稳定 ID、金额合计；
   并如实说明「保留聚合≠完全删除个人数据」。

## 3. 登录方案优先序

1. **免登录公开直播间采集**（首选，且应是唯一实现路径）。
2. 若免登录确实不可行，才评估**用户友好的二维码登录或官方授权**。
   - 必须由用户主动发起，不得静默登录；
   - 凭据只进本地加密凭据库（`src/platforms/shared/secret-store.mjs`），不进配置 JSON/日志/ZIP；
   - 必须支持「未登录也能采集聊天」，登录只用于增强（如礼物）。
3. 若必须**手动配置开发者密钥**、**购买第三方采集服务**、或**无法合法稳定获取必要数据**：
   **原则上不纳入开发计划。**
4. 任何方案都不得绕过访问控制、验证码或平台安全机制。

## 4. 七阶段门禁（G0–G6）

任何新平台必须顺序通过，前一阶段未通过不得进入下一阶段。
阶段产出必须落到仓库文档，口头结论无效。

| 阶段 | 名称 | 必须产出 | 通过判据 |
| --- | --- | --- | --- |
| **G0** | 技术资料及开源项目调查 | `docs/PLATFORM_EXPANSION_RESEARCH.md` 对应小节 | 项目地址/维护状态/许可证/是否免登录/字段/稳定 ID/重连/技术栈/付费依赖/非官方接口风险全部有结论；**无结论的写「待验证」** |
| **G1** | 免登录采集可行性验证 | 真实连接记录（时间、房间、结果、失败原因） | 用真实公开直播间验证成功；若失败，记录确切拒绝形态（HTTP 码、WS 关闭码、人机验证），**不得用规避手段重试** |
| **G2** | 用户名与弹幕字段验证 | 真实样本字段统计表（条数、有用户名占比、有稳定 ID 占比、有消息 ID 占比、CJK/Emoji 样本） | 文本、用户名、稳定 ID 的可得性有真实比例；不达标则停止或降级为「仅昵称」并接受风险 |
| **G3** | 稳定身份识别能力评估 | 昵称变更/重名/匿名风险的书面评估 | 明确「谁是身份」；不得用昵称 hash 或昵称本身当身份 |
| **G4** | 断线重连与多直播间稳定性测试 | 自动化测试 + 真实长测记录（≥30 分钟、含强制断线、≥2 房间并发） | 断线可恢复、去重有效、房间互相隔离；无法续传的必须标注「重连期间可能漏消息」 |
| **G5** | 真实 EXE 验收 | `scripts/verify-<platform>-exe.mjs` 结果 + 截图/日志摘要 | 真实 `dist/LiveMemory.exe` 上完成采集、状态显示、停止、历史读取 |
| **G6** | 合并与发布最终判断 | `docs/STATUS.md` 记录 + `AGENTS.md` 边界条款（如需） | 三个准入条件与 G1–G5 证据齐备；未验证项以 `NOT-OBSERVED` / `待验证` 明确列出 |

**G0 不通过 = 不写代码。** 允许在 G0 就否决或暂停（见 §6）。

## 5. 证据等级与对外表述口径

沿用 `docs/PLATFORM_INTEGRATIONS.md` §5 的真实性标注：

| 表述 | 允许使用的条件 |
| --- | --- |
| 「已支持 X」 | G5 通过 + 真实 EXE 验收记录在 STATUS |
| 「X 实验性 / 非官方协议」 | G1–G4 通过但依赖非官方接口，或其稳定性未长期验证 |
| 「待验证」 | 只有文档/README/示例，没有本仓库真实样本 |
| 「NOT-OBSERVED」 | 解析代码存在但未观测到真实事件（典型：礼物、订阅） |
| 「BLOCKED」 | 真实尝试后平台拒绝且无合规路径 |

硬性禁止：

- 不得仅凭 GitHub README 或示例断言「支持」。
- 不得把 Mock/模拟测试通过写成「真实平台接入完成」。
- 不得把「函数存在」写成「已获取到真实数据」。
- 依赖非官方接口时必须**同时**标注「非官方 / 实验性 / 可能失效」，不得描述为官方授权或合规。

## 6. 暂停与否决条件

命中任一条即可暂停该平台，并继续调查后续候选——**不为了增加平台数量而降低标准**。

1. 免登录不可行，且扫码/官方授权也不可行。
2. 需要用户自备开发者密钥、购买第三方服务或付费签名。
3. 无法取得用户名。
4. 无法实时取得公开聊天。
5. 唯一可行路径需要绕过访问控制、验证码或安全机制。
6. 许可证不兼容（见 §7），或依赖无许可证/来源不明的仓库。
7. 只有已归档/多年未更新的实现，且协议明显已变化，自研风险与收益不匹配。
8. 平台条款明确禁止此类采集，且无合规替代。

**暂停 ≠ 删除调查记录。** 必须在调查文档中保留结论、证据与重新评估的触发条件。

## 7. 开源组件与许可证策略

LiveMemory 自身 **MIT**；保持免费、公开源代码，允许主播商业使用；运行时**零依赖**。

### 7.1 可用

| 许可证 | 可否参考/集成 | 义务 |
| --- | --- | --- |
| MIT / ISC / BSD-2 / BSD-3 | 可以（参考实现或内联） | 保留版权与许可声明；在 `THIRD_PARTY_NOTICES.md` 记录 |
| Apache-2.0 | 可以 | 保留 NOTICE/许可证；标注修改 |
| 无许可证 | **禁止** | — |

### 7.2 AGPL-3.0（有条件）

可以**阅读研究**，可以作为协议参考，也可以在明确接受义务时集成，但必须：

1. 在 `THIRD_PARTY_NOTICES.md` 与 `docs/LICENSE_AGPL_<组件>.md` 中写明组件、版本、许可证；
2. 若代码/二进制被打进 EXE，按 AGPL-3.0 提供对应源代码（现有抖音签名组件已按此处理）；
3. **不得直接复制不兼容代码**到 MIT 代码区；不得把 AGPL 代码改写成「看起来是自己写的」；
4. 集成前必须评估对整体分发方式的影响（是否触发对 LiveMemory 整体的 AGPL 义务）。

### 7.3 其他硬性要求

- **不得依赖付费服务**作为采集必要条件。
- **不得引入运行时 npm 依赖**（会破坏零依赖与打包方式）；开源项目只作协议参考，用自有代码重写。
- 必须记录：项目是否使用非官方接口、最近提交时间、Issue 中是否报告「已失效/漏消息」。
- 参考别人实现时，**只借鉴协议事实，不照抄代码结构**；若确实复用片段，按其许可证标注。

## 8. 每个新平台的交付物清单（模板）

完成一个平台（到 G6）至少产生：

1. `src/platforms/<platform>/`：`link.mjs`（URL/ID 解析）、`client.mjs`（传输）、
   `messages.mjs` 或 `mapper.mjs`（翻译成 canonical event）、`adapter.mjs`、`service.mjs`、`errors.mjs`。
2. `src/server/routes.mjs`：连接/检查/停止路由；`/api/bootstrap` 的 `capabilities.platforms` 条目
   （含 `requiresLogin`、`unofficial` 等真实标记）。
3. `src/monitoring/constants.mjs` 的 `MONITOR_PLATFORMS` 与对应 detector（若支持自动开播监听）。
4. `src/web/js/pages/live.js` + 全部语言字典（`common.platform.*`、`live.source.*`、`errors.*`、`monitoring.*`）。
5. `tests/unit/<platform>*.test.mjs` + 真实样本夹具；`tests/integration` 路由/ingest 覆盖。
6. `scripts/verify-<platform>-exe.mjs`（真实 EXE 验收）。
7. `docs/PLATFORM_INTEGRATIONS.md` 新增一节（接入边界、连接流程、身份、金额、保留、验证状态）。
8. `docs/STATUS.md` / `docs/HANDOFF.md` / `log/<日期>-<主题>.md` 记录真实结果与 `NOT-OBSERVED`。
9. `scripts/build-windows.mjs` 的 `REQUIRED_MODULES`（新平台的必需模块必须进清单，否则打包失败应显式报错）。

## 9. 与其他规范的关系

- 本规范**不重复** `AGENTS.md` 的工程纪律，只补充平台侧门禁；冲突时以 `AGENTS.md` 为准。
- 本规范**不放宽**任何既有边界：不绕过访问控制、不登录、不依赖第三方签名服务、
  标注非官方/实验性、失败即如实报告（见 `AGENTS.md` §6.12、§10）。
- 数据保留与隐私要求见 `docs/PRIVACY_SECURITY.md`；数据库与身份模型见 `docs/DATA_MODEL.md`。
