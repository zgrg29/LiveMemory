# 国际化（i18n）架构与十语言实施规划

状态：**规划文档（2026-11-16）**。本轮只做调查与规划，**没有新增任何语言、没有修改业务代码**。
当前真实实现仍是三种语言（`zh-CN` / `ja` / `en`）。本文中的「目标十语言」是待开发目标，
不得据此在 README、界面或 `docs/STATUS.md` 中宣称已支持。

相关文档：`AGENTS.md` §6.9、§7；`docs/STATUS.md`；`docs/ROADMAP.md`（P38–P41）；
`docs/ARCHITECTURE.md` §1.8；`docs/AI_CONTRACT.md` §20；`docs/UI_DESIGN.md`；
`docs/PLATFORM_ADMISSION.md`（平台侧，与本轮另一条主线）。

## 1. 三层语言模型（本文的核心约束）

国际化必须把三件互相独立的事分开。任何实现都不得把三者混成一个「语言」开关。

| 层面 | 含义 | 存储位置 | 谁决定 | 是否可随界面语言变化 |
| --- | --- | --- | --- | --- |
| **L1 软件界面语言** | 主界面、菜单、按钮、设置、平台连接、AI 控制台、错误提示、使用说明 | `config/settings.json` 的 `locale`（`system` + 受支持语言码） | 用户（默认跟随系统） | 是，随时可切 |
| **L2 AI 分析输出语言** | 单场报告、长期画像的自然语言字段 | 任务创建时快照进 `ai_jobs.locale` / 记忆任务 `locale` | 用户（当前默认 = 界面语言） | **否**，任务内不可变；历史结果由翻译缓存按需切换阅读，原文不被改写 |
| **L3 原始弹幕语言** | 观众发送的原文 | `events.content`（原文）、`events.emotes`（平台表情元数据） | 观众 | **否**，永久原文，禁止翻译覆盖 |

三条不变式（后续任何里程碑都必须满足）：

1. **L1 ≠ L2**：用户可以使用韩语界面 + 日语分析报告。L2 必须是独立持久偏好，不能只是
   「拿界面语言当默认值再用一次」。
2. **L2 快照不可变**：任务一旦创建，`locale` 写入任务行；暂停、继续、重启、升级、切换界面语言
   都不得改变该任务的语言，也不得重写已保存结果的正文。
3. **L3 永不改写**：任何语言功能都不得把 `content` 替换成译文。翻译只能是「展示层附加」，
   且必须与原文分表存放（现有 `ai_translations` 已符合）。

## 2. 当前实现真实情况（2026-11-16 实测）

本节全部结论来自读代码与实测，不是推测。

### 2.2 启动器控制台语言

- 独立于网页语言：默认英文，`--lang zh-CN|ja|en` 覆盖（`src/launcher/launcher.mjs:138` 起）。
- 文案表 `MESSAGES` 三语，键集由测试强制一致（`src/launcher/cli-i18n.mjs`，
  校验见 `tests/unit/i18n.test.mjs:48-59`）。
- **Windows 控制台编码是真实约束**：`enableUtf8Console()` 执行 `chcp 65001`；
  返回 `not-tty` / `chcp-failed` 时 `unicode=false`，控制台降级为 ASCII 文案
  （`src/launcher/console.mjs:13-24`，`launcher.mjs:217-225`）。新增语言必须复用该降级路径。

### 2.3 AI 输出语言（L2）

| 环节 | 当前实现 | 位置 |
| --- | --- | --- |
| 默认值 | **`let locale = ctx.locale`** —— 默认等于当前界面语言 | `src/web/js/pages/ai.js:198` |
| 用户可选 | AI 中心有独立下拉框（3 个硬编码 `<option>`），随请求发送 | `ai.js:220-224,1332-1338` |
| 服务端解析 | `normalizeLocale(body.locale) \|\| resolveLocale(settings.locale, systemLocale)` | `routes.mjs:1632` |
| 快照落库 | 写入 `ai_jobs.locale`（Session 与 Memory 两个 Job 同 locale） | `routes.mjs:1634-1641`；`src/storage/repositories/ai-jobs.mjs` |
| 记忆任务 | `POST /api/memory/jobs` 同样解析并写入记忆任务 `locale` | `routes.mjs:1936-1946` |
| 任务内不变 | 状态返回 `job.locale`；Resume 复用已存任务 | `src/ai/api/runner.mjs:1690,1849` |
| 提示词分语言 | `SYSTEM[locale]`、`MEMORY_LANGUAGE_RULE[locale]`、`TEXT[locale]`、`MEMORY_SHAPE_TEXT[locale]` 均只有 3 个键 | `src/ai/api/prompts.mjs:108,146-150`；`src/ai/prompts/split.mjs:282-298,342` |
| 提示词版本 | `promptVersionFor(locale, mode)` → `lm-prompt-…-zh-CN` / `-ja` / `-en` | `src/ai/prompts/split.mjs` |
| 报告阅读语言 | `GET /api/ai/sessions/:id/report?locale=…` 只读、只应用缓存、绝不调用 Provider | `routes.mjs:1749-1760` |
| 翻译执行 | `POST /api/ai/sessions/:id/translation`，独立 `ai_translations` / `ai_translation_runs` | `src/ai/translation/service.mjs` |
| 翻译目标语言名 | `LOCALE_NAME` 只有 3 个键 | `src/ai/translation/service.mjs` |
| 不翻译字段 | `viewer_id`、`topic`、事实 ID/状态/certainty/证据/时间/金额/枚举/原始聊天 | `src/ai/translation/fields.mjs` |

**结论：L2 与 L1 目前是「默认耦合、单次可覆盖、但无独立持久偏好」的状态。**
不存在 `aiOutputLocale` 一类设置项。关掉页面重开，AI 中心的语言下拉会重置回界面语言。
这是本轮需求「必须独立」的主要差距。

### 2.4 原始弹幕（L3）

- `events.content` 保存原文；`src/shared/text.mjs` 只做安全截断，不做翻译。
- 表情：Unicode Emoji 原样保留；平台表情只在有可靠元数据时写 `emotes`，不下载图片（`chat.js` 除外，它只是画布）。
- 提示词明确要求：中文/日文/英文/混合语聊天「直接理解语义，不要逐行预翻译」
  （`src/ai/prompts/split.mjs:169,205`；`src/memory/prompt.mjs:297`
  「Keep the original language: mixed Chinese/Japanese/English stays as written, never translated」）。
- 因此 **L3 当前是合规的，不需要为新增语言做任何数据结构改动**；需要的是
  多语言混合样本的验收证据。

### 2.5 用户可见文字是否还有硬编码

对 `src/web/**/*.{js,html,mjs}` 做 CJK 正则扫描，命中仅 5 行：

| 位置 | 内容 | 判定 |
| --- | --- | --- |
| `src/web/js/i18n.js:42-43` | `'简体中文'`、`'日本語'` | **有意保留**：语言名必须以自身文字显示 |
| `src/web/js/pages/ai.js:318-320,482` | 中文**代码注释** | 非用户可见 |
| `src/web/index.html` | 十余处英文静态回退文案（导航、状态、提示）+ 8 处英文 `aria-label` | 水合前回退；`aria-label` 运行时由 `a11y.*` 覆盖，可接受 |

**所以「界面文案硬编码」不是本轮的主要债务。** 真正的债务在四处，且都不在
`src/web/i18n/*.json` 里：

1. `src/ai/prompts/*` 与 `src/ai/api/prompts.mjs` 的三语提示词文本（每语言约数千行规则）。
2. `src/launcher/cli-i18n.mjs` 的控制台词条（约 60 条/语言）。
3. 平台技术详情字符串（连接状态 `detail`、诊断行、TikTok/抖音/YouTube 抓取统计等）
   多为拼接式英文片段，见 §2.6。
4. `src/ai/translation/service.mjs` 的翻译系统提示词（英文元指令 + 目标语言名表）。

### 2.6 日期、数字、时间与错误

| 类别 | 现状 | 风险 |
| --- | --- | --- |
| 日期/时间 | 全部走 `Intl.DateTimeFormat(locale, …)`，`locale` 取 `ctx.locale` | 低。新增语言由 `Intl` 自动覆盖，但需检查 `dateStyle:'medium'` 在各语言下的长度 |
| 数字/金额 | `Intl.NumberFormat`；金额用最小货币单位整数 + 币种 | 低。需补 `pt-BR`（`1.234,56`）与 `de`/`es`/`fr`（空格/逗号）的视觉回归 |
| 字节/百分比 | `formatBytes` / `formatDecimal` 走 `Intl` | 低 |
| 错误提示 | 服务端只回 `messageKey`（如 `errors.roomNotFound`），前端 `t()` 渲染；`errors.*` 当前 216 处 | 低但有量：新增 7 语言 = 216×7 条错误文案 |
| 平台原始错误 | `detail` 里常含英文平台返回片段 | 中。需要「本地化外层说明 + 原文技术详情折叠」的统一规则 |

### 2.7 布局与截断风险（真实存在）

| 证据 | 位置 | 影响 |
| --- | --- | --- |
| `.language-select { max-width: 132px }` | `src/web/styles/components.css:665` | Header 语言选择器宽度写死。`Português (Brasil)`、`Bahasa Indonesia`、`繁體中文` 会被裁切 |
| 宽屏三段按钮 `LANGUAGE_CHOICES` 只有 3 项 | `src/web/js/app.js:39,276` | 10 语言无法用「三段 + 地球」表达，必须改为菜单/下拉 |
| `white-space: nowrap` 25 处、`text-overflow` 13 处 | `styles/*.css` | 德语/西语/法语通常比英文长 30–60%，按钮与胶囊标签存在溢出风险 |
| 固定小宽度标签 `max-width: 112px / 132px / 145px / 260px` | `components.css:665,708`；`pages.css:380,437` | 直播间标签、能力胶囊、统计标签最易被截断 |

结论：**「固定宽度导致翻译被截断」不是假设，是已存在的具体 CSS 约束**，
十语言验收必须把它们纳入检查项（M-I18N-1 修复、M-I18N-3 验收）。

### 2.8 Windows EXE 字体与 Unicode

| 层面 | 结论 |
| --- | --- |
| 网页界面 | 由用户本机浏览器渲染，字体来自系统字体栈；`<meta charset="utf-8">` 已声明；JSON 以 `application/json; charset=utf-8` 下发。韩文/西里尔/带音符拉丁字母在 Windows 10/11 默认字体均可用 |
| 启动器控制台 | 依赖 `chcp 65001` 成功；失败时降级 ASCII。**这是唯一真实的 EXE 级 Unicode 风险点** |
| 弹窗/诊断 | `native-dialog.mjs` 与 `diagnostics.mjs` 以 base64 UTF-8 传值给 PowerShell，无编码歧义 |
| 数据 | SQLite TEXT 存储 UTF-8；`emoji`/表情元数据按原文保存 |

需要注意的不确定性（未验证）：不同 Windows 版本/终端宿主（Windows Terminal vs 传统 conhost、
是否有 CJK 字体包）下 `chcp 65001` 的实际效果与字形覆盖。**未在真实机器上按语言逐一验证过**，
因此 M-I18N-3 必须包含「真实 EXE 逐语言启动 + 控制台字符检查」，不能仅凭代码判断。

### 2.9 兼容性：新增语言不得破坏旧配置与历史数据

已确认的兼容事实：

1. `config/settings.json` 的 `locale` 只会被写入受支持值；旧值 `zh-CN`/`ja`/`en` 语义不变，**不需要迁移**。
2. `ai_jobs.locale`、记忆任务 `locale`、`ai_translations.target_locale`、
   `ai_results.locale` 都是自由 TEXT 列，新增语言码不会与旧行冲突。
3. 历史报告正文不会被界面语言影响（原文 + 翻译缓存分离）。
4. 备份/恢复设置白名单是**显式枚举**（`src/server/backup/settings.mjs:15` 只有 `locale`）。
   **新增任何语言设置键，必须同步该白名单**，否则备份/恢复会静默丢失该设置。

已知的真实风险（必须在本轮之后解决，不能假装不存在）：

> **长期画像的合并键是语言相关的文本。**
> `dedupeKeyFor({kind, topic, statement})` = `kind:normalizeTopic(topic)`，
> `normalizeTopic()` 只做 NFKC/小写/去标点，**不做翻译**（`src/memory/model.mjs:47-76`）。
> 因此同一观众同一兴趣，若前一次用中文输出（`吉他`）、后一次用英文输出（`guitar`），
> 会得到两个不同的 `dedupe_key`，在「只有一条 live 事实」的唯一索引下并存，
> 表现为**重复事实 + 时间线语言混杂**。`memory_facts` 表没有 `locale` 列
> （只有 `source_job_id` 可回溯），所以事后也难自动归并。

## 3. 目标语言表与代码规范

| 语言 | 计划代码 | 现在 | 说明 |
| --- | --- | --- | --- |
| 简体中文 | `zh-CN` | 已实现 | 保持现有代码不变 |
| 英语 | `en` | 已实现 | 回退语言 |
| 日语 | `ja` | 已实现 | 保持 |
| 韩语 | `ko` | 计划 | |
| 西班牙语 | `es` | 计划 | 建议先只做 `es`（通用西语），`es-419`/`es-MX` 不拆 |
| 巴西葡萄牙语 | `pt-BR` | 计划 | 只做 `pt-BR`，不新增 `pt-PT` |
| 繁体中文 | `zh-TW` | 计划 | 需新增 `zh-*` 归一化分支，见下 |
| 法语 | `fr` | 计划 | |
| 德语 | `de` | 计划 | 文本最长，布局压力最大 |
| 印尼语 | `id` | 计划 | BCP-47 正码是 `id`；旧 `in` 需作为别名接受 |

**语言码规则（必须写进实现）：**

1. 一律 BCP-47、大小写规范（语言小写、区域大写：`pt-BR`、`zh-TW`）。
2. 归一化必须是「**可用集合驱动**」，不能写死映射到某一种中文：
   - `zh` / `zh-CN` / `zh-Hans` / `zh-SG` → `zh-CN`
   - `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` → `zh-TW`
   - `pt` / `pt-PT`（无 `pt-PT` 时）/ `pt-BR` → `pt-BR`
   - `id` / `in` → `id`
   - `ko` / `ko-KR` → `ko`；`es` / `es-*` → `es`；`fr` / `fr-*` → `fr`；`de` / `de-*` → `de`
   - 其余 → `null`（再由调用方回退 `system` → `en`）
3. **先在数据层判定可用性，再决定回退**：`zh-TW` 字典未落地前，`zh-HK` 系统必须仍然回退到
   `zh-CN`，不得出现「语言切到繁体但字典 404 白屏」。实现方式：`resolveLocale()` 接一个
   `available` 集合参数，逐级降级（`zh-HK`→`zh-TW`→`zh-CN`→`en`）。
4. 旧配置值不需要迁移；`system` 语义不变。

## 4. 技术调查结论（对应本轮要求的 8 个问题）

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 界面翻译资源如何组织 | 扁平点路径 JSON，`t('a.b.c', {name})` 插值；三份字典键集/占位符由 `tests/unit/i18n.test.mjs` 强制一致。**结构可继续扩展，无需重构** |
| 2 | 哪些用户可见文字仍硬编码 | 网页几乎为零（仅语言自身名称）；真正未国际化的部分是 AI 提示词、启动器控制台、平台技术详情与翻译系统提示词 |
| 3 | 是否存在语言配置与 AI 输出语言耦合 | **存在**：AI 输出语言默认取界面语言，且没有独立持久设置；单次任务可覆盖并正确快照 |
| 4 | Windows EXE 字体与 Unicode 能力 | 网页侧由浏览器系统字体保证；启动器依赖 `chcp 65001`，失败降级 ASCII。**未按语言逐一实测**，列为 M-I18N-3 必验项 |
| 5 | 是否存在固定宽度导致截断 | **存在**：Header 语言选择器 `max-width:132px`、宽屏三段按钮仅容 3 项、25 处 `nowrap`、多处 112–260px 标签宽度 |
| 6 | 日期/数字/时间/错误是否需要本地化 | 日期与数字已走 `Intl`（低风险，需视觉回归）；错误已走 `messageKey`（机制就绪，量是 216×新增语言数） |
| 7 | 新增语言后如何保持旧配置与历史数据兼容 | 设置/任务/翻译列均为自由 TEXT，无需迁移；**唯一必须同步的是备份设置白名单**；`zh-*` 归一化需可用性降级，避免旧行为突变为白屏 |
| 8 | 如何用 AI 辅助翻译并做术语/占位符/完整性检查 | 见 §6：以 `en.json` 为源、逐键机翻 + 术语表 + 机器门禁（键集/占位符/空串/长度比）+ 人工抽检；禁止整文件自由发挥 |

## 5. 分阶段里程碑

每个里程碑都写明前置条件、范围、完成标准与主要风险。**未满足完成标准不得推进下一阶段。**

### M-I18N-0：国际化架构整理（无新增语言）

## 6. AI 辅助翻译流程（可执行规范）

### 6.1 术语表（先定，再翻译）

必须在开始翻译前维护 `docs/i18n/GLOSSARY.md`（M-I18N-1 首个交付物），至少覆盖：

- 产品名：`LiveMemory`（不翻译，任何语言都保留英文）
- 平台名：`Bilibili` / `YouTube` / `Twitch` / `抖音` / `TikTok`（按各平台官方本地写法；不音译）
- 核心概念固定译法（逐语言给一列）：直播、场次、弹幕/聊天、观众、稳定 ID、长期画像、
  单场报告、AI 分析中心、Provider、API Key、批次、证据、事实、置信度、`stated`/`inferred`/`uncertain`
- **不翻译**：JSON 键名、枚举值、错误码、平台字段名、货币代码、`platform:uid` 形式、
  命令与路径、`--lang` 等 CLI 选项
- 语气规范：与现有三语保持一致（克制、客观、不营销、不使用感叹号堆叠）

### 6.2 翻译执行方式

1. **以 `en.json` 为源**（键集参考基准），逐键批处理；每批 ≤ 200 键，避免上下文漂移。
2. 只翻译**值**，不改键名、不改键顺序、不改 JSON 结构；不新增/删除键。
3. 占位符 `{name}` 原样保留，禁止翻译占位符内部、禁止改变大小写。
4. 含 HTML/标记的字符串（如有）原样保留标签。
5. 长句优先「按语言重写」而不是直译；但**不得改变事实含义**（例如「可能漏消息」不能译成「不丢消息」）。
6. 每条翻译记录来源批次，便于回溯（放在翻译工作分支的提交信息里，不写进 JSON）。

### 6.3 机器门禁（必须作为测试存在）

`tests/unit/i18n.test.mjs` 扩展为对**清单内所有语言**执行：

| 门禁 | 判定 | 失败即阻断 |
| --- | --- | --- |
| 键集完全一致 | 相对 `en.json` 缺失 0、多余 0 | 是 |
| 占位符一致 | 每键 `{param}` 集合完全相同 | 是 |
| 非空 | `value.trim().length > 0` | 是 |
| 类型 | 全部为 string | 是 |
| 残留英文检测 | 除白名单（品牌/平台/技术标识）外，非英文语言不得整键等于英文源值 | 是（允许显式白名单条目） |
| 长度预算 | 相对英文长度比 ≤ 1.9（按钮/胶囊类键更严，需单独列出短键白名单） | 警告→阻断（对短键） |
| 未解析键渲染 | 真实字典渲染页面后不得出现 `xx.yy.zz` 形态的原始键 | 是（现有 help/AI 测试已有同类断言，扩展到全部页面） |
| 控制台词条 | `cli-i18n` 键集与占位符一致 | 是 |

### 6.4 人工审校清单（逐语言）

- 术语与 §6.1 一致；同一概念全文同一译法。
- 语法性别/敬语一致（`es`/`fr`/`de`/`pt-BR` 尤其注意）。
- 数字/货币/日期读起来自然（`10.000 Zuschauer` vs `10,000 viewers`）。
- `zh-TW` 使用台湾用语与用字，不是简体转码。
- `id` 使用印尼语标准词（bukan Melayu 变体）。
- 无「机翻味」长句；无中英混排残留。
- 界面实际渲染无截断/无换行破坏（截图对比）。
