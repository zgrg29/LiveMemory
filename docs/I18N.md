# 国际化（i18n）架构与十语言实施

状态：**已随 LiveMemory v0.15.0 正式发布（2026-11-17）**。
P39（注册表/降级）、P40（十语言界面/启动器）、P41（十语言 AI 输出/独立设置）、P42（真实 Provider/EXE/回归验收）全部完成并合并到 `main`。
产品现在**真正支持十种界面语言与十种 AI 输出语言**：`zh-CN` / `ja` / `en` / `ko` / `es` / `pt-BR` / `zh-TW` / `fr` / `de` / `id`。
十份字典各 **2,373** 个叶子键（v0.18.0 发布时为 2,351；本次 Provider 保存诊断新增 22 键为 2,373。v0.15.0 发布时为 2,271，v0.16.0 Kick 新增 33 键为 2,304，v0.17.0 快手预览新增 47 键为 2,351），键集与占位符零差异；Header、设置页、启动器控制台均可选、可保存、可加载。

AI 分析、单场报告、长期画像、报告阅读翻译与任务恢复都支持这十种语言。
**界面语言（L1）与 AI 输出语言（L2）是两个独立持久设置**：`locale` 决定界面，`aiOutputLocale`
（默认 `follow-ui`）决定**新任务**的输出语言；任务创建时语言写入 `ai_jobs.locale` 快照，
之后切换界面语言、修改默认 AI 语言、暂停、重启都不会改变该任务。`aiOutput` 能力位仍是唯一的
能力门禁：没有提示词的语言永远不会被发送给 Provider。

相关文档：`AGENTS.md` §6.16、§7；`docs/i18n/GLOSSARY.md`（翻译与术语的唯一依据）；
`docs/STATUS.md` §0.49；`docs/ROADMAP.md` P39–P42；`docs/ARCHITECTURE.md` §8、§10.1；
`docs/AI_CONTRACT.md` §20；`docs/UI_DESIGN.md`。

## 1. 三层语言模型（长期不变式）

国际化必须把三件互相独立的事分开。任何实现都不得把三者混成一个「语言」开关。

| 层面 | 含义 | 存储位置 | 谁决定 | 是否可随界面语言变化 |
| --- | --- | --- | --- | --- |
| **L1 软件界面语言** | 主界面、菜单、按钮、设置、平台连接、AI 控制台、错误提示、使用说明 | `config/settings.json` 的 `locale`（`system` + 受支持语言码） | 用户（默认跟随系统） | 是，随时可切 |
| **L2 AI 分析输出语言** | 单场报告、长期画像的自然语言字段 | `config/settings.json` 的 `aiOutputLocale`（`follow-ui` 或语言码）；任务创建时快照进 `ai_jobs.locale` / 记忆任务 `locale` | 用户（默认 `follow-ui`） | **偏好**可按 `follow-ui` 跟随；**已创建任务**永不跟随 |
| **L3 原始弹幕语言** | 观众发送的原文 | `events.content`（原文）、`events.emotes`（平台表情元数据） | 观众 | **否**，永久原文，禁止翻译覆盖 |

三条不变式（后续任何里程碑都必须满足）：

1. **L1 ≠ L2**：用户可以使用韩语界面 + 日语分析报告。L2 必须是独立持久偏好，不能只是
   「拿界面语言当默认值再用一次」。
2. **L2 快照不可变**：任务一旦创建，`locale` 写入任务行；暂停、继续、重启、升级、切换界面语言
   都不得改变该任务的语言，也不得重写已保存结果的正文。
3. **L3 永不改写**：任何语言功能都不得把 `content` 替换成译文。翻译只能是「展示层附加」，
   且必须与原文分表存放（现有 `ai_translations` 已符合）。

## 2. P39 之后的真实实现（2026-11-16 实测）

### 2.1 单一语言清单

唯一可信来源：**`src/shared/locales.mjs`**。它是同构模块，Node 与浏览器引用同一份文件
（浏览器通过 `/shared/locales.mjs` 静态路由，服务端只暴露这一个共享模块）。

```js
LOCALE_REGISTRY = [
  {code: 'zh-CN', nativeName: '简体中文', englishName: 'Simplified Chinese',
   language: 'zh', script: 'Hans', regions: ['CN','SG','MY'], available: true},
  {code: 'ja',    nativeName: '日本語',   englishName: 'Japanese',
   language: 'ja', script: null,   regions: ['JP'],        available: true},
  {code: 'en',    nativeName: 'English',  englishName: 'English',
   language: 'en', script: null,   regions: ['US','GB','AU','CA','NZ','IE'], available: true}
]
```

- `AVAILABLE_LOCALES` = 声明为 available 的语言码，按选择器顺序。
- `DEFAULT_LOCALE = 'en'`。
- 注册表只列**真实随产品发布**的语言；计划语言不得提前加入 `available: true`。
- 原生语言名只在这里维护。`src/web/i18n/*.json` 里的 `settings.language.*` 仍保留为界面文案，
  但测试逐语言断言它们与注册表完全一致。
- 别名表只包含 BCP-47 旧码（`in`→`id`、`iw`→`he`、`ji`→`yi`），不是语言清单。

所有使用者都从这一来源派生：

| 使用点 | 位置 | 用法 |
| --- | --- | --- |
| 浏览器字典加载 / 原生名 | `src/web/js/i18n.js` | 直接 import 共享模块；不再有第二份 `SUPPORTED_LOCALES` |
| 旧接口兼容 | `src/shared/locale.mjs` | 重导出 `SUPPORTED_LOCALES = AVAILABLE_LOCALES` 并保留原有函数签名 |
| 服务端生效语言 | `src/server/routes.mjs` | `resolveLocale(..., {available})`；`/api/bootstrap` 返回 `locales` |
| 实际已安装资源 | `src/server/locale-resources.mjs` | 检查 `src/web/i18n/<code>.json` 是否存在 |
| Header 选择器 | `src/web/js/language-control.js` | 由 `bootstrap.locales.available` 生成，无固定三项 |
| 设置页语言卡 | `src/web/js/pages/settings.js` | 由同一列表生成 |
| AI 输出语言下拉 | `src/web/js/pages/ai.js` | 由同一列表生成 |
| 报告阅读语言 | `src/web/js/pages/ai-report.js` | 由同一列表生成 |
| AI 分析支持的 locale | `src/ai/constants.mjs` | `SUPPORTED_LOCALES` 从共享注册表导入 |
| 长期画像 locale | `src/memory/constants.mjs` | `SUPPORTED_MEMORY_LOCALES` 从共享注册表导入 |
| 翻译目标语言名 | `src/ai/translation/service.mjs` | `LOCALE_NAME` 由 `LOCALE_REGISTRY` 生成，输出格式不变 |
| 结果 JSON Schema | `src/ai/schemas/*.json`、`src/memory/schemas/*.json` | **协议产物镜像**；`tests/unit/locale-registry.test.mjs` 断言其 `enum` 与注册表一致 |

> JSON Schema 是给外部 AI 的静态协议文件，不能 import JS；它被明确视为「注册表的协议镜像」，
> 由测试强制同步，不是第二份可独立维护的语言清单。

### 2.2 语言解析与降级规则

解析分成三层，互不覆盖：

1. **用户偏好**：`settings.locale`，取值 `system` 或注册表内的语言码；由 `normalizeLocalePreference()` 校验。
2. **系统检测**：`detectSystemLocale()` 读取 `LC_ALL` / `LC_MESSAGES` / `LANG`，再回退
   `Intl.DateTimeFormat().resolvedOptions().locale`；只用于解析 `system`，从不写回设置。
3. **实际资源**：`resolveLocale(preference, systemLocale, {available})` 返回一个**已安装**的语言。
   若偏好语言存在但字典缺失，按语言族降级；若系统语言不在支持集合内，降级到默认语言。

`resolveLocaleTag(value, {available})` 的匹配顺序：

1. 规范化 tag（大小写、`_`→`-`、去掉 `.UTF-8`/`@modifier`、旧码别名）。
2. 精确匹配 `code`。
3. 同语言族匹配：优先 region 命中，其次 script 命中（`zh-HK` 推得 `Hant`），再取注册表顺序中
   第一个同族资源。
4. 没有同族资源 → `null`，调用方回退 `defaultLocaleFor(available)`（默认 `en`）。

已实测的降级矩阵：

| 输入 | 当前资源（`zh-CN`/`ja`/`en`） | 未来有 `zh-TW` 资源时 |
| --- | --- | --- |
| `zh-CN` / `zh-Hans` / `zh-SG` / `zh-MY` | `zh-CN` | `zh-CN` |
| `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` | **`zh-CN`（安全降级）** | **`zh-TW`（优先）** |
| `ja` / `ja-JP` | `ja` | `ja` |
| `en` / `en-US` / `en-GB` | `en` | `en` |
| `pt` / `pt-PT`（有 `pt-BR` 时） | 无 pt 资源 → `en` | `pt-BR` |
| `in` / `in-ID`（有 `id` 时） | 无 id 资源 → `en` | `id` |
| `fr-FR` / `de-DE` / 未知 | `null` → 默认 `en` | 未新增前仍 `en` |

**关键区别**：`zh-TW` 不是「永久映射到 `zh-CN`」。当字典与注册表条目落地后，同一套解析逻辑
自动优先选择 `zh-TW`；`zh-HK` 等地区变体由 script 推断命中它，无需再改归一化代码。

### 2.3 资源不存在 / 加载失败

- 服务端启动时用 `detectInstalledLocales(webRoot)` 检查真实字典文件；缺失的语言不会出现在
  `/api/bootstrap` 的可选项中，生效语言自动降级。
- 浏览器 `loadDictionary(locale)`：目标字典 404/损坏时，回退默认字典一次；默认字典也失败时
  抛出错误，由既有启动失败页显示本地化说明，**不会白屏、不会出现空语言按钮**。
- `settings.locale` 的合法值不会被「资源暂时缺失」改写；缺失只影响 effective 值。
- 全部字典缺失的极端情况：服务端仍返回默认可选项，字典加载走上述失败路径并显示错误。

### 2.4 Header 语言选择器与布局

- 选项来自 `/api/bootstrap` 的 `locales.available`，顺序即注册表顺序；每项 `{code, nativeName}`。
- 现有三种语言：保持原交互——宽屏 `#language-segmented` 三段按钮 + 系统按钮，≤860px 折叠为
  `#language-select`。视觉与改动前一致。
- 语言数 > 3，或三项原生名总长度 > 24 字符：自动切换为同一个原生 `<select>`（所有宽度均显示），
  系统选项仍在列表首项。**未来十语言不需要再改选择器逻辑。**
- 已删除 `.language-select { max-width: 132px }` 与 `@media (max-width:420px) { max-width:112px }`；
  select 使用内容自适应宽度，`max-width:100%` 只防止超出容器。
- 语言项始终带自身文字的 `nativeName` 与 `lang` 属性；不使用当前界面语言翻译语言名。
- 语言切换仍走 `PATCH /api/settings {locale}`，成功后重新加载字典并重渲染，行为与旧版一致。

### 2.5 启动器控制台（P40 已完成十语言）

- `src/launcher/cli-i18n.mjs` 现在有**与注册表完全一致的十套消息**（`CLI_LOCALES === AVAILABLE_LOCALES`，
  由测试强制）。键集与 `{placeholder}` 集合十语言一致。
- `--lang` 仍接受任意注册表语言码（`--lang ko`、`--lang de`、`--lang pt-PT`→`pt-BR`），
  旧三语参数完全兼容；`--help` 里的语言清单不再逐语言硬编码，而是由注册表填充 `{locales}`。
- **ASCII 安全回退**：`src/launcher/console.mjs` 在控制台无法切到 UTF-8（无 TTY / `chcp` 失败 /
  重定向输出）时，改用**英文 ASCII 消息集**并把非 ASCII 值折叠为 `?`；所有写入都包在 try/catch 中，
  控制台不可用、管道被关闭都不会让启动失败。`console.ready` 启动日志记录 `asciiFallback`。
- SEA 引导器（`scripts/sea-bootstrap.cjs`，运行于解压之前，无法 import 注册表）拥有自包含的十语言
  启动失败消息表；语言解析按注册表的族/地区规则实现，未知语言回退英文。该文件仍保留自己的
  消息表，这是「解压前不能 import 项目模块」的结构限制，**不是第二份可选语言清单**
  （其语言码集合由 `tests/unit/bootstrap.test.mjs` 与注册表逐条比对）。
- 控制台语言与 Web 界面语言仍然**各自独立**（`--lang` 只影响控制台）。

### 2.6 十语言的实现与验收（P40）

#### 2.6.1 注册表（唯一来源，仍然是 `src/shared/locales.mjs`）

```js
LOCALE_REGISTRY = [
  zh-CN(Hans, CN/SG/MY), ja, en, ko, es, pt-BR(pt, BR), zh-TW(Hant, TW/HK/MO),
  fr, de, id            // 顺序 = 所有选择器的顺序
]
AI_OUTPUT_LOCALES = ['zh-CN', 'ja', 'en']   // = 注册表中 aiOutput: true 的条目
```

- 新字段 **`aiOutput`**：显式标注某语言是否具备 AI 输出能力（提示词 + 结果 Schema +
  翻译目标名）。UI 语言清单与 AI 输出清单**不是两份清单**，而是同一注册表上的能力筛选。
- `AVAILABLE_LOCALES`（10）用于界面选择器/设置页/启动器；`AI_OUTPUT_LOCALES`（3）用于
  `SUPPORTED_LOCALES`、`SUPPORTED_MEMORY_LOCALES`、翻译目标与结果 Schema `enum`。
- 十种语言的 `nativeName` 只用该语言自身文字：简体中文 / 日本語 / English / 한국어 /
  Español / Português (Brasil) / 繁體中文 / Français / Deutsch / Bahasa Indonesia。
- **没有新增任何字典键**：`settings.language` 仍只有 `zh` / `ja` / `en` 三个历史原生名键，
  其余语言名一律来自注册表。因此十份字典仍是 **2,265** 个叶子键，P39 的键数契约未变，
  也没有新增「无关键」。`tests/unit/locale-registry.test.mjs` 断言 `settings.language` 恒为 10 个键。

#### 2.6.3 AI 输出语言的**安全收窄**（P40 新增约束）

十语言界面带来一个真实风险：界面语言是 `ko`/`de`/`fr`… 时，AI 任务若沿用界面语言就会把
没有提示词的语言发给 Provider。P40 的处理（**不提前实现 P41**）：

1. `/api/bootstrap` 增加 `locales.aiOutput`（注册表 `aiOutput: true` 的条目）；界面语言清单
   `locales.available` 仍为十种。
2. AI 中心与报告阅读语言下拉只列 `aiOutput` 三种，不再列十种。
3. `POST /api/ai/analyze/run`、`POST /api/memory/jobs` 用 `aiOutputLocale()` 收窄：
   同族优先（`zh-TW`→`zh-CN`），否则 `en`；**任何未支持语言都不会到达 Provider**。
4. 报告/翻译只读接口的 `locale` 校验改用 `AI_OUTPUT_LOCALES`（十语界面下 `de` 会被 400 拒绝，
   而不是进入一个不存在的提示词）。
5. JSON Schema 的 `locale.enum` 继续镜像 **`AI_OUTPUT_LOCALES`**（仍为三项），
   由 `tests/unit/locale-registry.test.mjs` 强制同步；`buildInstructions(locale)` /
   `memoryPromptVersionFor(locale)` 对未支持语言回退 `en` 的既有行为保持不变。
6. 新增测试：`aiOutputLocale` 降级矩阵、Schema 镜像、提示词语言集合、API 校验。
   **未新增 `aiOutputLocale` 设置，未改任务 locale 快照，未改翻译缓存语义。**

#### 2.8.2 提示词国际化方案（不是机械翻译）

新增唯一来源 `src/ai/prompts/language.mjs`。每种语言一条记录：

```js
OUTPUT_LANGUAGES['ko'] = {
  name: 'Korean', nativeName: '한국어',
  rule:  'summary, title, ... 등 사용자에게 보이는 모든 자연어 필드는 자연스러운 한국어로 작성하세요.',
  guard: 'JSON 키 이름, 열거형 값, 프로토콜 필드, viewer_id, message_id, seq, 타임스탬프, 플랫폼 식별자는
          번역하지 말고 그대로 두세요. … 기존 사실의 topic을 번역하지 말고 그대로 재사용하세요.',
  system: '당신은 LiveMemory의 로컬 분석 엔진입니다. …',
  repair: '이전 답변이 LiveMemory 검증을 통과하지 못했습니다. …',
  example: {summary, topic, statement}   // 目标语言的 Compact 记忆示例
}
```

产品决定（写进代码注释与本文档）：

1. **指令语言 ≠ 输出语言**。三套经过验证的完整指令正文（`zh-CN` / `ja` / `en`）原样保留；
   另外七种语言复用**已验证的英文正文** + 各自的 `rule`/`guard`/`system`/`repair`/`example`。
   机械翻译整套 30 条规则到十语言不会改善输出，只会增加维护面。
2. **每条 prompt 只发当前语言**。十语言能力不会让单次请求变成十语文本：
   `tests/unit/ai-prompt-locales.test.mjs` 断言每种语言新增的 session 指令长度 < 英文 + 2000 字符。
3. **机器契约优先**：`rule` 要求自然语言字段用目标语言，`guard` 要求 JSON 键名/枚举/协议字段/
   `viewer_id`/`message_id`/`seq`/时间戳/平台标识保持原样、原始聊天与证据引用不翻译不改写、
   续写事实复用原 topic。`topic` 是去重键，翻译它会破坏同语言去重（见 §6）。
4. **每个 prompt 面都注入同一契约**：
   - 系统提示词：`src/ai/api/prompts.mjs` 的 `SYSTEM` 由 `systemPromptFor(locale)` 生成（十语）；
   - 分析包 `instructions.md`：`buildInstructions()` 在 intro 之后插入 `## 输出语言` /
     `## 出力言語` / `## Output language` 段（`Locale: \`ko\`` + `rule` + `guard`）；
   - 记忆任务：`src/ai/prompts/split.mjs` 的 `memoryRules[0]` 用该语言 `rule+guard` 替换；
     `memoryCompactShape()` 使用该语言的示例散文（否则模型会照抄英文示例）；
   - 分批/分层/最终汇总：`OUTPUT LANGUAGE (<code>): <rule>` 作为最后一条规则追加；
   - 修复请求：`buildRepairMessages()` 的标签由 `repairLabelFor(locale)` 提供；
   - 人工粘贴记忆说明（`src/memory/prompt.mjs`，旧入口）：在标题下插入
     `- output_language: <code>` + `rule+guard`，并把原先「按原文语言记录」的规则改成
     「写入记忆用目标语言，引用原文不翻译」。
5. **提示词版本推进**：`lm-prompt-m6.3` → **`lm-prompt-m6.4`**、`lm-prompt-v13.2` →
   **`lm-prompt-v13.3`**、`lm-prompt-m7.1` → **`lm-prompt-m7.2`**。旧任务保留自己行上的版本号，
   旧结果不重写。
6. **Schema / 枚举 / 稳定标识不变**：结果 Schema 的字段名、枚举、`required`、`additionalProperties:false`
   全部未改，只把 `locale.enum` 扩到十项。`viewer_id`、`message_id`、`evidence`、时间戳、平台标识
   仍由本地程序注入与校验，模型仍不能输出 `viewer_id`（compact 契约）。

## 6. P41 正式设计依据：长期画像跨语言策略（方案 B）

**用户在 2026-11-16 明确选择方案 B：允许长期画像中出现不同语言的事实，并接受跨语言语义重复。**
本节是 P41 的正式设计依据。**P39 只记录决策，未修改任何长期画像代码、数据库或 AI 分析逻辑。**

必须遵守：

1. **不锁定观众首次分析语言。** 观众先用中文分析、后用日语分析是合法状态。
2. **不要求不同语言的同义事实自动合并。** `吉他` 与 `guitar` 可以同时作为两条 `live` 事实存在；
   不引入翻译式 topic 归一化。
3. **不引入跨语言别名表、语义归一化服务或专门数据库迁移。** 现有 `memory_facts` 不加 `locale` 列。
4. **保留现有同语言事实合并与去重行为。** `dedupeKeyFor() = kind:normalizeTopic(topic)` 不变，
   NFKC/小写/去标点规则不变；同语言同 topic 仍正常 add/confirm/update/supersede。
5. **切换 AI 输出语言不得删除、覆盖或重新翻译已有事实。** 历史事实保留原文语言；
   `supersede`/`outdated` 只能由新的分析判断触发，不能由语言切换触发。
6. **后续分析允许使用新的输出语言**，历史事实可以继续保留原来的语言；报告/画像时间线允许语言混合。
7. **语言混合不得导致数据库约束冲突、任务失败或历史数据损坏。** 唯一键、批处理、证据映射、
   导入事务必须继续成立；P41 必须补「同一观众跨语言两次分析」的集成测试。
8. **产品表述必须如实**：不得声称不同语言的事实会自动合并，也不得把语言混合描述为数据损坏。
   如 UI 需要提示，只能提示「已有事实按原语言保留」，不得自动改写。

**P41 已实现（2026-11-16）**：`aiOutputLocale` 持久设置、十语言提示词语言表与 Compact 示例、
跨语言集成测试、真实 Provider 双语画像验收（`ko` 7 条韩语事实、`de` 7 条德语事实），
均按本节规则落地；跨语言事实按方案 B 共存，未加列、未加别名表、未改去重键。

## 7. AI 辅助翻译流程（P40 使用）

### 7.1 术语表（先定，再翻译）

必须在开始翻译前维护 `docs/i18n/GLOSSARY.md`，至少覆盖：

- 产品名：`LiveMemory`（不翻译）
- 平台名：`Bilibili` / `YouTube` / `Twitch` / `抖音` / `TikTok`（按官方本地写法，不音译）
- 核心概念固定译法：直播、场次、弹幕/聊天、观众、稳定 ID、长期画像、单场报告、AI 分析中心、
  Provider、API Key、批次、证据、事实、置信度、`stated`/`inferred`/`uncertain`
- **不翻译**：JSON 键名、枚举值、错误码、平台字段名、货币代码、`platform:uid`、命令与路径、`--lang`
- 语气：克制、客观、不营销、不堆感叹号

### 7.2 翻译执行

1. 以 `en.json` 为源，逐键批处理，每批 ≤ 200 键。
2. 只翻译值，不改键名/顺序/结构。
3. `{name}` 占位符原样保留。
4. 长句按语言重写，不改变事实含义。

### 7.3 机器门禁（必须作为测试存在）

| 门禁 | 判定 |
| --- | --- |
| 键集一致 | 相对 `en.json` 缺失 0、多余 0 |
| 占位符一致 | 每键 `{param}` 集合完全相同 |
| 非空 / 类型 | 全部为非空 string |
| 残留英文 | 除白名单外，非英文语言不得整键等于英文源值 |
| 长度预算 | 短键/按钮类单独限制，超限阻断 |
| 未解析键渲染 | 真实字典渲染后不得出现 `xx.yy.zz` 原始键 |
| 控制台 | `cli-i18n` 键集与占位符一致 |

### 7.4 人工审校

术语一致、语法性别/敬语、数字/货币/日期自然、`zh-TW` 台湾用语、`id` 标准印尼语、
无「机翻味」、真实渲染无截断。
