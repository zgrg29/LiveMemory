状态：**P39 / I18N-M0 已完成（2026-11-16，本地开发里程碑，未发布）**。
当前产品仍然只有三种界面语言（`zh-CN` / `ja` / `en`）；本轮只把架构从「三语假设」升级为
「单一语言清单 + 可用性驱动降级 + 动态选择器」，**没有新增任何语言**。十语言整体仍未完成，
`ko` / `es` / `pt-BR` / `zh-TW` / `fr` / `de` / `id` 仍不可选择、不得在 README 或界面中宣称已支持。

## 1. 三层语言模型（长期不变式）

国际化必须把三件互相独立的事分开。任何实现都不得把三者混成一个「语言」开关。

| 层面 | 含义 | 存储位置 | 谁决定 | 是否可随界面语言变化 |
| --- | --- | --- | --- | --- |
| **L1 软件界面语言** | 主界面、菜单、按钮、设置、平台连接、AI 控制台、错误提示、使用说明 | `config/settings.json` 的 `locale`（`system` + 受支持语言码） | 用户（默认跟随系统） | 是，随时可切 |
| **L2 AI 分析输出语言** | 单场报告、长期画像的自然语言字段 | 任务创建时快照进 `ai_jobs.locale` / 记忆任务 `locale` | 用户（当前默认 = 界面语言） | **否**，任务内不可变；历史结果由翻译缓存按需切换阅读，原文不被改写 |
| **L3 原始弹幕语言** | 观众发送的原文 | `events.content`（原文）、`events.emotes`（平台表情元数据） | 观众 | **否**，永久原文，禁止翻译覆盖 |

三条不变式（后续任何里程碑都必须满足）：

1. **L1 ≠ L2**：用户可以使用韩语界面 + 日语分析报告。L2 必须是独立持久偏好，不能只是
   「拿界面语言当默认值再用一次」。
2. **L2 快照不可变**：任务一旦创建，`locale` 写入任务行；暂停、继续、重启、升级、切换界面语言
   都不得改变该任务的语言，也不得重写已保存结果的正文。
3. **L3 永不改写**：任何语言功能都不得把 `content` 替换成译文。翻译只能是「展示层附加」，
   且必须与原文分表存放（现有 `ai_translations` 已符合）。

## 2. P39 之后的真实实现（2026-11-16 实测）

### 2.1 单一语言清单

唯一可信来源：**`src/shared/locales.mjs`**。它是同构模块，Node 与浏览器引用同一份文件
（浏览器通过 `/shared/locales.mjs` 静态路由，服务端只暴露这一个共享模块）。

```js
LOCALE_REGISTRY = [
  {code: 'zh-CN', nativeName: '简体中文', englishName: 'Simplified Chinese',
   language: 'zh', script: 'Hans', regions: ['CN','SG','MY'], available: true},
  {code: 'ja',    nativeName: '日本語',   englishName: 'Japanese',
   language: 'ja', script: null,   regions: ['JP'],        available: true},
  {code: 'en',    nativeName: 'English',  englishName: 'English',
   language: 'en', script: null,   regions: ['US','GB','AU','CA','NZ','IE'], available: true}
]
```

- `AVAILABLE_LOCALES` = 声明为 available 的语言码，按选择器顺序。
- `DEFAULT_LOCALE = 'en'`。
- 注册表只列**真实随产品发布**的语言；计划语言不得提前加入 `available: true`。
- 原生语言名只在这里维护。`src/web/i18n/*.json` 里的 `settings.language.*` 仍保留为界面文案，
  但测试逐语言断言它们与注册表完全一致。
- 别名表只包含 BCP-47 旧码（`in`→`id`、`iw`→`he`、`ji`→`yi`），不是语言清单。

所有使用者都从这一来源派生：

| 使用点 | 位置 | 用法 |
| --- | --- | --- |
| 浏览器字典加载 / 原生名 | `src/web/js/i18n.js` | 直接 import 共享模块；不再有第二份 `SUPPORTED_LOCALES` |
| 旧接口兼容 | `src/shared/locale.mjs` | 重导出 `SUPPORTED_LOCALES = AVAILABLE_LOCALES` 并保留原有函数签名 |
| 服务端生效语言 | `src/server/routes.mjs` | `resolveLocale(..., {available})`；`/api/bootstrap` 返回 `locales` |
| 实际已安装资源 | `src/server/locale-resources.mjs` | 检查 `src/web/i18n/<code>.json` 是否存在 |
| Header 选择器 | `src/web/js/language-control.js` | 由 `bootstrap.locales.available` 生成，无固定三项 |
| 设置页语言卡 | `src/web/js/pages/settings.js` | 由同一列表生成 |
| AI 输出语言下拉 | `src/web/js/pages/ai.js` | 由同一列表生成 |
| 报告阅读语言 | `src/web/js/pages/ai-report.js` | 由同一列表生成 |
| AI 分析支持的 locale | `src/ai/constants.mjs` | `SUPPORTED_LOCALES` 从共享注册表导入 |
| 长期画像 locale | `src/memory/constants.mjs` | `SUPPORTED_MEMORY_LOCALES` 从共享注册表导入 |
| 翻译目标语言名 | `src/ai/translation/service.mjs` | `LOCALE_NAME` 由 `LOCALE_REGISTRY` 生成，输出格式不变 |
| 结果 JSON Schema | `src/ai/schemas/*.json`、`src/memory/schemas/*.json` | **协议产物镜像**；`tests/unit/locale-registry.test.mjs` 断言其 `enum` 与注册表一致 |

> JSON Schema 是给外部 AI 的静态协议文件，不能 import JS；它被明确视为「注册表的协议镜像」，
> 由测试强制同步，不是第二份可独立维护的语言清单。

### 2.2 语言解析与降级规则

解析分成三层，互不覆盖：

1. **用户偏好**：`settings.locale`，取值 `system` 或注册表内的语言码；由 `normalizeLocalePreference()` 校验。
2. **系统检测**：`detectSystemLocale()` 读取 `LC_ALL` / `LC_MESSAGES` / `LANG`，再回退
   `Intl.DateTimeFormat().resolvedOptions().locale`；只用于解析 `system`，从不写回设置。
3. **实际资源**：`resolveLocale(preference, systemLocale, {available})` 返回一个**已安装**的语言。
   若偏好语言存在但字典缺失，按语言族降级；若系统语言不在支持集合内，降级到默认语言。

`resolveLocaleTag(value, {available})` 的匹配顺序：

1. 规范化 tag（大小写、`_`→`-`、去掉 `.UTF-8`/`@modifier`、旧码别名）。
2. 精确匹配 `code`。
3. 同语言族匹配：优先 region 命中，其次 script 命中（`zh-HK` 推得 `Hant`），再取注册表顺序中
   第一个同族资源。
4. 没有同族资源 → `null`，调用方回退 `defaultLocaleFor(available)`（默认 `en`）。

已实测的降级矩阵：

| 输入 | 当前资源（`zh-CN`/`ja`/`en`） | 未来有 `zh-TW` 资源时 |
| --- | --- | --- |
| `zh-CN` / `zh-Hans` / `zh-SG` / `zh-MY` | `zh-CN` | `zh-CN` |
| `zh-TW` / `zh-HK` / `zh-MO` / `zh-Hant` | **`zh-CN`（安全降级）** | **`zh-TW`（优先）** |
| `ja` / `ja-JP` | `ja` | `ja` |
| `en` / `en-US` / `en-GB` | `en` | `en` |
| `pt` / `pt-PT`（有 `pt-BR` 时） | 无 pt 资源 → `en` | `pt-BR` |
| `in` / `in-ID`（有 `id` 时） | 无 id 资源 → `en` | `id` |
| `fr-FR` / `de-DE` / 未知 | `null` → 默认 `en` | 未新增前仍 `en` |

**关键区别**：`zh-TW` 不是「永久映射到 `zh-CN`」。当字典与注册表条目落地后，同一套解析逻辑
自动优先选择 `zh-TW`；`zh-HK` 等地区变体由 script 推断命中它，无需再改归一化代码。

### 2.3 资源不存在 / 加载失败

- 服务端启动时用 `detectInstalledLocales(webRoot)` 检查真实字典文件；缺失的语言不会出现在
  `/api/bootstrap` 的可选项中，生效语言自动降级。
- 浏览器 `loadDictionary(locale)`：目标字典 404/损坏时，回退默认字典一次；默认字典也失败时
  抛出错误，由既有启动失败页显示本地化说明，**不会白屏、不会出现空语言按钮**。
- `settings.locale` 的合法值不会被「资源暂时缺失」改写；缺失只影响 effective 值。
- 全部字典缺失的极端情况：服务端仍返回默认可选项，字典加载走上述失败路径并显示错误。

### 2.4 Header 语言选择器与布局

- 选项来自 `/api/bootstrap` 的 `locales.available`，顺序即注册表顺序；每项 `{code, nativeName}`。
- 现有三种语言：保持原交互——宽屏 `#language-segmented` 三段按钮 + 系统按钮，≤860px 折叠为
  `#language-select`。视觉与改动前一致。
- 语言数 > 3，或三项原生名总长度 > 24 字符：自动切换为同一个原生 `<select>`（所有宽度均显示），
  系统选项仍在列表首项。**未来十语言不需要再改选择器逻辑。**
- 已删除 `.language-select { max-width: 132px }` 与 `@media (max-width:420px) { max-width:112px }`；
  select 使用内容自适应宽度，`max-width:100%` 只防止超出容器。
- 语言项始终带自身文字的 `nativeName` 与 `lang` 属性；不使用当前界面语言翻译语言名。
- 语言切换仍走 `PATCH /api/settings {locale}`，成功后重新加载字典并重渲染，行为与旧版一致。

### 2.5 启动器控制台（本轮边界）

- 启动器仍使用独立的 `src/launcher/cli-i18n.mjs` 消息表（三语），与 Web 字典是两套资源；
  这与 `docs/ARCHITECTURE.md` §1 的启动器/网页分层一致。
- P39 只保证 `CLI_LOCALES` 与 `AVAILABLE_LOCALES` 完全一致（测试强制），**未扩语言、未改控制台行为**。
- 未来是否把控制台扩到十语、或保持三语 + 英文回退，属 P40 的明确决策项；本轮不擅自扩大范围。

语言码规则：

1. 一律 BCP-47、大小写规范（语言小写、区域大写：`pt-BR`、`zh-TW`）。
2. 归一化必须由**可用集合 + 语言族/script/region**驱动，不得写死「所有 `zh-*` → 某一种中文」。
3. 新增语言必须同时落地：注册表条目、`src/web/i18n/<code>.json`、原生语言名、
   `tests/unit/i18n.test.mjs` 的遍历校验、P40 的布局/UI/EXE 验收。
4. 旧配置值不需要迁移；`system` 语义不变。

## 4. 技术调查结论（P39 更新）

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 翻译资源如何组织 | 扁平点路径 JSON + `t(key, params)`；结构可扩展，无需重构 |
| 2 | 哪些用户可见文字仍硬编码 | 网页几乎为零（语言自身名称已集中到注册表）；未国际化部分仍是 AI 提示词、启动器控制台、平台技术详情、翻译系统提示词 |
| 3 | 语言配置与 AI 输出语言是否耦合 | **仍存在**：AI 输出默认取界面语言且无独立持久设置；P41 处理 |
| 4 | Windows EXE 字体与 Unicode | 网页由浏览器系统字体保证；启动器依赖 `chcp 65001` 并保留 ASCII 降级；本轮未逐语言实测控制台 |
| 5 | 固定宽度导致截断 | P39 已删除语言选择器 132px/112px 限制，并用真实浏览器验证十语言布局；其他页面标签的 112–260px 约束属 P40 走查项 |
| 6 | 日期/数字/错误本地化 | 日期/数字已走 `Intl`；错误走 `messageKey`；机制就绪 |
| 7 | 新增语言后的兼容性 | 设置/任务/翻译列均为自由 TEXT；旧三语配置原样加载；新增设置键（P41）必须同步备份白名单 |
| 8 | AI 辅助翻译流程 | 以 `en.json` 为源、逐键批处理 + 术语表 + 机器门禁 + 人工审校；见 §7 |

## 6. P41 正式设计依据：长期画像跨语言策略（方案 B）

**用户在 2026-11-16 明确选择方案 B：允许长期画像中出现不同语言的事实，并接受跨语言语义重复。**
本节是 P41 的正式设计依据。**P39 只记录决策，未修改任何长期画像代码、数据库或 AI 分析逻辑。**

必须遵守：

1. **不锁定观众首次分析语言。** 观众先用中文分析、后用日语分析是合法状态。
2. **不要求不同语言的同义事实自动合并。** `吉他` 与 `guitar` 可以同时作为两条 `live` 事实存在；
   不引入翻译式 topic 归一化。
3. **不引入跨语言别名表、语义归一化服务或专门数据库迁移。** 现有 `memory_facts` 不加 `locale` 列。
4. **保留现有同语言事实合并与去重行为。** `dedupeKeyFor() = kind:normalizeTopic(topic)` 不变，
   NFKC/小写/去标点规则不变；同语言同 topic 仍正常 add/confirm/update/supersede。
5. **切换 AI 输出语言不得删除、覆盖或重新翻译已有事实。** 历史事实保留原文语言；
   `supersede`/`outdated` 只能由新的分析判断触发，不能由语言切换触发。
6. **后续分析允许使用新的输出语言**，历史事实可以继续保留原来的语言；报告/画像时间线允许语言混合。
7. **语言混合不得导致数据库约束冲突、任务失败或历史数据损坏。** 唯一键、批处理、证据映射、
   导入事务必须继续成立；P41 必须补「同一观众跨语言两次分析」的集成测试。
8. **产品表述必须如实**：不得声称不同语言的事实会自动合并，也不得把语言混合描述为数据损坏。
   如 UI 需要提示，只能提示「已有事实按原语言保留」，不得自动改写。

P41 待做（不在本轮）：`aiOutputLocale` 持久设置、提示词语言表扩展、跨语言集成测试、
真实 Provider 双语言画像验收。本轮未提前实现任何一项。

## 7. AI 辅助翻译流程（P40 使用）

### 7.1 术语表（先定，再翻译）

必须在开始翻译前维护 `docs/i18n/GLOSSARY.md`，至少覆盖：

- 产品名：`LiveMemory`（不翻译）
- 平台名：`Bilibili` / `YouTube` / `Twitch` / `抖音` / `TikTok`（按官方本地写法，不音译）
- 核心概念固定译法：直播、场次、弹幕/聊天、观众、稳定 ID、长期画像、单场报告、AI 分析中心、
  Provider、API Key、批次、证据、事实、置信度、`stated`/`inferred`/`uncertain`
- **不翻译**：JSON 键名、枚举值、错误码、平台字段名、货币代码、`platform:uid`、命令与路径、`--lang`
- 语气：克制、客观、不营销、不堆感叹号

### 7.2 翻译执行

1. 以 `en.json` 为源，逐键批处理，每批 ≤ 200 键。
2. 只翻译值，不改键名/顺序/结构。
3. `{name}` 占位符原样保留。
4. 长句按语言重写，不改变事实含义。

### 7.3 机器门禁（必须作为测试存在）

| 门禁 | 判定 |
| --- | --- |
| 键集一致 | 相对 `en.json` 缺失 0、多余 0 |
| 占位符一致 | 每键 `{param}` 集合完全相同 |
| 非空 / 类型 | 全部为非空 string |
| 残留英文 | 除白名单外，非英文语言不得整键等于英文源值 |
| 长度预算 | 短键/按钮类单独限制，超限阻断 |
| 未解析键渲染 | 真实字典渲染后不得出现 `xx.yy.zz` 原始键 |
| 控制台 | `cli-i18n` 键集与占位符一致 |

### 7.4 人工审校

术语一致、语法性别/敬语、数字/货币/日期自然、`zh-TW` 台湾用语、`id` 标准印尼语、
无「机翻味」、真实渲染无截断。
