# UI 设计规范（UI_DESIGN）

## 1. 设计原则

参考 Apple 官网与其产品界面的视觉语言，但**不使用任何 Apple 商标、图片或专有资源**：

- 清晰层级：标题 → 说明 → 数据 → 操作
- 大量留白：页面最大宽度 1120px，卡片间距 16px，区块间距 32–44px
- 克制强调色：只有主操作、选中态与数据高亮使用蓝色
- 细腻边框与阴影：1px 半透明描边 + 极轻阴影，避免“卡片堆叠感”
- 统一交互反馈：hover 变色、按下轻微缩放、focus-visible 蓝色描边
- 平滑但不过度：180–240ms，`cubic-bezier(0.4, 0, 0.2, 1)`，尊重 `prefers-reduced-motion`

## 2. 字体

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "Helvetica Neue",
  "Noto Sans SC", "PingFang SC", "Microsoft YaHei UI", "Hiragino Sans",
  "Yu Gothic UI", "Noto Sans JP", "Meiryo", sans-serif;
```

- 全部使用系统字体，无商业字体授权问题。
- 标题字重 600、字距 -0.02 ~ -0.035em；正文 15px/1.5。
- 数字使用 `font-variant-numeric: tabular-nums`，避免跳动。
- 中日文回退已显式指定，Windows 上优先 Segoe UI + 微软雅黑 UI / Yu Gothic UI。

## 5. 布局

```text

│ Sidebar 256 │ Topbar（粘性、半透明模糊）            │
│ 品牌         ├──────────────────────────────────────┤
```

- 侧边栏固定、半透明 + `backdrop-filter`，底部显示连接状态与版本。
- 顶栏：页面标题、隐私提示、语言切换、主题切换。
- 语言切换与外观切换同一区域：宽屏为 `简体中文 / 日本語 / English` 三个始终以各自语言显示的分段按钮 + 地球“跟随系统”按钮；≤860px 折叠为带地球标识的原生 select。不得只提供当前语言文字按钮；切换不刷新页面。
- ≤860px：侧边栏变抽屉（hamburger + 遮罩 + Esc 关闭），顶栏保留。
- 统计卡：桌面 4 列 → 900px 2 列；页面网格 900px 单列。
- 390px 宽度下无横向溢出（已截图验证）。

## 7. 页面结构

1. **直播记录**：顶部多场标签栏（固定「＋ 新建记录」+ 可横向滚动的直播标签）→ 当前场次状态 Hero（录制状态、停止记录、已记录时长、消息数）→ 4 统计卡 → 消息密度图 → 最近动态 + 可滚动 Top 100 最活跃观众；新建视图在无运行任务时展示上一场摘要，有运行任务时明确提示它们仍在后台记录。
2. **直播历史**：表格化列表（场次、时长、消息、观众、支持、AI 状态）；详情含统计卡、时间线、经济支持、最活跃观众、**AI 报告摘要卡**、存储信息。
3. **观众档案**：主播范围选择器 + 搜索 + 列表（头像首字、平台 ID、当前主播范围的场次/发言/支持、参与主播数、关注星标）；详情含身份、参与过的主播（可切换）、当前主播的互动档案、该主播场次/支持、昵称历史、全局参与概览（明确标注）与兴趣占位。主播多时范围选择器附搜索框。
4. **AI 分析中心**：五步单入口（选择直播 / 选择 API 配置 / 选择内容 / 费用与预算确认 / 开始 AI 分析）→ 请求统计与阶段 → 报告。界面不绑定任何 AI 品牌；只使用用户自备 API Key，不提供匿名免费或手动 JSON 入口。
5. **设置**：语言（含跟随系统与实际生效语言，并提示 Header 为主入口）、外观（三张预览卡）、存储模式、YouTube 接入、**数据存储位置**（真实路径、来源、位置记录、可写状态、空间、计数、修改/打开/刷新）、**数据管理**（清空数据、恢复出厂设置、数据库快照说明）、关于。

### 7.1 聊天文字与表情显示

- 弹幕原文使用 `textContent` 渲染，保留中文/日文/英文混排、Unicode Emoji、变体选择符、肤色修饰符与 ZWJ 序列。
- 平台表情优先显示平台提供的文字标签（例如 Bilibili 的「就这」）；正文已有 `[猫猫鼓掌]` 时原样显示，不额外替换成图片。
- 只有正文为空、但存在表情元数据时，才显示本地化回退「平台表情：名称 / id」；表情缺失不影响昵称、时间戳和消息顺序。
- 本版本不下载、不缓存、不显示平台表情图片；未来若增加，必须有加载失败回退到文字，并把图片缓存与长期聊天数据分开。
- 未知表情不臆测情绪，不使用颜色/图标暗示“开心/生气”。

### 7.2 AI 任务说明

- AI 分析中心顶部用自然语言列出：整场话题与变化、时段讨论变化、回看片段、新观众初始画像、既有观众新信息/兴趣变化/画像更新。
- 说明文字明确“文字、Unicode Emoji 与平台表情名称；未知表情会被标记，不会猜测含义”。
- 提供“使用你选择的 AI 服务”说明，不假设存在一个通用 AI 网站；不同 AI 的文件大小、ZIP 支持和上下文长度差异由用户自行处理。
- 正式指令由软件按任务与协议版本生成，用户只需复制，不需要手写提示词。

### 7.3 直播来源：三个标签

直播记录页的「直播来源」卡片是唯一让用户选择平台的地方，固定三个标签：**模拟直播 / Bilibili 直播 / YouTube 直播**。标签切换不得清空当前正在进行的记录。

YouTube 标签只有一个入口，与 Bilibili 一样直接：

- 一句说明 + 「直播链接或视频 ID」输入框 + 「检查直播」按钮。
- 检查结果用胶囊表达：正在直播（`live`）、尚未开始、已结束、非直播、聊天关闭；不可记录时说明原因，不显示开始按钮。
- 可记录时显示标题/频道/当前观看/开始时间与「开始记录直播」。
- 连接后显示连接状态、当前观看、已收消息数与「可能漏消息」；10 秒轮询一次。
- 不显示：官方 API / 实验模式切换、Google 登录、API Key、OAuth、配额、实验 badge、模式技术说明。
- 不要求用户先理解接入机制；数据保留说明（天数 + 立即清理）保留在面板底部。
- 设置页的 YouTube 卡只读说明：无需登录/Key/Cookie；非 YouTube 官方稳定 API、可能失效；30 天保留。
- 动态流显示平台确认的 badge 文本；没有 badge 不占位。

### 7.4 数据存储位置与危险操作

- “数据存储位置”卡显示：当前真实目录（等宽字体）、来源（默认/自定义位置/命令行临时指定）、位置记录文件、可写状态、可用空间、LiveMemory 占用、数据库占用、场次/观众/事件；按钮：修改存储位置、打开数据文件夹、刷新。
- “修改存储位置”对话框：
  - 目标路径输入 + 浏览（Windows 原生 FolderBrowserDialog，由本地服务启动；浏览器不伪造目录选择器）；
  - 浏览返回完整绝对路径；取消不报错、不改变输入；无交互桌面时仍可手动输入；
  - 两种模式：迁移现有数据（推荐）/ 在新目录创建新的数据空间，均有清楚说明；
  - 云同步/临时目录/长路径 warning + 需要勾选确认；UNC 直接拒绝；
  - 成功后显示原目录（未删除）、新目录、迁移前后事件数、位置记录；旧目录不会自动删除。
- “数据管理”危险区：两个独立操作（清空数据 / 恢复出厂设置），每个都有范围说明；二次确认对话框要求输入 `DELETE` / `RESET`，默认勾选数据库快照，记录中禁用。
- 删除成功后显示清理前后场次/事件/观众、备份路径、清理文件数；按钮“完成并刷新”。快照目录默认不在数据目录内。

### 7.5 多主播范围选择器

- 默认“当前主播”（服务端按直播中/最近真实场次确定）；选项包括全部主播、其他主播、待确认主播（仅当存在 unresolved 历史）。
- 主播数 > 8 时显示搜索框；排序：发言最多/参与场次最多/支持最多/最近出现/最新出现。
- 列表在具体主播范围下只显示该主播的场次、发言、支持；全部主播显示全局合计与“参与过 N 位主播”。
- 详情页的“参与过的主播”行可点击切换；当前主播范围高亮；全局概览放在最后并用虚线卡片与“全部主播”标注，不与当前主播档案混排。
- **详情页只列该观众实际互动过的主播**（`viewer_broadcasters`，含礼物/SC/大航海）；不显示全局主播列表，也不显示无意义的“全部主播”。
  只有一个关联主播时用只读标签代替下拉；没有关联主播时显示明确空状态，不回退到全部主播。
- 主播身份 chip：已确认频道（强调色）/ 按直播间识别（警告）/ 模拟直播（中性）/ 待确认（警告）。

### 7.6 多直播间标签与 Top 100（v0.6.0）

**标签栏**

- 结构：`[＋ 新建记录] [主播 A ● 记录中] [主播 B ● 重连中] [主播 C ● 已停止 ×]`。
- 「新建记录」固定在左侧，不随标签横向滚动；右侧标签区独立 `overflow-x: auto`，窄屏可横向滑动，不挤压 Hero/图表。
- 标签显示主播名（缺失时直播间标题或平台名）、状态点与短状态：连接中 / 记录中 / 重连中 / 已停止 / 连接失败。
- 运行中标签**不显示关闭按钮**；必须先「停止记录」，避免用户以为关闭标签会保留后台采集，或误触停止。
- 已停止/连接失败的标签保留在当前页面并显示 `×`；关闭只移除已结束的标签，数据已写入直播历史。
- 标签仅切换视图。页面顶部提示“标签只切换查看，不会停止其他直播；停止记录请在该场直播内操作”。
- 切换标签立即重建当前场次 Hero/统计/图表/最近动态/Top 100；其他场次继续在服务端采集。
- 页面重新进入时按 `/api/live/recordings` 恢复所有运行中任务；软件重启后不显示上次任务为运行中。

**每场独立内容**

- Hero：当前场次标题、平台、模拟标记、连接状态、观看/人气/重试次数、开始时间、已记录时长、消息数。
- 停止按钮只在当前场次显示，旁注“只停止当前这一场；其他标签页的直播会继续记录。”
- 已结束/失败的场次显示最终状态、结束时间与“在历史中查看”，不再提供停止按钮。
- 统计卡、消息密度图、最近动态、经济支持均取自当前 `sessionId`；旧标签的异步响应由 `viewToken` 丢弃。

**Top 100 排行榜**

- 卡片标题「最活跃观众」，hint「本场前 100 名 · 按有效弹幕数」。
- 默认约 10 行可见；列表区域固定最大高度（桌面 352px、窄屏 350px）内部滚动，最多 100 行，不拉长整页。
- 行结构：名次（`#1`…）、观众名称、`N 条消息`；名次用服务端 rank，不在前端重排。
- 搜索框匹配当前场次昵称或稳定 UID；过滤后保留原始名次，显示“显示 X / Y 名”。无匹配显示空状态。
- 排名稳定：消息数降序 → `platform_uid` → `viewer_id`；昵称相同但 UID 不同的观众是两行。
- 点击整行打开 `/viewers/<id>?broadcaster=<当前主播>`，保留主播上下文。
- 刷新约 4 秒一次，事件触发 2.5 秒节流；内容签名未变化时不重建 DOM，避免高频全量刷新。
- 排行榜只属于当前场次，不展示长期累计或跨主播合计；这些仍在观众档案页单独标注。

**启动器控制台**

- 双击 EXE 的控制台默认英文，不跟随网页界面语言；这是为了让 CLI 输出稳定可读。
- 网页界面继续保留简体中文 / 日本語 / English 与跟随系统。
- `--lang zh-CN|ja|en` 仍然覆盖控制台语言，网页语言不受影响。

### 7.6.1 自动监听持久 Tab（v0.10.0）

- 标签栏扩展为：`[监控 A ◎ 等待开播] [监控 B ◎ 直播中] [＋ 新建记录] [手动场次…]`。
  监听标签固定在左侧；由监听目标产生的场次不再额外生成 session-only 标签。
- 监听标签不显示 `×`：Tab 对应直播间/频道，关播后仍保留。删除目标必须走目标视图的
  「删除监听目标」确认弹窗；删除不删除历史场次。
- 状态文案：等待开播 / 正在检查 / 正在连接 / 直播中 · 正在记录 / 正在重连 / 正在确认关播 /
  监听已暂停 / 需要处理；状态点颜色使用同一套 tokens。
- 目标视图 Hero：平台 +「自动监听」chip + 状态；标题为直播间/频道名；副标题为平台与目标 ID；
  操作：查看本场记录（记录中）、暂停/恢复监听、立即检查、删除目标。
- 信息卡：当前状态、检查频率、上次检查、下次检查、上次直播、目标 ID。
- 错误卡：可读原因 + 下次自动重试时间 +「立即重试」；不使用无限静默重试。
- 最近场次卡：最多 10 条，显示标题、开始时间、时长、消息数、可识别观众数、状态；有未识别身份消息时显示「N 条未识别」；点击进入历史详情。
- **观众统计口径（v0.13.2 审计后）**：所有页面统一使用「可识别观众」= 本场至少一条事件带稳定平台 UID 的去重互动者（含礼物/SC/大航海-only）。不得再写「独立观众 / 本场参与人数」。
  有未识别消息时，直播页显示警告卡，历史列表显示行内徽标、详情显示警告卡，AI 中心任务规模显示「未识别身份消息」并提示画像覆盖范围。
  缺失 UID 的弹幕仍计入消息数，但不计入观众，不按昵称合并。
- 新建视图的平台面板增加「自动监听此直播间 / 频道」复选框（默认关闭）。勾选后按钮变为
  「添加自动监听」，输入占位符随平台变化；关闭时保持原手动连接流程。
- 记录中的监听场次额外显示「自动监听」chip，并在停止提示中说明：停止只结束本场，目标与 Tab 保留。
- 三语、明暗主题、≤700px 时目标操作换行、信息行单列、最近场次纵向排列；文本只用 `textContent`。

### 7.7 直播历史管理与搜索（v0.7.0）

**列表顶部工具栏**

- 第一行：统一搜索框（placeholder「按主播、标题或观众搜索」）+ 搜索范围（全部字段 / 主播 / 标题 / 观众）。
- 第二行：平台、状态、开始日期、结束日期、包含已归档、重置筛选；控件紧凑，620px 以下自动换行，不出现横向滚动。
- 结果区上方：`显示 X / Y 场`；有隐藏归档时显示「另有 N 场已归档未显示 · 查看归档」；观众搜索时显示
  「没有稳定平台 ID 的匿名消息无法按观众搜索；同名昵称分别列出，绝不合并」。
- 空状态区分「还没有记录」与「没有匹配的场次」；后者提供重置筛选。

**列表行**

- 保持标题、状态 chip、归档 chip、模拟标记、主播/主播身份、开始时间、AI 状态；右侧为 `···` 菜单按钮。
- 搜索时标题下方显示匹配原因 chip（标题匹配 / 主播名称匹配 / 观众参与匹配）。
- 观众匹配行显示「昵称 · 平台 · 稳定 UID · 本场 N 条消息」；点击进入该场详情并启用观众下钻；最多 3 行，其余折叠为 `+N`。
- 整行可点击进入详情；行内按钮（`···`、观众行）不触发行跳转。

**场次操作菜单（列表与详情共用）**

- 记录中：只有「停止记录」；已停止/结束/中断：归档或取消归档 + 永久删除。
- 菜单 fixed 定位，靠近视口边缘时上翻/夹紧；方向键、Home/End、Esc、外部点击、滚动/缩放关闭；关闭后焦点回到触发按钮。
- 停止确认：显示主播、标题、平台、日期、消息/观众；说明只停止本地采集、数据保留、平台直播可能仍在进行。
- 删除确认（危险色）：同上事实 + 将被删除/将保留的范围 + 必须勾选「我了解此操作不可撤销」；未勾选时删除按钮禁用。
- 归档/取消归档不弹确认，直接执行并 toast，可用「取消归档」立即恢复。

**详情页**

- 标题区右上角：`Open AI analysis` + `···` 菜单（与列表同一实现）。
- 归档场次显示提示卡：默认列表隐藏，但仍可搜索、查看、导出；可从菜单取消归档。
- `end_reason=user` 显示「你已停止记录」提示，明确不是平台直播结束。
- `?viewer=<id>` 时显示「本场观众」卡：稳定 ID、本场发言/付费事件、首末出现、最近 50 条发言、打开观众档案；
  无参与记录时显示明确提示，不虚构关系。
- 停止/归档后原地刷新；删除成功后返回历史列表；已删除场次不再显示旧数据。

**响应式与可访问性**

- 900px 以下列表隐藏时长/消息/观众列，保留标题、状态、支持与 `···`；菜单在 390px 内不溢出。
- 所有操作按钮有 aria-label；菜单为 `role=menu` / `role=menuitem`；对话框使用原生 `<dialog>`（焦点圈闭、Esc）。
- 全部文本经 `textContent` 渲染，不使用 `innerHTML`。

### 7.8 AI 导入与直播分析报告（v0.8.0，历史）

> v0.13.1 已删除手动导入/提示词/任务下载 UI；本节的导入卡与提示词卡仅作为历史设计记录。当前界面见 §7.13。

**AI 分析中心**

- 步骤卡：`选择直播 → 创建任务/导出分析包 → 复制提示词 → 任意 AI 分析 → 导入 JSON → 查看报告`。
  普通用户不需要理解 JSON Schema 或数据库；高级说明只在需要时展开。
- 「创建分析任务」：直播选择、分析语言（新任务）、高级“每批消息数”（100–5000，默认 1000）、
  创建按钮；成功后显示任务摘要。手动路径明确“LiveMemory 不会为手动分析调用 AI API”；自动路径在入口处说明会发送给第三方免费服务并要求同意。
- 任务卡：状态 chip、创建时间、批次进度、缺失批次、提示词版本、结果版本、汇总包、重新分析；
  每个批次包可单独下载；旧版任务标记 legacy。
- 提示词卡：批次/汇总选择器 + 版本 + 等宽可滚动预览 + 复制按钮；内容与包内 `instructions.md` 一致。
- 导入卡：文件选择与粘贴文本框并列；校验按钮 → 预检查面板（场次、任务、批次、Schema、覆盖、
  重复/新版本）→ 确认导入；错误显示字段路径 + 原因 + 修复建议，警告可折叠；
  重复结果禁止再次写入；新版本必须点击「作为新版本导入」。
- 报告卡：AI 分析 badge + 完成/不完整状态；摘要、话题时间线、情绪、争论、候看片段、观众画像、来源；
  证据可展开为真实消息；原文不可用时明确提示。多批未汇总时按批次分别显示，绝不合并成整场。
- 切片提示必须写明“只分析聊天与事件，没有视频/音频，不能生成切片”。

**历史详情**

- AI 报告摘要卡：有完整结果时显示 AI 摘要、画像数量、导入时间与「查看完整报告」；
  部分导入显示 Incomplete；仅导出显示等待导入；无任务显示原有 AI 待分析提示。

**响应式/主题**

- 任务行动作在窄屏换行；证据行在 ≤760px 改为单列；报告卡与提示词预览不产生横向溢出。
- 明亮/黑暗分别使用 tokens；AI badge、低可信度 chip、不可用证据使用语义色，不写死颜色。

### 7.9 平台状态与直播生命周期（v0.8.1）

**原则**：平台直播状态与本地采集状态分开表达，不能用一个绿色「直播中」混合两件事。

- 直播记录 hero：连接状态 + 平台状态两个 chip；平台已下播/确认中时采集 chip 变为
  「正在确认下播」/「正在结束记录」（warn），不再使用 live 绿色。
- 多场标签：运行中显示连接状态；自动结束后标签显示「已下播」，并保留该场可查看；
  其他标签继续运行。
- 历史列表：采集状态 chip（直播中 / 已下播 / 手动停止 / 采集中断 / 已结束）+
  必要时的平台状态 chip；平台 chip 统一带「平台：」前缀（例如「平台：直播中」），
  避免与采集状态混淆。
- 历史详情「直播生命周期」卡：
  - 采集状态、平台状态、最后确认直播中、平台结束时间、最后检查/检测时间、结束原因；
  - 平台结束时间未知时显示「未知」，并固定显示说明：
    「最后一条弹幕时间不会被当作下播时间，记录时长是本地采集窗口」；
  - 自动下播显示「平台直播已结束」说明；手动停止仍显示「你已停止记录，不代表平台下播」。
- 记录时长在 `ended_at` 固定后不再增长；刷新、切换标签、重启 EXE 一致。
- 未开播/轮播房间：显示「未开播」/「轮播中」，开始按钮禁用并说明只记录正在直播的房间。
- 三语键：`status.*`、`history.detail.*`、`history.endReason.*`、
  `live.hero.platformEndedNotice`、`live.source.onlyLiveCanStart`、
  `errors.bilibiliRoomNotLive|Carousel`。
- 视觉验证：`live-status-history-v081-zh.png`（中文详情）、
  `live-status-history-v081-dark-390.png`（390px 黑暗列表，无横向溢出）。

## 8. 主题行为

- 首次启动默认跟随系统；`theme-boot.js` 在 CSS 之前设置 `data-theme`，避免闪烁。
- 用户选择明亮/黑暗后覆盖系统，并保存到 `config/settings.json` + `localStorage` 镜像。

- 图表监听 `livememory:themechange` 重绘；切换不改变布局尺寸。

## 9. 多语言

- 三语 JSON：`src/web/i18n/{zh-CN,ja,en}.json`，由测试保证键与占位符完全一致。
- 语言切换即时生效：重新加载字典 → 更新静态文案与导航 → 重渲染当前页；不刷新浏览器、不丢失数据。
- 用户可见的错误来自 `errors.*` 键，不直接展示服务器英文。
- 直播原文（昵称、弹幕、礼物名、标题）不翻译。
- 日期/数字/货币使用 `Intl` 按当前语言格式化；货币保留原币种符号与小数位。

## 10. 可访问性

- 语义化标题层级；导航 `aria-current="page"`。
- 图标按钮均有 `aria-label`（随语言更新）。
- 焦点可见（2px 强调色描边，2px offset）。
- 图表有 `aria-label` 概括，关键数值同时以文本呈现。
- 抽屉导航支持 Esc 关闭；列表行支持 Enter/Space 打开。
- 对比度：正文与背景 ≥ 7:1（明亮）/ ≥ 12:1（黑暗），次要文字 ≥ 4.5:1。
- 动画在 `prefers-reduced-motion` 下关闭。

「创建任务并导出分析包」上方。不新建独立页面；原手动流程原样保留，并用
「或使用手动分析」分隔线明确分区。

**结构**：

```text
┌ 自动 AI 分析（免费 · 匿名） ─────────────────────────────┐
│ 自动创建任务、分析、校验并更新长期记忆，不需要下载/上传文件。 │
│ [自动 AI 分析]  [取消]                                      │
│ （失败时）目前免费 AI 自动分析暂时不可用，请使用下方的手动 AI │
│           分析功能。                                        │
│ 查看详情（折叠：稳定错误码 + 脱敏 detail）                   │
└────────────────────────────────────────────────────────────┘
──────────────────── 或使用手动分析 ────────────────────
```

**状态文案**（只反映真实阶段，不显示虚假百分比）：

| 阶段 | 文案（zh-CN） |
| --- | --- |
| preparing | 正在准备分析数据…… |
| connecting | 正在连接免费 AI…… |
| analyzing | 正在分析第 X/Y 批……（X/Y 来自服务端真实批次） |
| validating | 正在验证 AI 结果…… |
| importing | 正在更新观众长期记忆…… |
| aggregating | 正在生成整场汇总…… |
| complete | AI 分析完成（有记忆覆盖时附 X/Y 位观众） |
| canceled | 自动分析已取消 |

**交互**：

- 第一次点击显示自定义 modal：说明本场聊天与相关观众记忆会发送给第三方免费 AI，
  处理方式取决于第三方隐私政策；用户确认后才发请求。确认记录在
  `localStorage['livememory.aiAutoConsent.v1']`，不写入数据库。
- 运行中禁用自动按钮，防同一任务重复启动；显示「取消」。
- 页面切走/刷新不取消服务端任务；回到页面后从 `/api/ai/auto/status` 恢复真实状态。
- 完成后刷新任务列表、提示词与报告；不自动滚动或弹窗打断用户。
- 失败时**不使用 `alert()`**、不自动切换手动模式、不删除已完成的分析结果；红色文案位于按钮
  正下方，技术原因折叠在「查看详情」。用户可立即继续使用下方手动导出/导入。
- 取消只停止后续请求；已导入批次保留，可再次点击从缺失批次恢复。
- 窄屏（≤700px）标题与 chip 纵向排列，按钮换行；不产生横向溢出。
- 颜色只用 tokens：错误文案 `var(--danger)`，成功状态 `var(--success)`，其余
  `var(--text-secondary)`；明亮/黑暗分别适配。
- 所有文案在 `src/web/i18n/*.json` 的 `ai.auto.*`；禁止硬编码、禁止 `innerHTML`。

```text
│ Token / 已知费用                                          │
│ [暂停/继续] [取消分析]                                    │
│ 错误一句话 + [查看技术详情]                               │
└─────────────────────────────────────────────────────────┘
```

**规则**：

- 没有 API 配置时，只显示「打开 API 设置」，开始按钮禁用；不显示匿名免费或手动 JSON 替代入口。
- 只有 `paid + pricing + capabilities.session + capabilities.memory` 才显示长期画像选项；`api_free` 只允许单场。
- 付费或未知价格显示费用确认；长期画像额外显示 opt-in；两者都勾选并具备能力时才可开始。
- 首次使用显示一次数据发送同意 modal；之后记录在本地 `localStorage`，不写数据库。
- 运行中禁用重复启动；暂停/继续/取消都调用服务端；页面刷新从服务端恢复状态。
- 请求统计来自 `status.requestStats`；不显示伪造的官方 RPM/费用。
- 失败只显示简单原因 + 折叠详情；不弹 `alert()`，不删除已完成结果。
- 历史报告与长期画像仍通过报告卡只读展示；没有手动导入/上传/修复控件。
- 三语文案在 `ai.center.*`、`ai.v13.stage.*`、`ai.v13.price.*`、`ai.v13.billing.*`、`ai.v13.memory.*`；禁止硬编码、禁止 `innerHTML`。

### 7.14 v0.13.1 实际使用修复

**场次选择**
- `#/ai?session=<stable_id>` 按 id 选中；目标不在前 100 行时按 id 加载；删除/无效时回退第一场并更新 URL。
- 用户手动选择其他场次后 `history.replaceState` 更新 URL，旧参数不会反复强制切回。

**配置状态**
- 未创建配置：显示「尚未配置 AI 服务，请前往设置添加 API Key。」
- 已有配置但缺 Key：显示缺 Key 警告；不是“未配置”。
- Key 已保存但未检测：中性提示“尚未完成能力检测”。
- 检测失败：显示失败原因；缺价格：显示补价格提示。
- 已就绪：不再显示任何“未配置”警告。

**进度**
- 开始按钮下方立即出现进度卡；进度条显示真实百分比（单场请求无批次时显示不确定动画）。
- 单场：`单场报告 0/1`；画像：`批次 done/total` + `已处理观众 done/total`；两者分别显示。
- 100% 只在服务端 `complete` 后显示；失败最多 99%。
- 1.5 秒轮询；刷新/离开再返回从服务端恢复；旧响应由 epoch 丢弃。

**报告**
- 报告只有一个挂载点；并发刷新只有最新响应可挂载。
- 长期画像作为独立卡片，不与单场报告混淆。

**监听**
- 新增状态「直播中 · 本场已停止采集」；Tab 保留。
- 目标页显示说明与「开始接收弹幕」按钮；暂停监听仍是独立状态。
- Bilibili 未开播也显示真实主播名；查询失败先显示「Bilibili · 房间号」，后续低频检查自动更新。

### 7.16 v0.13.2 长期画像错误、统计与部分成功

**失败状态（`failed` / `partial` / `needs_action`）**

- 普通文案只显示本地化的一句话原因（`ai.center.reason.<CODE>`）；未知代码回退为 `ai.center.reason.unknown`（含代码），不再直接显示裸代码。
- 「查看技术详情」为 `<details>`，只显示本地诊断字段，纯 `textContent` + `white-space: pre-wrap`：
  - 错误代码、发生阶段、任务 ID、批次（index + batchId）、字段路径/错误码/参数；
  - 每个失败批次一行（`failedBatches`）；
  - 可恢复（是/否）与建议操作（继续 / 检查配置）。
- 不显示模型原始回答、聊天正文、API Key、请求头或任何未处理内容。
- `combined` 单场成功、画像失败：状态 `partial`，文案明确「单场报告已完成，长期画像未完成」，并显示已处理/未完成人数；不显示为整场失败。

**完成统计**

- `complete` 的长期画像显示：已处理 / 总数、有新增语义事实人数、仅客观互动人数。
- 报告「长期观众画像」卡使用 `longTermProfiles.stats` 的 def-list：应处理、已成功处理、有新增语义事实、仅客观互动、尚未完成、失败批次涉及。
- 旧任务没有 `stats` 时回退到 `longTermCount` 文案；不伪造统计。

**usage**

- 有 session + memory 两个 Job 时，统计区分别显示「单场报告用量」「长期画像用量」的请求数与输入/输出 token；总 Token/费用仍为任务合计。
- 任一 Job 费用未知时，总费用不显示（不是 0）；未知用量文本为「用量未知」。

**三语**

- 新增键：`ai.center.reason.AI_IMPORT_INVALID`、`ai.center.reason.unknown`、`ai.center.errorMeta.*`、`ai.center.completeMemoryStats`、`ai.center.partialMemoryStats`、`ai.center.stats.sessionUsage|memoryUsage|requestsTokens`、`ai.report.longTerm{Total,Processed,Semantic,ObjectiveLabel,Pending,Failed}`。
