# 隐私与安全（PRIVACY_SECURITY）

## 1. 网络面

- 服务只绑定 `127.0.0.1`，不监听 `0.0.0.0`，不开放公网。
- 端口默认 47800，冲突时自动顺延或由系统分配；不写死、不对外公告。
- 启动器仅在本机服务确认就绪后打开浏览器。

## 2. HTTP 防护

- **Host 校验**：只接受 `127.0.0.1:<port>`、`localhost:<port>`、`[::1]:<port>`，防止 DNS rebinding。
- **Origin 校验**：非 GET/HEAD 请求若带 Origin，必须与本地源一致。
- **CSP**：`default-src 'self'`，禁止内联脚本/样式、禁止 framing、禁止 object。
- **nosniff / Referrer-Policy / CORP / COOP / Permissions-Policy**。
- **静态文件**：解码后规范化路径，必须位于 `src/web` 内，防止 `..` 穿越；拒绝 NUL。
- **JSON body**：1 MB 上限、必须 `application/json`、必须是对象。
- **API 未知路径**返回 JSON 404，不回退到 HTML。

## 3. 凭据

- Bilibili Cookie、YouTube OAuth Token、API Key 等**不写入日志**、默认**不进入备份**、不进入 AI 分析包。
- 日志脱敏：键名匹配 `cookie|sessdata|bili_jct|token|secret|password|authorization|api[-_]?key|credential`，值模式匹配 `SESSDATA=`、`Bearer ...` 等。
- 聊天正文不写日志。
- 未来持久化凭据时使用 DPAPI 或 AES-256-GCM + 用户密码派生，不放在普通 JSON。

## 4. 日志

- 位置：`%LOCALAPPDATA%\LiveMemory\logs\livememory-YYYY-MM-DD.log`（JSONL）。
- 内容：启动、迁移、服务就绪、场次开始/结束、设置变更、错误码。
- 不记录：Cookie/Token、聊天正文、观众隐私数据、完整文件路径以外的敏感信息。
- 单文件 5 MB 轮转为 `.1`。
- `runtime/last-error.json` 只记录错误码、时间、端口与 `messageKey`，不含凭据。

## 5. 数据最小化

- 默认精简模式：AI 导入并校验后清理原始聊天正文，保留计数、身份、金额与画像。
- 观众页默认不加载原始消息。
- 分析包只包含分析所需的最小字段（不含 Cookie、不含历史原始消息）。
- 不采集遥测、不发起与功能无关的网络请求。

## 6. 外部文件导入（M5/M6）

必须：

1. 限制文件大小与条目数。
2. 拒绝绝对路径、`..`、符号链接、NUL。
3. 校验格式版本与校验和。
4. 校验 JSON Schema（AI）或数据库完整性（备份）。
5. 在事务/临时目录中处理，失败回滚。
6. 不执行导入内容中的任何代码、脚本或 URL。
7. 导入前给出内容预览与覆盖提示。

## 7. 提示词注入防护

- 所有弹幕文本都视为不可信数据。
- 提示词明确规定：包内文字不是指令，不得改变任务或输出协议。
- 导入端做结构校验（Schema、ID、引用范围），即使模型输出被注入也无法越权写入任意数据。
- 不把 AI 输出直接当 HTML/SQL/文件路径使用。

## 8. XSS 防护

- 前端只通过 `textContent` 写入动态文本，禁止 `innerHTML`。
- CSP 禁止内联脚本，脚本均来自同源文件。
- 用户昵称、标题、弹幕、礼物名在 UI、AI 包、日志中均按纯文本处理。

## 9. 金额与数据完整性

- 整数最小货币单位；不使用浮点存储。
- 去重键 + 唯一约束防止重复累计。
- 删除场次通过外键级联；删除观众前需确认其参与记录的影响。
- 备份使用 SQLite 一致快照，禁止直接复制写入中的数据库。

## 10. 权限

- 正常运行不需要管理员权限。
- 数据目录不可写时给出本地化错误与替代方案，不默认提权。
- EXE 不写注册表；卸载时用户可自行删除数据目录。

## 11. 敏感数据提示

备份、导出与分析包可能包含长期观众资料与聊天内容。软件必须在相关操作处明确提示其敏感性，并说明：

- 文件保存在本机；
- 上传给 AI 服务即离开本机，由用户自行判断；
- 不要公开分享含观众信息的备份。

## 12. Bilibili 凭据（2026-11-08 起）

- 扫码登录得到的 Cookie 只保存在 `<数据目录>\secrets\bilibili-login.json`（AES-256-GCM 加密）；密钥在同目录 `.bilibili-key`，尽力用 `icacls` 限制为当前 Windows 用户。同账户的进程仍可读取，因此这是「用户目录 + 加密」级别的保护，不是 DPAPI。
- 状态 API（`/api/bilibili/status`）只返回 `loggedIn`、`uid`、`name`、时间，不返回 Cookie。
- 日志脱敏覆盖 `SESSDATA`、`bili_jct`、`DedeUserID`、`Bearer …`、JSON 中的 `token/cookie/apiKey/secret/password`（本轮修复了一个会把原值重新拼回文本的正则缺陷）。
- 二维码登录页在系统默认浏览器中打开 Bilibili 自己的页面；应用不截屏、不上传、不把登录参数写入日志。
- AI 分析包不包含登录信息与 Cookie（导出只读取数据库事件与统计）。
- 观众身份来自平台 UID；平台不提供 UID（UID=0）时不猜测、不按昵称合并，也不会因此把观众写进别人的档案。

## 13. YouTube 接入（v0.5.0 起）

- YouTube 只使用公开直播页面的网页聊天机制：
  - 不发送 Cookie、OAuth token 或用户 API Key；不需要 Google 登录。
  - 不再是官方 Data API/OAuth/API Key 双轨实现；相关代码、配置读取、登录路由与 UI 已删除。
- 旧版本可能在 `<数据目录>\secrets\` 留下 `youtube-oauth.json` / `.youtube-oauth-key`；v0.5.0 **不读取也不再使用**这些文件，也不会自动删除用户凭据。用户可用“恢复出厂设置”或自行删除；迁移不会把它们带进新的数据空间之外的任何位置（仍是受管 `secrets/`）。
- `/api/youtube/status` 不再返回登录/令牌/配额字段；不提供伪造登录。
- 日志脱敏规则仍覆盖 `authorization`、`token`、`api[-_]?key`、`secret`、`refresh_token` 等键名与 `Bearer …` 值，作为纵深防御。
- **撤销与删除**：退出登录会先调用 Google revoke 端点（尽力而为），再删除本地加密文件；跨电脑迁移需要重新登录（密钥不导出，这是刻意设计）。
- **日志**：脱敏规则覆盖 `authorization`、`token`、`api[-_]?key`、`secret`、`refresh_token` 等键名与 `Bearer …` 值；YouTube `code`/`state` 不写日志。
- **回调安全**：回环接收器只绑定 `127.0.0.1`、只接受一次性随机端口与固定路径、校验 `state`、5 分钟超时、回调页无外部资源。

## 14. YouTube 数据保留与外部 AI

- YouTube 公开直播聊天属于平台数据。即使不再使用官方 API、也不需要 OAuth，仍采用 **30 个日历日** 的保守上限，而不是认为「非 API 就可以无限保存」。
- 实现：`youtubeRawRetentionDays` 只允许 **1–30 天**（默认 30）。超过窗口后清理：
  - 聊天原文 `events.content`；
  - 表情元数据 `events.emotes`；
  - 作者 badge `events.badges`；
  - 平台金额显示文本 `events.amount_display`；
  - 过期 YouTube 观众的昵称历史与当前昵称。
- 保留：事件行、消息计数、稳定 Channel ID、场次/观众币种合计。**这仍不等同于删除全部个人数据**；严格删除/去标识化模式尚未实现，文档不得声称已经完全合规。
- 触发：启动、YouTube 场次结束、`POST /api/youtube/retention/apply`。
- Bilibili 数据不受 Google/YouTube 政策约束，未被该清理自动处理。
- 公开网页聊天（唯一路径）：
  - 不发送 Cookie、OAuth token 或用户 API Key；
  - 仍会拿到公开的观众昵称、Channel ID 与聊天内容，因此同样受上述保留策略约束；
  - 该接口不是官方稳定 API，可能违反 YouTube ToS；不作为“官方/合规”宣传，设置页与隐私说明中如实告知可能失效。
- AI 分析包默认由用户手动导出并交给自选 AI 服务，软件不自动上传；v0.12.0 的自动分析只在用户明确同意后，由本地进程直接发送给已验证的匿名服务（见 §25）。包内不含凭据。导出前建议先执行保留清理。
- 不为了「长期画像」而绕过平台政策，也不改用抓取作为默认发布方案。

## 15. 公开网页接口的边界（v0.5.0）

- 只读：不发送消息、不点赞、不关注、不修改任何平台状态。
- 不携带任何用户登录态；不读取、不保存 Cookie。
- 不绕过登录、验证码、年龄墙、地区限制；被拒绝时显示真实原因。
- 不把网页接口的 key 当作用户凭据；它来自公开页面，只用于该次只读请求。
- 不把该接口描述为官方 API，也不声称获得 YouTube 授权或保证永久可用；设置页/隐私说明中保留简短、准确的失效风险提示，不在每次连接时堆叠技术模式警告。
- 该路径是 v0.5.0 唯一的 YouTube 连接方式；不再要求用户先切换模式。
- 真实采样、许可证与历史研究见 `docs/YOUTUBE_ANONYMOUS_RESEARCH.md`；旧官方 API 对照内容仅作历史记录。

## 16. 数据位置、迁移与本地目录选择（v0.5.0）

- 位置记录只含 `version/dataDir/updatedAt`，保存在 `%LOCALAPPDATA%\LiveMemory\data-location.json`，镜像到 `%APPDATA%\LiveMemory\data-location.json`；不含数据库内容、Cookie、Token 或 API Key。
- 位置记录目标必须已存在并含 `database/livememory.db`；否则启动失败，不创建空库、不覆盖旧数据。恢复方式：重新连接磁盘、`--data-dir` 或 `--forget-data-location`。
- 迁移拒绝：UNC 网络共享、磁盘根目录、Windows/Program Files/ProgramData 系统目录、用户主目录/桌面/下载/文档根目录、与源目录相同或嵌套、目标已有 LiveMemory 数据、空间不足。
- OneDrive/Dropbox/Google Drive、临时目录、长路径只警告并要求显式确认；**映射网络盘（盘符形式）未自动识别**，用户必须自行确认是本地磁盘。
- 迁移前停止适配器、checkpoint、关闭 SQLite；复制到目标卷 staging，校验 SQLite `integrity_check`、表计数、schema 版本与配置/凭据/导出文件 SHA-256；成功后移入目标并切换运行时。
- **原目录永远不由应用自动删除**；失败回滚到原目录。旧目录可能仍含敏感聊天与凭据，用户确认新目录可用后需自行安全删除。
- 目录选择器：本地服务用 `spawn(..., {stdio:'ignore'})` 启动固定 PowerShell 脚本，调用 WinForms FolderBrowserDialog；选择结果经临时文件返回，不经过 stdout 管道，不执行用户输入的命令，不使用 `cmd /c`。打开文件夹只接受 `data/exports/backups/logs` 四个受管键，不拼接任意路径。
- 管理员权限：发布 EXE 的 Manifest 为 `requireAdministrator`，但数据目录校验、迁移 staging/回滚、删除范围不因提权放宽。同账号 UAC 通常不改变 `%LOCALAPPDATA%`；跨管理员账号时应用扫描本地用户配置，恰好一个库则使用，多个则拒绝猜测。
- 迁移期间 API 进入维护模式，除 relocation/clear/health/status 外返回 503，避免并发写库。

## 17. 清空数据与恢复出厂（v0.4.0）

- 两种模式的范围见 `docs/STATUS.md` §2.3：
  - `data` 保留语言、主题、存储模式、数据目录、位置记录、平台登录凭据、`backups/`、日志与根目录无关文件；
  - `factory` 额外删除偏好、凭据、日志、缓存并重置默认设置；仍不删除位置记录、`backups/`、根目录无关文件或外部备份。
- 必须输入 `DELETE` / `RESET`；记录中禁用并由服务端再次校验（409）；不做“一键立即删除”。
- 默认创建数据库快照到 `%LOCALAPPDATA%\LiveMemory-Backups`（`LIVE_MEMORY_BACKUP_DIR` 可覆盖），**不在即将清空的数据目录内**。快照只含数据库，不含分析包/凭据/设置；不是 M5 `.livememory` 备份。
- 数据库删除在事务内，随后 `VACUUM` + WAL checkpoint；文件删除（`exports/`、`cache/`，factory 另含 `secrets/`、`logs/`）是尽力而为。极端断电可能留下部分文件，但数据库仍为空且下次启动会重新初始化。
- “清空数据”**不删除登录凭据**；如果用户希望同时清除授权，使用“恢复出厂设置”或在对应平台退出登录。
- 应用管理的目录：`config/`、`database/`、`secrets/`、`exports/`、`cache/`、`logs/`、`runtime/`、`backups/`。根目录其他个人文件与外部备份不属于清空范围。

## 18. 多主播身份、关联性与保留（v0.4.0）

- 主播维度关系表 `viewer_broadcasters` 会新增“同一平台账号出现在哪些主播处”的关联。这比单主播统计更容易识别跨频道活动，属于新增的链接性风险。
- 默认观众页、统计与 AI 包都以“当前主播”为范围；跨主播合计明确标注，不自动混入当前主播画像。AI 包只给其他主播的数量 `other_broadcaster_count`，不含其互动细节。
- 主播身份是公开频道标识（YouTube channelId / Bilibili anchor uid/room id），不是观众个人数据；但主播—观众关系仍是可关联数据。
- 保留规则不因新增关系表而放宽：
  - YouTube 30 天清理仍删除原文、emotes、badges、amount_display 与过期昵称；关系表只保留计数/稳定 ID/金额合计；
  - 删除观众（未来 UI）会级联删除其 `viewer_broadcasters` 与币种合计；
  - 恢复出厂删除全部关系表；
  - 旧 YouTube 场次无法确认主播时保持 `unresolved`，不猜归属。
- 目前没有“跨主播 AI 画像合并”；未来如提供，必须由用户明确选择，并标注证据来源与主播范围。

## 19. 历史搜索、归档与永久删除（v0.7.0）

- 搜索完全在本地 SQLite 执行，不调用 AI、不上传任何数据。搜索只读 `sessions`、`broadcasters`、
  `viewers`、`viewer_nicknames`、`viewer_sessions`，不把聊天正文加载到浏览器；观众下钻只取该身份在该场
  最近的 50 条消息。
- 搜索输入按字面处理（`%`/`_` 转义），不会因特殊字符扩大匹配范围；本地服务仍只监听 `127.0.0.1`，
  修改类请求继续受 Host/Origin 校验。
- 归档是可见性管理，不改变数据：归档场次仍保留全部消息、观众关系、统计、经济支持与 AI 包，仍可搜索/导出。
  默认列表隐藏只是 UI 过滤，不删除任何行。
- 永久删除是真实删除，不是隐藏：
  - 必须显式 `confirm:true` 且 UI 二次确认；正在记录或 adapter 未退出的场次被服务端拒绝；
  - 一个 SQLite 事务内删除该场次的消息、事件、经济支持、场次统计、观众参与关系、AI 包记录；
  - 受影响观众的全局/主播维度计数与币种合计按剩余证据重建；只存在于该场次的观众被清理；
    用户标记为重要的观众（`focused=1`）保留身份但计数归零；仍参与其他场次的观众与其他主播档案不受影响；
  - 提交后删除 `exports/` 内该场次的分析包文件；路径被限制在导出目录，不能删除其他文件；
  - 失败回滚，不会出现“删了一半”。删除不可撤销，本版本不提供回收站。
- 删除不等于去标识化的完全匿名：如果观众仍参与其他场次，其稳定平台 ID、其他场次计数与金额合计会保留；
  文档与界面不得把“删除单场”描述为“清除该观众全部个人数据”。要清除全部数据仍需“清空数据/恢复出厂”。

## 20. AI 分析结果导入与报告（v0.8.0）

AI 结果是**外部输入**，按不可信数据处理：

- **不执行**：不执行 AI 返回的代码、命令、URL；不打开其指定的路径；结果不能修改设置、凭据、数据目录或
  原始事件。导入只接受 JSON（可剥离一层代码围栏），不接受 ZIP 或任意脚本。
- **不注入**：结果按字段白名单重建、清除控制字符；前端全部通过 `textContent` 渲染。
  `<script>`、`<img onerror>`、链接等只会显示为普通文本，不会成为 DOM。
- **不记账**：结果 Schema 没有金额/计数写入口；AI 摘要中的数字不会写回 `events`、场次统计或观众聚合。
  金额、币种、时间和稳定平台身份仍以本地数据库为准。
- **身份不猜测**：`viewer_profiles` 只能引用该批次 `viewer_context` 中的稳定 `viewer_id`；
  昵称不参与身份解析；不同平台/不同 UID 不合并；跨主播的观众身份不会因为同名而关联。
- **证据可验证**：每个 `message_refs` 都映射到导出时的 `seq → event_id`；报告只从真实 `events` 行
  读取昵称、时间和原文。原文已被保留策略清理或行已删除时，报告明确显示“原文不可用/已删除”，不重建内容。
- **范围限制**：结果必须匹配场次、任务、批次、主播快照；时间必须落在直播记录窗口内；汇总结果必须等
  所有批次结果存在。未通过校验的内容不写入（单事务，失败回滚）。
- **版本与重复**：相同内容重复导入不写第二行；不同内容必须显式创建新版本；旧版本保留，报告使用最新版本。
  这避免 AI 重试或重复上传造成重复统计，也避免静默覆盖历史。
- **删除**：删除场次于同一事务删除 `ai_jobs`、`ai_job_batches`、`ai_job_messages`、`ai_job_viewers`、
  `ai_results`、`ai_result_evidence` 与 `ai_packages`，提交后删除批次包与汇总包文件。清空数据包含全部 AI 表。
- **导出**：分析包不含 Cookie、Token、API Key 或凭据；只含本地记录的聊天、统计、稳定 ID 与主播上下文。
  用户把包上传到外部 AI 服务属于用户自己的选择，LiveMemory 不做任何上传。

### 20.1 保留与已知限制

- YouTube 30 天策略会清理事件正文、表情/徽章元数据、金额显示文本与过期昵称；报告随后把相关证据标记为
  “原文不可用”。保留计数、稳定 ID、金额合计与 AI 结果行。
- **已导入的 AI 结果（摘要、话题、观众画像）不会因 YouTube 30 天清理自动删除**。它们是本地衍生数据，
  含稳定观众 ID 与 AI 推断，默认保留到用户删除场次或清空数据。这是已知限制：
  - 不得声称“手动导入的 AI 结果自动符合平台保留政策”；
  - M7 若做长期观众画像，必须把 AI 画像纳入保留/去标识化/单版本删除策略；
  - 用户可通过删除场次、清空数据或恢复出厂移除这些衍生数据。
- 本版本没有单结果版本删除 UI/API；版本只追加。若用户需要彻底移除某场 AI 数据，删除整个场次是唯一入口。
- AI 结果不会跨主播合并：每个任务只包含一个场次/一个主播的上下文；报告也不会把其他主播数据混入。

## 21. AI 长期记忆（M6 更新）

- 当前没有独立的“长期 AI 画像”表；M6 的 `viewer_profiles` 存在于每场的结果 JSON 与报告中，属于场次级衍生数据。
- 观众身份仍以 `viewers.id`（platform:stable_uid）为唯一锚点；AI 结果不能创建新观众、不能修改昵称或计数。
- 跨主播的 AI 画像必须在 M7 明确设计：只能按“主播 × 观众”维度保存，必须带证据与版本，且能随原文清理而
  降级/删除；禁止把 `lifetime` 或其他主播数据写成本主播画像。
- 删除场次会删除该场所有 AI 结果；未来若引入跨场画像，删除/保留策略必须先于功能实现。

## 22. 长期观众记忆（M7 / v0.9.0）

- **隔离**：记忆行唯一键是 `(broadcaster_id, viewer_id)`。读取、写入、删除、证据解析、版本回滚、
  AI 更新包导出全部限定在单个主播；同一平台账号在其他主播处拥有独立记忆，界面不提供合并。
  更新包只包含本主播的 `broadcaster_context` 与 `lifetime` 计数，不含其他主播的内容。
- **AI 仍是不可信输入**：记忆更新结果按字段白名单重建；`viewer_id` 必须在该批次名单内；
  `target_fact_id` 必须是该观众现有事实；证据必须命中真实 `seq → event_id`。
  结果不能修改金额、计数、事件、设置或凭据。
- **不把推断变事实**：`certainty` 三态与 `status` 五态分开存储；只有主播手动确认才写 `user_verified`。
  `stated` 必须有引用消息，否则导入被拒绝；无证据的 `inferred` 自动降级为 `uncertain`。
- **敏感属性**：提示词明确禁止推断健康、性取向、宗教、政治、财务状况、真实姓名、住址、联系方式；
  礼物金额不得用于推断经济能力、人格或忠诚度。软件不提供这些字段。
- **删除单个观众的记忆**：`POST /api/memory/viewers/:id/delete`（必须 confirm）删除事实、证据与全部版本，
  记忆头保留为空墓碑；删除时间晚于更新包生成时间时，该旧包被拒绝，防止恢复已删除数据。
  本地一键合并同样不会复活已删除的记忆。
- **原文清理后的证据状态**：YouTube 30 天保留策略清理原文、表情/徽章、金额显示文本与过期昵称后，
  记忆事实保留，但其证据状态变为 `purged`（部分为 `partial`）；事件行被删除则为 `unavailable`。
  界面明确显示「原文已清理 / 来源已删除」，不再声称可以验证。
- **删除场次**：同事务删除该场的 `memory_jobs`（级联批次/映射/结果）与导出文件；
  引用该场的记忆事实保留，证据降级为不可用。这是刻意的：主播积累的记忆不应因删除一场聊天而静默丢失。
- **清空/恢复出厂**：覆盖 `viewer_memories`、`memory_facts`、`memory_fact_evidence`、`memory_versions`、
  `memory_jobs`、`memory_job_batches`、`memory_job_messages`、`memory_job_viewers`、`memory_results`。
- **清理长期未出现的观众**：`POST /api/memory/prune` 默认 `dryRun:true` 只预览；删除需要显式
  `dryRun:false`，范围 30–3650 天，删除后同样留下墓碑。
- **保留策略（如实）**：记忆保留到用户删除（或清空数据）；证据可用性跟随平台原文保留窗口。
  软件不会因为「记忆是本地衍生数据」就宣称自动合规；长期画像的保留由用户控制。

## 23. 自动监听（P7 / v0.10.0）

- **存储**：`monitor_targets` 只保存平台、真实房间号/频道 ID、展示名、用户输入、主播身份、
  调度时间、错误码与最后/当前场次 ID。不保存聊天、视频、音频或页面 HTML。
- **网络行为**：等待开播时只做低频、只读的公开状态请求。
  - Bilibili：`room/v1/Room/get_info`。若用户已登录，请求会带其现有 Cookie（与手动连接相同），
    Cookie 仍只存于加密凭据库，不写日志；匿名状态也能检测。
  - YouTube：公开 `/channel/<id>/live`（解析失败时 RSS + watch 页）。**不发送 Cookie、OAuth、
    API Key 或登录态**。
- **不绕过访问控制**：不处理验证码、不使用代理轮换、不建立账号池、不伪造身份。
  遇到 403/429/验证/登录要求时按错误显示并退避；连续失败进入可见 `error`。
- **不下载媒体**：发现直播后只建立现有聊天连接；不下载视频/音频，也不抓取普通视频或评论。
- **用户控制**：可暂停监听（当前记录继续）、恢复、立即检查、删除目标；删除目标不删除历史场次。
  `DELETE /api/monitoring/:id` 需要 `confirm:true`，记录中拒绝。
- **单实例**：监听调度在本地服务进程内运行；浏览器窗口只调用本地 API，不会各自轮询平台，
  因此多开页面不会放大请求量。软件关闭后不继续监听。
- **错误可见**：界面显示稳定错误码对应的三语原因与下次重试时间，不做无限静默重试。
- **页面变化**：YouTube 公开页面不是官方稳定 API；解析失败会尝试 RSS 回退，仍失败则显式报错。
  LiveMemory 不声称获得 YouTube 授权，也不保证长期可用。

## 24. 统一分析与长期记忆（P8 / v0.11.0）

- **范围**：长期记忆按 `broadcaster × viewer` 隔离；同一位观众在不同主播处是两份独立记忆。
  统一分析包只包含当前主播的数据，不包含其他主播的聊天或记忆。
- **所有可识别观众**：每位有稳定 ID 的观众都会进入本场分析包与记忆覆盖表；没有最低发言次数
  或活跃度筛选。只有礼物/SC 的观众也会进入，但只更新平台实际提供的客观互动记录。
- **客观 vs 语义**：首次/最近、场次、发言数、支持等由本地真实记录确定性计算，AI 输出不能修改；
  AI 只提出兴趣/经历/状态等语义事实，必须有证据或明确标记为推断/待确认。
- **不编造**：普通问候、表情、刷屏或付费事件不能推断性格、兴趣、经济能力或忠诚度；
  没有语义信息时允许 `no_new_information`，但仍标记为已处理。
- **证据**：语义事实的证据 seq 必须命中本批次 `ai_job_memory_messages`，且消息作者必须与
  `viewer_id` 一致；跨批次、他人消息、不存在的 seq 全部拒绝。原文被清理后只降级证据。
- **旧包与删除**：记忆删除后，删除时间晚于任务创建时间的旧包会被拒绝；客观历史不会复活已删除的
  语义记忆。重复导入不会重复计数或重复创建事实。
- **独立工作流移除**：不再提供独立长期记忆 AI 任务或页面；用户只执行一次分析包往返。
  观众详情仍可查看、确认/修正、回滚与删除记忆，删除操作与旧 M7 规则一致。
- **本地优先**：没有云端记忆、账号体系或遥测；手动路径由用户自行选择 AI 文件往返，自动路径见 §25。

## 25. 自动 AI 分析（P9 / v0.12.1）

- **默认关闭**：用户必须点击「自动 AI 分析」并在自定义对话框确认后才会发送数据；服务端要求
  `consent:true`，没有后台自动上传、没有遥测。
- **发送范围**：只发送当前分析任务的包内容——本场聊天（含昵称、稳定观众 ID、平台表情元数据）、
  `viewer_context`、`memory_context`（已有观众记忆）、`viewer_excerpts`、本地统计上下文与结果 Schema。
  v0.12.1 起 `memory_context` 不再重复 `viewer_context` 的累计字段，并附带该观众允许引用的
  `evidence_seqs`；发送的数据量更小，范围不变。
  不发送数据库文件、Cookie/Token/API Key、操作系统账户信息、与本场无关的历史直播或软件日志。
- **模型不处理身份**：v0.12.1 自动批次只让模型返回 `ref` 与语义内容；稳定观众 ID 由本地
  程序按批次分配表填入，模型从不接收“要求复制 ID”的任务，也不能提供新身份。
- **第三方处理**：当前唯一 provider 为 OVHcloud AI Endpoints（`gpt-oss-20b`）。其官方文档声明
  数据不存储、基础设施在欧洲；但第三方处理仍受其条款与隐私政策约束，软件不得声称“所有匿名服务都不保存数据”。
- **无开发者服务器**：请求由本地进程直接发往第三方，不经过任何 LiveMemory 云端代理、网关或账号。
- **无凭据**：请求不带 `Authorization`、Cookie、用户 API Key；不使用开发者密钥。
- **频率**：官方匿名 2 请求/分钟/IP/模型；客户端串行、2/60s 限流、尊重 `Retry-After`，
  单次运行有请求预算，避免消耗公共免费资源。
- **输出安全**：模型返回内容是不可信外部输入，必须经现有 Schema/业务校验与事务导入；
  不执行脚本/命令/HTML，不打开其路径。
- **日志最小化**：只记录事件名、job/batch id、provider、HTTP 状态、耗时与错误码；
  不记录提示词、聊天正文或模型回答。`runtime/ai-auto.json` 同样不含内容。
- **失败不影响本地数据**：自动失败只写状态与错误码；不删除手动结果、不覆盖已有长期记忆、
  不自动创建新版本、不切换到手动模式（手动入口始终保留）。
- **保留与删除**：自动导入的分析结果/记忆仍按 M6/M7 规则保存到用户删除场次或清空数据；
  YouTube 30 天清理继续影响证据可用性，不会因为来源是 `auto` 而改变。
- **失败提示**：界面只显示规定红色文案；「查看详情」可显示匿名服务不可访问、429、超时、
  JSON/Schema 不合法、规模超限等稳定错误码，便于排查。
- **未知/限制**：OVH 匿名通道可能限流或下线；没有第二个已验证 provider；真实 EXE 网络行为尚未验收。
  这些必须在状态/交接文档中如实保留，不能把“曾经测通”写成“永久可用”。

## 26. 用户自带 AI API（v0.13.0）

- **凭据存储**：API Key 写入 `<数据目录>/secrets/ai-keys.json`，AES-256-GCM + 每安装随机密钥；普通配置 `<数据目录>/config/ai-providers.json` 只保存 `credentialReference`。这不是 DPAPI：同一 Windows 用户的其他进程仍可能读取密钥与密钥文件；文档与界面都如实说明。
- **区域隔离**：同一 Provider 的不同区域是独立配置；切换区域/Base URL 会生成新的 credential reference，旧 Key 不再被复用。
- **发送目的地**：已知 Provider 只允许其官方区域 Base URL；自定义 Base URL 必须显式配置。服务端阻止云元数据、私网地址与 localhost，除非用户显式勾选 `allowLocalNetwork`（本地模型场景）；请求前做 DNS 解析检查。API Key 只发送到该配置确认的 Base URL。
- **不进入日志/导出**：日志、状态文件、分析 ZIP、数据库导出、错误详情与前端 HTML 均不包含 Key。状态文件只保存 provider/model/job/stage/usage。
- **数据范围**：单场任务发送本场聊天、统计、时间线与表情；画像任务额外发送本场相关观众摘录与已有长期记忆。不会发送数据库文件、Cookie、无关历史直播或系统账户信息。
- **付费与预算**：费用状态由实际模型/服务商价格决定；未知价格保持 unknown 并需要显式确认。画像是 opt-in；预算保护只对已知价格/币种生效。估算不是最终账单。
- **删除**：删除配置会删除对应加密密钥；清空数据会清理 config/secrets。远程服务商是否保留请求数据由该服务商政策决定，LiveMemory 无法撤回。
