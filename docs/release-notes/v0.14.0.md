# LiveMemory v0.14.0 — Multi-Platform Release

> **Stable release** · Windows 10/11 x64 · Local-first · MIT (source)
>
> Build ID `17f84b1956e1` · EXE SHA-256 `6862079a025fa08d5b7fcf82c16cc3152fedbb7852866022dad4c96977bbe0d9`

LiveMemory is a local-first livestream memory app for Windows. It records chat, gifts, Super Chats
and membership events from live streams, keeps per-stream statistics, and builds long-term viewer
profiles using **your own AI provider API key**. There is no developer server, no account, and no
telemetry: the database, the AI requests and the reports all stay on your computer.

This release is the first stable release of the **five-platform** version: Bilibili Live,
YouTube Live, Twitch, Douyin Live and TikTok Live.

---

## Highlights

- **Five live platforms in one local app** — Bilibili, YouTube, Twitch, Douyin and TikTok, each with
  its own adapter, connection state and per-stream session.
- **Recording needs no account on any of the five** — public live rooms only. No developer API
  application, no paid capture service, no third-party signing service.
- **Concurrent multi-stream recording** — several rooms at once, each with an independent tab,
  connection state, statistics and stop action. Starting the same platform + room twice is refused.
- **Long-term viewer memory** — facts with certainty, status history and per-message evidence,
  scoped per broadcaster × viewer and keyed by the platform's stable user ID.
- **AI analysis with your own key** — one entry point: pick a stream, pick a configured model, pick
  the scope, start. Session report and long-term profile are saved independently.
- **One-file backup, restore and migration** — a single `.livememory` archive with a consistent
  SQLite snapshot and full checksums; restore keeps a pre-restore copy and can be rolled back.
- **Three UI languages** — Simplified Chinese, Japanese and English, following the system language
  unless you choose otherwise, with a built-in user guide.

## Supported Platforms

| Platform | Live chat capture | Stable viewer ID | Login for chat | Paid events |
| --- | --- | --- | --- | --- |
| **Bilibili Live** | Public live WebSocket (verified in real rooms) | Platform UID — may be masked to `uid=0` when logged out | Not required (optional QR login improves identity) | Gifts / Super Chat / guard mapped from public protocol |

**Read this table literally.** “Verified” means the event was observed on a real live room during the
project's own acceptance runs. “Parsed / not observed” means the code path and automated tests exist,
but no real event of that type was seen — it must not be read as “supported and confirmed”.

## Improvements

### New platform integrations

- **Twitch (new)**: anonymous IRC chat plus read-only public channel metadata. No Twitch account,
  OAuth token, API key, cookie or paid capture service. Channel links or account names start
  recording; automatic live monitoring is supported. Acceptance: 6 public channels concurrently for
  60 seconds produced 418 events, **418/418 carrying a stable user ID and a message ID**; one real
  resub notification was observed.
- **Douyin / 抖音 (new)**: public room page plus an anonymous signed WebSocket. Nickname, stable UID
  (`douyin:<user.id>`), original chat text, Unicode/emoji, message ID, dedupe, reconnect, two-step
  offline confirmation, multi-room isolation and automatic live monitoring. Gifts require login;
  sign-in uses your own Chrome/Edge on the official page and shows the same QR code, never bypassing
  captcha or risk control.
- **TikTok (new)**: capture is unified on the **anonymous local `webcast` WebSocket** using only the
  anonymous `ttwid` device cookie every visitor receives. No account, no QR login, no cookie import,
  no browser relay and no paid or community signing service. Room metadata, host ID, title and gift
  catalogue are read locally from TikTok's public endpoints. This is **not** an official TikTok API:
  it is an unofficial web protocol, it is experimental, and it may break at any time.
- **Concurrent TikTok rooms**: the previous front-end treated “any TikTok recording exists” as
  “this room is already recording” and disabled the start button. That restriction is now scoped to
  the same room, so several different TikTok LIVE rooms can be recorded at once.

### Recording, identity and continuity

- Every event of all five platforms goes through the same ingest pipeline: dedupe by
  `UNIQUE(session_id, dedupe_key)`, viewer aggregation keyed by `platform:stable_uid`, amounts summed
  per currency and per value kind.
- Anonymous sessions without a stable ID are never merged into someone else's profile: `uid=0` and
  missing IDs produce unidentified messages instead of a fake identity.
- Reconnect with exponential backoff and jitter; platform errors are reported as real errors, never
  silently converted into “connected”. Two consecutive offline confirmations are required before a
  stream is considered ended, and network failures are not treated as “stream offline”.
- Multi-room isolation: stopping one room does not affect the others; a failed capture does not stop
  the remaining rooms; switching tabs or reloading the page does not stop background capture.

### AI analysis and long-term memory

- One analysis entry point with five steps (stream → provider configuration → scope → scale → start).
- Batch-level saving, bounded retries, per-viewer failure isolation and Resume, so one bad viewer does
  not drag down the whole stream; completed batches are never re-requested.
- Long-term profile validation covers schema, identity, evidence and coverage; facts without evidence
  and cross-viewer evidence are rejected. History versions can be inspected and rolled back.
- Provider-reported token usage with an **estimated** cost based on the prices you enter. The estimate
  is not an invoice.

### Backup, restore and migration

- Single-file `.livememory` archive: sessions, chat, viewers, payments, long-term memory, AI reports and
  settings. API keys and platform credentials are excluded.
- Consistent SQLite snapshot (`VACUUM INTO`), full checksums, transactional restore, pre-restore
  snapshot, and crash recovery through a restore journal.

### Internationalization groundwork (planning only)

- This release adds **planning documents only** for a ten-language UI, an independent AI output
  language, and a platform admission standard. **No new language and no new platform is included.**
  See “What's Next”.

## Fixes

- **Douyin opened two login browser windows** on Windows: the login session is now created once and
  reused, including when the window is closed and reopened.
- **Douyin login state is verified** instead of assumed: cookie format, incompleteness, expiry,
  platform refusal and network failure are reported as distinct states.
- **TikTok frames were parsed as the wrong type**: `PushFrame` was treated as `WebcastResponse`, so a
  real connection could report zero events. Frames are now decoded correctly, and a `403` from the
  room page is no longer misread as “login expired”.
- **TikTok capture state was invisible**: the connect response now reports the real capture state
  (configured / room refused / room unconfirmed / receiving events) instead of a generic failure.
- **TikTok reconnect loop**: the capture path now honours the platform's rate limits, reports
  `rate_limited` separately from `failed`, and stops re-reading already-processed history.
- **TikTok room list did not refresh** after adding or removing a room; it now updates in place.
- **Stale TikTok browser profile**: an old version left a dedicated browser profile on disk; startup
  now removes only the directories LiveMemory itself marked as owned, and never touches your normal
  Chrome/Edge profiles.
- **Simulated-live UI removed** from the production interface. The simulator remains an internal test
  fixture and historical simulated sessions are still readable.

## Known Limitations

- **Unofficial paths may break.** YouTube uses the public watch page, TikTok uses an unofficial web
  protocol, and Twitch uses anonymous IRC plus public web data. None of these is an official stable
  API, and none is claimed to be “authorized” or “compliant”. When a platform changes, capture fails
  and reports the real reason.
- **TikTok and Douyin have no resume cursor.** Messages may be missed while reconnecting; the app does
  not claim complete chat coverage for those platforms.
- **Not every paid event type has been observed.** Twitch Bits and gifted subscriptions, Douyin gifts
  and TikTok gift / subscription events are parsed and covered by automated tests but were **not
  observed** on a real stream during acceptance. Amounts without a local currency value are stored as
  unknown and are never converted into streamer income.
- **Bilibili may mask identities when logged out.** The platform can mask nicknames and send `uid=0`;
  those messages cannot be attributed to a stable viewer, and historical masked messages are never
  guessed back.
- **AI output can be wrong.** Long-term profiles are organized summaries, not verdicts. Expand the
  original evidence before relying on a fact; the app does not force review, but it also does not treat
  AI output as ground truth.
- **Provider verification is uneven.** DeepSeek has been exercised through the real paid path; the
  other providers are implemented and covered by local/Mock tests but have not each been individually
  verified with real paid traffic. Run the capability test before relying on a provider.
- **UI languages are three.** Simplified Chinese, Japanese and English. The ten-language plan in this
  release is a roadmap, not a feature.
- **Data retention**: platform chat originals are purged after the retention window (default and
  maximum 30 days), keeping counts, stable IDs and amount totals. This is not equivalent to full
  deletion of personal data; see the privacy documentation.
- **Unsigned binary.** There is no code-signing certificate, so Windows SmartScreen may show “unknown
  publisher”. Verify the SHA-256 below.
- **No clean-Windows acceptance.** The app has not been validated on a clean Windows installation, all
  antivirus combinations, or every Windows build. The UAC prompt is a standard Windows prompt and
  remains a manual check.
- **Not tested**: long multi-room stress runs, real NIC disconnection, real long offline periods, and
  a real mobile QR scan for Douyin login.

- **Ten-language UI** (`ko`, `es`, `pt-BR`, `zh-TW`, `fr`, `de`, `id` on top of the current three):
  planned in milestones, starting with an architecture pass that adds no language yet.
- **Independent AI output language**: today the analysis output language defaults to the UI language
  and can be overridden per run. A separate, persisted setting — and the long-term-profile
  compatibility questions around switching it — is planned.
- **Kick technical feasibility**: a candidate investigation has been completed (anonymous public chat
  read path, stable sender ID, licence review of existing open-source implementations). **No Kick
  support is included, and none will be claimed until a real connection is verified.**
- Additional candidate platforms (Huya, Douyu, CHZZK, SOOP, Kuaishou, Niconico, Xiaohongshu, YY,
  Facebook Live) are investigation-only at this point.

These items are **not implemented**. The UI language count, the AI output language setting and all
platforms other than the five above remain unchanged.

## Installation

1. Download `LiveMemory-v0.14.0-windows-x64.zip`.
2. Verify the archive with `SHA256SUMS.txt` (see “Checksums”).
3. Extract to any writable folder — there is no installer.
4. Double-click `LiveMemory.exe`. Windows shows the standard **UAC administrator prompt**; choose
   “Yes” to start, or “No” to cancel. Right-clicking “Run as administrator” is not required, and the
   app never bypasses or disables UAC.
5. The console opens the local console page in your default browser. If it does not open, run
   `LiveMemory.exe` again instead of opening an old address manually.
6. On first use, pick your language and theme in Settings, then create a full backup.
7. To use AI: Settings → AI Provider → add your provider, model and API key → run the capability
   test → then start an analysis from the AI page.
8. Data is stored in `%LOCALAPPDATA%\LiveMemory\` by default.

**Upgrading from v0.13.2-rc.0**: replace the old `LiveMemory.exe`; the data folder is unchanged.
Database migrations run automatically on first start. Create a full backup before upgrading.

**Third-party costs**: AI analysis is billed by your provider, not by this project. The cost shown in
the app is an estimate based on the prices you enter.
