# LiveMemory v0.19.0 — AI Provider Reliability Update

**Official release.** Version `0.19.0`, database schema **16** (no migration).
This release focuses on making AI provider configuration reliable for everyday users. Live
platform support is unchanged: six platforms are released and usable; **Kuaishou remains a
preview with live capture disabled**.

## English

### What changed

- **API configuration can be saved reliably.** DeepSeek, OpenCode, and custom
  OpenAI-compatible providers no longer fail to save because of a harmless Base URL difference.
  A trailing slash, host letter case, or an explicit default port is treated as the same
  endpoint, not as a new provider.
- **Pasted API keys work.** A key copied from a provider dashboard often ends with a newline.
  LiveMemory now trims outer whitespace before validating it; an internal line break is still
  rejected because it would corrupt the authentication header.
- **Saved keys are no longer lost.** Credential writes are transactional: a new key is written
  first, the configuration is saved, and the old key is removed only after success. If saving
  fails, the previous key is restored. A failed save no longer leaves a half-written config.
- **The encrypted credential store is protected.** If the local credential file or its
  per-install key is unreadable, LiveMemory reports the problem and refuses to overwrite it.
  A damaged provider configuration is preserved as a backup instead of being silently replaced.
- **OpenCode compatibility is improved.** Custom OpenAI-compatible endpoints that point at
  `opencode.ai` now receive the required session header. The built-in OpenCode provider remains
  the recommended choice.
- **Errors are specific and actionable.** The settings page now distinguishes missing fields,
  invalid URLs, changed endpoints, local file permissions, a locked file, a full disk, a
  read-only folder, and a damaged credential store. The localized message, a stable error code,
  and the relevant path appear next to the save/test button. API keys, authorization headers,
  cookies, and tokens are never shown.
- **Provider switching remains safe.** Switching to a different provider, region, or Base URL
  still requires a new API key, because the old key must never be sent to an unconfirmed
  endpoint. This is a security rule, not a lost configuration.

### Data and upgrade

- Your live recordings, viewers, long-term profiles, AI jobs, and saved reports are unchanged.
- Database schema is still **16**; no migration is required.
- Existing provider configurations and encrypted keys are preserved. Valid configurations are
  read normally.
- **You do not need to delete configuration files, clear AppData, or reinstall LiveMemory.**
  Replace `LiveMemory.exe` with this release.
- A damaged configuration or credential file is preserved with a timestamped backup before you
  are asked to add the provider again.
- Creating a full backup before upgrading is still recommended.

### Verification

- Full automated suite: **1,269 passed / 0 failed / 0 skipped** (871 unit + 398 integration).
- Windows EXE: `requireAdministrator` manifest, `verify-provider-save-exe` **14/14**,
  `verify-exe` **11/11**, `verify-help-exe` **14/14**, `verify-ai-token-exe` **16/16**.
- The EXE build ID, size, and SHA-256 are recorded in the repository's `docs/STATUS.md`;
  size and SHA-256 are also in `SHA256SUMS.txt`.

### Known limitations

- **No real paid OpenCode inference was run in this release** (no real key). OpenCode protocol
  and model-list integration are covered by automated and mock tests; real billing,
  `usage.cost`, and 429/5xx behavior still require a user-supplied key and explicit spend
  approval.
- Real paid verification for OpenAI, Anthropic, MiniMax, Alibaba Cloud Model Studio,
  OpenRouter, and fully custom endpoints is still provider-by-provider work.
- Kuaishou remains a preview; live H5 capture stays disabled until written permission is
  obtained.
- **Real double-click UAC (accept/deny), a clean Windows account, the native file dialog, and
  real provider billing were not manually verified in this release.** The EXE is unsigned, so
  SmartScreen may warn about an unknown publisher.
- Twitch Bits/gifted subscriptions, Douyin gifts, TikTok gifts, and some Kick lifecycle events
  remain `NOT-OBSERVED`.

## 简体中文

### 本次修复

- **API 配置可以可靠保存。** DeepSeek、OpenCode 和自定义 OpenAI-compatible Provider 不再因为
  Base URL 的无害差异而保存失败。末尾斜杠、主机大小写或显式默认端口会被视为同一个端点，
  而不是换了一个服务商。
- **粘贴的 API Key 可以正常使用。** 从服务商页面复制的 Key 常带尾部换行；LiveMemory 现在会先
  去掉外层空白再校验。内部换行仍会被拒绝，因为它会破坏认证请求头。
- **已保存的 Key 不会丢失。** 凭据写入改为事务式：先写新 Key，再保存配置，成功后才删除旧 Key；
  保存失败会恢复旧 Key，不再留下半写状态。
- **本地加密凭据库受到保护。** 凭据文件或每安装密钥不可读时，LiveMemory 会明确报错并拒绝覆盖。
  损坏的 Provider 配置会先保留时间戳备份，而不是被静默替换。
- **OpenCode 兼容性改进。** 自定义 OpenAI-compatible 地址指向 `opencode.ai` 时，会补发所需的
  会话请求头；仍建议优先使用内置的 OpenCode Provider。
- **错误提示更准确。** 设置页会区分必填字段缺失、URL 无效、端点变化、文件权限不足、文件被占用、
  磁盘空间不足、目录只读和凭据库损坏。本地化提示、稳定错误码和相关路径显示在保存/测试按钮旁；
  不会显示 API Key、认证请求头、Cookie 或 Token。
- **切换 Provider 仍然安全。** 更换服务商、区域或 Base URL 时仍需重新输入 Key，因为旧 Key
  不能被发送到未经确认的新地址。这是安全规则，不是配置丢失。

### 数据与升级

- 直播记录、观众、长期画像、AI 任务和已保存报告均不受影响。
- 数据库 Schema 仍为 **16**，无需迁移。
- 已有 Provider 配置与加密 Key 会保留，正常配置可以照常读取。
- **不需要删除配置文件、清空 AppData 或重新安装。** 直接用本版本替换 `LiveMemory.exe` 即可。
- 如果配置或凭据文件已损坏，LiveMemory 会先保留带时间戳的备份，再请用户重新添加服务商。
- 升级前仍建议创建一次完整备份。

### 验证

- 全量自动化：**1,269 passed / 0 failed / 0 skipped**（871 unit + 398 integration）。
- Windows EXE：`requireAdministrator`；`verify-provider-save-exe` **14/14**、
  `verify-exe` **11/11**、`verify-help-exe` **14/14**、`verify-ai-token-exe` **16/16**。
- EXE 的 Build ID、大小与 SHA-256 见仓库 `docs/STATUS.md`；大小与 SHA-256 也记录在
  `SHA256SUMS.txt` 中。

### 已知限制

- **本版未使用真实 OpenCode Key 发起付费推理**。协议与模型列表由自动化和模拟测试覆盖；
  真实账单、`usage.cost` 与 429/5xx 行为仍需用户提供 Key 并明确授权费用。
- OpenAI、Anthropic、MiniMax、阿里云百炼、OpenRouter 与完全自定义端点的真实付费验收仍需
  逐个 Provider 进行。
- 快手仍为预览；在取得书面许可前，实时 H5 采集保持禁用。
- **真实双击 UAC（同意/拒绝）、干净 Windows 账户、原生文件对话框和真实 Provider 账单
  未在本版人工验证。** EXE 未签名，SmartScreen 可能提示未知发布者。
- Twitch Bits/赠订、抖音礼物、TikTok 礼物和部分 Kick 生命周期事件仍为 `NOT-OBSERVED`。

## 日本語

### 今回の修正

- **API 設定を確実に保存できるようになりました。** DeepSeek、OpenCode、カスタムの
  OpenAI-compatible Provider が、Base URL の無害な違いで保存に失敗しなくなりました。
  末尾のスラッシュ、ホスト名の大文字小文字、明示された既定ポートは同じ接続先として扱われ、
  別の Provider とは判定されません。
- **貼り付けた API Key が使えます。** Provider の画面からコピーした Key には末尾の改行が
  付くことがあります。LiveMemory は外側の空白を除去してから検証します。内部の改行は
  認証ヘッダーを壊すため、引き続き拒否します。
- **保存済みの Key を失わなくなりました。** 認証情報の書き込みをトランザクション化しました。
  新しい Key を書き、設定を保存し、成功した後だけ古い Key を削除します。保存に失敗した場合は
  以前の Key を復元し、中途半端な設定を残しません。
- **暗号化された認証情報ストアを保護します。** 認証情報ファイルまたはインストール固有の
  キーが読めない場合、問題を報告し、上書きを拒否します。破損した Provider 設定は
  タイムスタンプ付きのバックアップとして保存されます。
- **OpenCode の互換性を改善しました。** カスタムの OpenAI-compatible 接続先が
  `opencode.ai` を指す場合、必要なセッションヘッダーを送信します。引き続き組み込みの
  OpenCode Provider の利用を推奨します。
- **エラー表示が具体的になりました。** 必須項目の不足、URL の形式、接続先の変更、
  ファイル権限、ファイルの使用中、ディスク容量不足、読み取り専用フォルダー、
  認証情報ストアの破損を区別します。ローカライズされたメッセージ、安定したエラーコード、
  関連パスを保存/テストボタンの近くに表示します。API Key、認証ヘッダー、Cookie、Token は
  表示しません。
- **Provider の切り替えは引き続き安全です。** Provider、リージョン、Base URL を変更する際は
  新しい API Key が必要です。古い Key を未確認の接続先へ送らないための安全規則であり、
  設定の消失ではありません。

### データとアップグレード

- 配信記録、視聴者、長期プロフィール、AI タスク、保存済みレポートは変更されません。
- データベース Schema は **16** のままで、移行は不要です。
- 既存の Provider 設定と暗号化された Key は保持されます。正常な設定はそのまま読み込まれます。
- **設定ファイルの削除、AppData の消去、再インストールは不要です。**
  `LiveMemory.exe` をこのリリースで置き換えてください。
- 設定または認証情報ファイルが破損している場合は、タイムスタンプ付きのバックアップを
  保存してから、Provider の再追加を案内します。
- アップグレード前の完全バックアップを引き続き推奨します。

### 既知の制限

- **本リリースでは実際の OpenCode Key による有料推論を実行していません。**
  プロトコルとモデル一覧は自動テストとモックで検証していますが、実際の請求、
  `usage.cost`、429/5xx の動作は、ユーザー提供の Key と費用承認が必要です。
- OpenAI、Anthropic、MiniMax、Alibaba Cloud Model Studio、OpenRouter、完全カスタム接続先の
  実際の有料検証は、Provider ごとに未完了です。
- 快手はプレビューのままで、書面許可が得られるまでリアルタイム H5 収集は無効です。
- **実際のダブルクリック UAC（許可/拒否）、クリーンな Windows アカウント、ネイティブの
  ファイルダイアログ、実際の Provider 請求は本リリースで手動検証していません。**
  EXE は署名されていないため、SmartScreen が未知の発行元として警告する場合があります。
- Twitch Bits/ギフトサブスク、Douyin ギフト、TikTok ギフト、一部の Kick ライフサイクル
  イベントは `NOT-OBSERVED` のままです。
