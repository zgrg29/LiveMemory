# LiveMemory v0.19.1 — Windows Credential Storage Fix

**Official release.** Version `0.19.1`, database schema **16** (no migration).
This is a focused Windows reliability patch for API key storage. Live platform support is
unchanged: six platforms are released and usable; **Kuaishou remains a preview with live capture
disabled**.

## English

### What changed

- **Some Windows users can save AI API keys again.** LiveMemory no longer depends on an
  ACL-managed credential file inside the data folder for AI provider keys. The previous
  `AI_PROVIDER_CREDENTIAL_PERMISSION` failure could occur when that file, its per-install key,
  or the folder ACL was not writable for the current Windows account.
- **API keys now use Windows Credential Manager first.** Each provider key is stored as a
  separate Windows generic credential protected by Windows DPAPI and scoped to the current
  Windows user. A key is not written to the settings JSON, logs, backups, ZIP files or HTML.
- **Existing readable keys migrate automatically.** On first launch, the old encrypted
  `secrets/ai-keys.json` is read, each key is written to Credential Manager and read back for
  verification, and only then is a migration marker written. The old file is **not deleted,
  renamed or overwritten**.
- **A damaged or unreadable old store does not block new keys.** The old file is preserved
  unchanged, the settings page explains that some old keys could not be migrated, and you can
  enter the API key again. New keys still go to the new backend. If an old key is temporarily
  unavailable from the new backend, the encrypted old file remains a read-only fallback.
- **Provider switching and existing configurations are unchanged.** DeepSeek, OpenCode, and
  custom OpenAI-compatible configurations save normally. Changing provider, region, or Base URL
  still requires a new key because the old key must not be sent to an unconfirmed endpoint.
- **Credential errors are specific.** Missing Credential Manager, access denied, write failure,
  and a damaged stored credential have distinct errors. The settings page also substitutes the
  real path/code instead of showing a literal `{path}` or `{code}`. A failed save is never
  reported as success and never falls back to plaintext.
- **No extra runtime or manual setup.** The bridge uses the built-in Windows PowerShell with a
  fixed embedded C# call into `CredWriteW` / `CredReadW` / `CredDeleteW`. The API key is passed
  only on stdin, not in command-line arguments, environment variables, or a temporary plaintext
  file. You do not need to change PowerShell execution policy or install Python/Node.js.

### Data and upgrade

- Your live recordings, viewers, long-term profiles, AI jobs, saved reports, and existing tasks
  are unchanged.
- Database schema is still **16**; no migration is required.
- Existing provider configurations and readable API keys are preserved and migrated
  automatically.
- **You do not need to delete old configuration files, clear AppData, or reinstall LiveMemory.**
  Replace `LiveMemory.exe` with this release.
- If an old key cannot be read, the old file is kept and you can enter the key again; other
  providers keep working.
- Creating a full backup before upgrading is still recommended.

### Verification

- Full automated suite: **1,294 passed / 0 failed / 2 skipped** (889 unit + 407 integration;
  the 2 skipped tests are opt-in real Windows Credential Manager tests).
- Real Windows Credential Manager: **2/2** (save, read, update, chunked large key, delete, and
  legacy migration with automatic test-target cleanup).
- Windows EXE (`requireAdministrator`): `verify-provider-save-exe` **24/24**,
  `verify-exe` **11/11**, `verify-help-exe` **14/14**, `verify-ai-token-exe` **16/16**.
- Ten interface languages: **2,379** keys with aligned key sets and placeholders.
- The final EXE Build ID, size, and SHA-256 are recorded in the repository's `docs/STATUS.md`;
  size and SHA-256 are also in `SHA256SUMS.txt`.

### Known limitations

- **Real double-click UAC (accept/deny), a clean Windows account, a second Windows user, a full
  machine restart, and enterprise group-policy environments were not manually verified in this
  release.** The EXE is unsigned, so SmartScreen may warn about an unknown publisher.
- Some enterprise-managed Windows environments may block Windows PowerShell, Credential Manager,
  or both. In that case saving fails with a specific error instead of writing a plaintext key;
  LiveMemory does not bypass group policy or security controls.
- Kuaishou remains a preview; live H5 capture stays disabled until written permission is
  obtained.
- Real paid verification for OpenCode, OpenAI, Anthropic, MiniMax, Alibaba Cloud Model Studio,
  OpenRouter, and fully custom endpoints is still provider-by-provider work.
- Twitch Bits/gifted subscriptions, Douyin gifts, TikTok gifts, and some Kick lifecycle events
  remain `NOT-OBSERVED`.

## 简体中文

### 本次修复

- **部分 Windows 用户无法保存 AI API Key 的问题已修复。** LiveMemory 不再让 AI Provider 的
  Key 依赖数据目录内由 ACL 管理的凭据文件。旧版中，当该文件、每安装密钥或目录 ACL 对当前
  Windows 账户不可写时，就会出现 `AI_PROVIDER_CREDENTIAL_PERMISSION`。
- **API Key 现在优先使用 Windows 凭据管理器保存。** 每个 Provider 的 Key 是一条独立的
  Windows Generic Credential，由 Windows DPAPI 保护，并按当前 Windows 用户隔离。Key 不会
  写入设置 JSON、日志、备份、ZIP 或 HTML。
- **旧版可读取的 Key 会自动迁移。** 首次启动时读取旧的加密 `secrets/ai-keys.json`，逐个写入
  凭据管理器并读回校验，全部成功后才写迁移标记。旧文件**不会被删除、改名或覆盖**。
- **旧凭据损坏或不可读不会阻止新 Key。** 旧文件保持原样；设置页会说明部分旧 Key 未能迁移，
  用户可以直接重新输入。新 Key 仍保存到新后端。若旧 Key 在新后端暂时不可用，旧加密文件仍可
  作为只读回退。
- **Provider 切换与已有配置不变。** DeepSeek、OpenCode 和自定义 OpenAI-compatible 配置均可
  正常保存。更换 Provider、区域或 Base URL 仍需重新输入 Key，因为旧 Key 不能被发送到未经确认
  的新地址。
- **凭据错误更具体。** 凭据管理器不可用、访问被拒绝、写入失败和已保存凭据损坏分别提示；
  设置页会正确替换真实的 `{path}`/`{code}`，不会再显示字面占位符。保存失败不会显示成功，
  也不会回退明文。
- **不需要额外运行环境或手动设置。** 使用 Windows 内置 PowerShell 和固定的内嵌 C# 调用
  `CredWriteW` / `CredReadW` / `CredDeleteW`。API Key 只经 stdin 传递，不进入命令行参数、
  环境变量或临时明文文件。用户不需要修改 PowerShell 执行策略，也不需要安装 Python/Node.js。

### 数据与升级

- 直播记录、观众、长期画像、AI 任务、已保存报告和已有任务均不受影响。
- 数据库 Schema 仍为 **16**，无需迁移。
- 已有 Provider 配置与可读取的 API Key 会保留并自动迁移。
- **不需要删除旧配置文件、清空 AppData 或重新安装。** 直接用本版本替换 `LiveMemory.exe` 即可。
- 如果旧 Key 无法读取，旧文件会保留，用户可以重新输入；其他 Provider 不受影响。
- 升级前仍建议创建一次完整备份。

### 验证

- 全量自动化：**1,294 passed / 0 failed / 2 skipped**（889 unit + 407 integration；
  2 项跳过为 opt-in 的真实 Windows 凭据管理器测试）。
- 真实 Windows 凭据管理器：**2/2**（保存、读取、更新、大 Key 分块、删除、旧数据迁移；
  测试目标自动清理）。
- Windows EXE（`requireAdministrator`）：`verify-provider-save-exe` **24/24**、
  `verify-exe` **11/11**、`verify-help-exe` **14/14**、`verify-ai-token-exe` **16/16**。
- 十种界面语言：**2,379** 键，键集与占位符一致。
- 最终 EXE 的 Build ID、大小与 SHA-256 见仓库 `docs/STATUS.md`；大小与 SHA-256 也记录在

### 已知限制

- **本版未人工验证真实双击 UAC（同意/拒绝）、干净 Windows 账户、第二个 Windows 用户、
  整机重启和企业组策略环境。** EXE 未签名，SmartScreen 可能提示未知发布者。

- OpenCode、OpenAI、Anthropic、MiniMax、阿里云百炼、OpenRouter 与完全自定义端点的真实付费
  验收仍需逐个 Provider 进行。
- Twitch Bits/赠订、抖音礼物、TikTok 礼物和部分 Kick 生命周期事件仍为 `NOT-OBSERVED`。

## 日本語

### 今回の修正

- **一部の Windows ユーザーが AI API Key を保存できない問題を修正しました。**
  LiveMemory の AI Provider Key は、データフォルダー内の ACL 管理された認証情報ファイルに
  依存しなくなりました。旧版では、そのファイル、インストール固有キー、またはフォルダーの ACL が
  現在の Windows アカウントで書き込み不可の場合、`AI_PROVIDER_CREDENTIAL_PERMISSION` が
  発生することがありました。
- **API Key は Windows 資格情報マネージャーを優先して保存します。** 各 Provider の Key は
  個別の Windows Generic Credential として保存され、Windows DPAPI で保護され、現在の
  Windows ユーザーにスコープされます。Key は設定 JSON、ログ、バックアップ、ZIP、HTML には
  書き込まれません。
- **旧版で読み取れる Key は自動移行されます。** 初回起動時に旧暗号化
  `secrets/ai-keys.json` を読み取り、各 Key を資格情報マネージャーへ書き込んで読み戻し検証し、
  すべて成功した後だけ移行マーカーを書き込みます。旧ファイルは**削除、改名、上書きしません**。
- **旧認証情報が破損・読み取り不能でも新しい Key を妨げません。** 旧ファイルはそのまま保持し、
  設定画面で一部の旧 Key を移行できなかったことを説明します。ユーザーは Key を再入力できます。
  新しい Key は新しいバックエンドに保存されます。旧 Key が新しいバックエンドで一時的に
  利用できない場合、旧暗号化ファイルは読み取り専用のフォールバックとして残ります。
- **Provider の切り替えと既存設定は変わりません。** DeepSeek、OpenCode、カスタムの
  OpenAI-compatible 設定は通常どおり保存できます。Provider、リージョン、Base URL の変更には
  引き続き新しい Key が必要です。古い Key を未確認の接続先へ送らないためです。
- **認証情報のエラーが具体的になりました。** 資格情報マネージャーが利用できない場合、
  アクセス拒否、書き込み失敗、保存済み認証情報の破損を区別します。設定画面は `{path}` /
  `{code}` を実際の値に置き換え、リテラルのプレースホルダーを表示しません。保存失敗を成功と
  表示せず、平文へフォールバックしません。
- **追加の実行環境や手動設定は不要です。** Windows 内蔵 PowerShell と固定の埋め込み C# から
  `CredWriteW` / `CredReadW` / `CredDeleteW` を呼び出します。API Key は stdin でのみ渡し、
  コマンドライン引数、環境変数、一時的な平文ファイルには入れません。PowerShell の実行ポリシー
  変更や Python/Node.js のインストールは不要です。

### データとアップグレード

- 配信記録、視聴者、長期プロフィール、AI タスク、保存済みレポート、既存タスクは変更されません。
- データベース Schema は **16** のままで、移行は不要です。
- 既存の Provider 設定と読み取り可能な API Key は保持され、自動移行されます。
- **旧設定ファイルの削除、AppData の消去、再インストールは不要です。**
  `LiveMemory.exe` をこのリリースで置き換えてください。
- 旧 Key を読み取れない場合、旧ファイルは保持され、Key を再入力できます。他の Provider は
  そのまま動作します。
- アップグレード前の完全バックアップを引き続き推奨します。

### 既知の制限

- **本リリースでは、実際のダブルクリック UAC（許可/拒否）、クリーンな Windows アカウント、
  2 人目の Windows ユーザー、マシン全体の再起動、企業のグループポリシー環境を手動検証して
  いません。** EXE は署名されていないため、SmartScreen が未知の発行元として警告する場合が
  あります。
- 一部の企業管理 Windows 環境では、Windows PowerShell、資格情報マネージャー、または両方が
  ブロックされる場合があります。その場合、保存は具体的なエラーで失敗し、平文 Key は書き込まれ
  ません。LiveMemory はグループポリシーやセキュリティ制御を回避しません。
- 快手は引き続きプレビューです。書面による許可を得るまで、ライブ H5 キャプチャは無効です。
- OpenCode、OpenAI、Anthropic、MiniMax、Alibaba Cloud Model Studio、OpenRouter、
  完全カスタム接続先の実課金検証は、引き続き Provider ごとに必要です。
- Twitch Bits/ギフトサブスク、Douyin ギフト、TikTok ギフト、一部の Kick ライフサイクル
  イベントは `NOT-OBSERVED` のままです。
