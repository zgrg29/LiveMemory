# LiveMemory v0.15.0 — 10-Language Internationalization

> **Stable release** · Windows 10/11 x64 · Local-first · MIT (source)
>
> Build ID `945bee868455` · EXE SHA-256 `b8458ab75704ebedc44fc64ebe000ddf97828687bf1af7896266b219469c826e`
>
> **LiveMemory remains free and open-source software.** No account, no telemetry, no developer
> server. All AI analysis uses **your own** provider API key and runs on your own computer.

LiveMemory is a local-first livestream memory app for Windows. It records chat, gifts, Super Chats
and membership events from live streams, keeps per-stream statistics, and builds long-term viewer
profiles. This release is about **languages**, not about new platforms: the app now speaks ten
interface languages and can produce AI reports in all ten, while the five supported live platforms
stay exactly as they were.

---

## Highlights

1. **Seven new interface languages — ten in total.**
   `zh-CN` (简体中文), `ja` (日本語), `en` (English), `ko` (한국어), `es` (Español),
   `pt-BR` (Português do Brasil), `zh-TW` (繁體中文), `fr` (Français), `de` (Deutsch) and
   `id` (Bahasa Indonesia). Every dictionary has **2,271 keys** with identical key sets and
   placeholders; the whole console — live, history, viewers, AI centre, settings, help — switches
   language at runtime and persists the choice.

2. **Ten-language AI session analysis and long-term profiles.**
   System prompts, packaged instructions, memory rules, batching/summary rules, repair prompts and
   result JSON schemas all cover the ten languages. A task's output language is written into
   `ai_jobs.locale` when the task is created and never changes afterwards.

3. **AI output language is independent from the interface language.**
   A new persisted setting `aiOutputLocale` (default `follow-ui`) lets you run, for example, a
   Korean interface with Japanese reports. Changing the interface later does not touch existing
   tasks or saved text.

4. **Ten-language report reading translation.**
   Any saved report can be re-read in another supported language. Translation only produces a
   display layer: the original report, its structured fields, evidence references, `viewer_id`,
   fact IDs and statuses are never rewritten. Each target language has its own cache row, repeated
   reads issue **zero** provider requests, and a failed translation falls back to the original text.

5. **Cross-language long-term profiles coexist (Plan B).**
   Facts written in different languages live side by side (`吉他` and `기타` can both exist), the
   per-fact dedupe key is unchanged, the same-language merge behaviour is unchanged, and no existing
   fact is translated, deleted or overwritten when you switch output language. Language mixing does
   not cause constraint conflicts, task failures or data loss.

6. **Ten-language Windows launcher and in-app help.**
   The console launcher (`--help`, `--lang <code>`, errors, ASCII fallback) and the built-in user
   guide (112 help keys × 10 languages) are fully translated. Language names are always shown in
   their own script.

7. **Task resume and historical data compatibility.**
   Tests resume an interrupted Korean task after switching the interface to German and the AI
   preference to Spanish, restarting the app, and the task continues and finishes in Korean without
   re-sending completed batches. A real schema-15 database upgrades to schema 16 with identical
   counts and content hashes; the old `settings.json` is not rewritten, old reports stay readable,
   and backup → restore into a fresh directory reproduces the same counts.

8. **The five platform integrations are unchanged.**
   Bilibili Live, YouTube Live, Twitch, Douyin Live and TikTok Live keep their existing capture
   paths, stable identities, dedupe rules, amount semantics and retention policy. **No new live
   platform was added in this release.**

## What changed technically

| Area | Change |
| --- | --- |
| Locale registry | `src/shared/locales.mjs` is the single source for codes, native names, scripts, regions, availability and the `aiOutput` capability flag; Node and the browser import the same file |
| Resolution | Preference / system detection / installed resources are resolved separately; `zh-HK`/`zh-MO`/`zh-Hant` → `zh-TW`, `pt-PT` → `pt-BR`, `in` → `id`, unknown → `en`, never a white screen |
| Dictionaries | Ten files under `src/web/i18n/`, **2,271** leaf keys each, zero missing/extra keys, zero placeholder differences, no untranslated English sentences outside the reviewed whitelist |
| AI prompts | New `src/ai/prompts/language.mjs` holds per-language `rule/guard/system/repair/example`; only the current language is sent per request |
| Schemas | `locale.enum` mirrors the registry (ten values); field names, enums, `required` and `additionalProperties:false` are unchanged |
| Settings | `aiOutputLocale` added to the settings store and to the backup key whitelist; old configs and old backups without the key read as `follow-ui` |
| Launcher | Ten console message sets (61 keys each), `--lang` accepts the ten codes and regional variants, `{locales}` is filled from the registry, ASCII fallback preserved |
| Version | `package.json` and `APP_VERSION` are `0.15.0`; the EXE embeds the same version, build ID and commit |

## Known limitations — read this literally

- **No new live platform.** Kick, Huya, Douyu, CHZZK, SOOP, Kuaishou, Niconico, Xiaohongshu, YY and
  Facebook Live remain **unimplemented**; this release does not change that.
- **Twitch and Douyin real capture was not re-verified in the final acceptance round.** Twitch had
  no live channel available and Douyin had no live room during P42, so their real capture is
  reported as **not verified**, not as passing. Bilibili, YouTube and TikTok were exercised on real
  live rooms in that round.
- **Some languages have not been reviewed by native speakers.** Quality is enforced by machine
  gates (key sets, placeholders, no empty values, no untranslated sentences, layout checks in a real
  browser) plus sampling by the maintainer. There is **no native-speaker sign-off** for any of the
  ten languages.
- **Gift/subscription evidence is unchanged.** TikTok gifts, super chats, streaks and subscriptions,
  Douyin real gifts and Twitch Bits/gifted subs remain **NOT-OBSERVED**; only the existing parsed
  code paths and automated tests cover them.
- **The Windows EXE requires administrator rights.** The published `LiveMemory.exe` carries a
  `requireAdministrator` manifest: double-clicking shows the standard Windows UAC prompt, accepting
  starts it elevated, declining cancels the launch. The program never bypasses or disables UAC and
  does not require right-clicking "Run as administrator".
- **The EXE is unsigned.** SmartScreen may warn about an unknown publisher, and Windows **Smart App
  Control** in enforcement mode can block unsigned binaries entirely. If the app does not start and
  Windows reports an application-control block, that is a Windows security policy decision, not a
  LiveMemory error.
- **Real double-click UAC (accept and decline) and a clean Windows account were not verified by
  this automated session.** The release manifest is asserted before and after injection. The
  functional EXE scenarios ran on a **separately built asInvoker binary with the same build ID**
  (`945bee868455`), because this build machine's application-control policy refuses to start binaries
  that were re-patched after the build. The physical UAC click path remains a manual check.
- **The PE `VERSIONINFO` resource of the EXE still describes the embedded Node.js runtime
  (`24.21.0`)**, as in earlier releases. LiveMemory's own version is embedded in `build-info.json`
  and shown by `--version`, the launcher banner, the About card, `/api/health` and `/api/bootstrap`;
  all of them report `0.15.0`.
- **Long multi-block report translation and real 429 rate limiting were not exercised** with a real
  provider; translation caching and failure fallback were.
- **Twitch / Douyin / TikTok / Bilibili / YouTube platform protocols are unchanged** and can break
  at any time. TikTok uses an unofficial web protocol and is marked experimental.

## 简体中文摘要

**LiveMemory v0.15.0 是一次语言能力发布，不是平台扩展。**

- **界面语言从三种扩展到十种**：简体中文、日本語、English、한국어、Español、Português (Brasil)、
  繁體中文、Français、Deutsch、Bahasa Indonesia。十份字典各 2,271 个键，键集与占位符完全一致，
  整个控制台（直播记录、历史、观众、AI 分析中心、设置、使用说明）可实时切换并保存。
- **AI 单场分析与长期画像支持十种语言**。任务创建时把语言写入 `ai_jobs.locale`，之后暂停、继续、
  重启、切换界面语言都不会改变该任务。
- **AI 输出语言与界面语言是两个独立设置**（`aiOutputLocale`，默认「跟随界面语言」），
  可以用「韩语界面 + 日语报告」。
- **报告阅读翻译支持十种语言**：只生成展示层译文，原文、结构化字段、证据引用、`viewer_id`、
  事实 ID 与状态永不被改写；每个目标语言独立缓存，重复阅读不再请求 Provider，翻译失败回退原文。
- **跨语言长期画像按方案 B 共存**：`吉他` 与 `기타` 可以同时存在，同语言去重与合并规则不变，
  切换输出语言不会删除、覆盖或重新翻译已有事实。
- **Windows 启动器与内置使用说明十语言完整**，语言名始终用该语言自身文字显示。
- **任务恢复与历史数据兼容**：暂停的韩语任务在切换界面德语、AI 偏好西班牙语并重启后仍以韩语继续，
  已完成批次不重发；真实 schema-15 数据库升级到 16 后计数与内容哈希完全一致，旧设置文件未被改写，
  旧报告仍可读，备份 → 全新目录恢复计数一致。
- **五个直播平台保持不变**：Bilibili / YouTube / Twitch / 抖音 / TikTok，本轮**没有新增直播平台**。

**必须如实说明的限制**：

- LiveMemory 仍然是**免费开源软件**，没有账号、没有遥测、没有开发者服务器。
- **Twitch 与抖音的真实采集未在本轮重新验证**（当时无在播频道 / 无真实在播房间），不能写成已通过；
  Bilibili、YouTube、TikTok 本轮在真实直播间验证通过。
- **部分语言尚未经过母语人工终审**，质量由机器门禁、布局检查和维护者抽样阅读保证。
- TikTok 礼物/连送/订阅、抖音真实礼物、Twitch Bits/赠订仍为 **NOT-OBSERVED**。
- **Windows EXE 运行需要管理员权限**：双击时 Windows 显示标准 UAC，同意后启动，拒绝即取消；
  程序不绕过 UAC，也不需要右键「以管理员身份运行」。EXE 未签名，SmartScreen 可能提示未知发布者。
- 本轮自动化环境**没有完成真实双击 UAC（同意与拒绝两条路径）与干净 Windows 账户验收**，
  该项列为人工验证待办。
