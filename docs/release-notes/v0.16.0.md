> **LiveMemory remains free and open-source software.** No account, no telemetry, no developer
> server. All AI analysis uses **your own** provider API key and runs on your own computer.

LiveMemory is a local-first livestream memory app for Windows. It records chat, gifts, Super Chats
and membership events from live streams, keeps per-stream statistics, and builds long-term viewer
profiles. **v0.16.0 adds Kick as the sixth supported platform**, including automatic live
monitoring, while keeping the existing five platforms unchanged.

---

## New: Kick Support

- **Kick joins LiveMemory as the sixth supported livestream platform.**
- **Public chat collection without a Kick login or developer API key.** Paste a channel link such as
  `https://kick.com/<channel>`; LiveMemory reads the same public realtime feed the Kick website uses,
  with an anonymous guest token that is refreshed automatically before it expires.
- **Multiple Kick channels can be recorded simultaneously**, each with its own connection, session,
  status and stop action.
- **Stable viewer identity** (`kick:<sender.id>`) for long-term viewer memories; nicknames are shown
  but never used as identity, and messages without a stable id do not create viewer profiles.
- **KICKs gifts and gifted subscription events** are stored. KICKs amounts stay display-only (no fiat
  value is invented); gifted subscriptions keep the gifter and each recipient, and recipients without
  a stable id do not get a profile.
- **Session history and AI analysis integration.** Kick events use the same local SQLite pipeline,
  viewer profiles, AI analysis centre and 30-day raw-content retention as every other platform.

## New: Kick Auto Live Monitoring

- **Monitor Kick channels while they are offline.**
- **Automatically start recording when a monitored channel goes live.**
- **End the session when the stream ends** — the adapter confirms the public channel state
  periodically and requires two consecutive offline observations, because Kick's chat socket can
  stay connected after a stream ends.
- **Continue monitoring for future streams**: a finished session returns the target to “waiting”
  and the next broadcast creates a new session.
- **A manual stop is respected**: the same broadcast is not restarted automatically; the target
  waits for the stream to end before accepting a new one.
- **Restore monitoring targets after an application restart**, without duplicating a session.
- **Support multiple monitored channels** with independent state and sessions.

## Localization

- Kick capture and monitoring controls are available in **all ten supported interface languages**
  (`zh-CN`, `ja`, `en`, `ko`, `es`, `pt-BR`, `zh-TW`, `fr`, `de`, `id`).
- Dictionaries keep identical key sets and placeholders (2,304 leaf keys each); no untranslated
  sentences outside the reviewed allowlist.

## Reliability

- **Reconnection and guest-token refresh**: exponential backoff with jitter, proactive refresh before
  the guest token expires, and immediate refresh on token-expired errors.
- **Message deduplication** by Kick message UUID / gift transaction id, enforced by
  `UNIQUE(session_id, dedupe_key)`; a reconnect never adds a duplicate row.
- **Independent session management** per room; a stopped room never receives late events, and one
  monitored channel cannot start or stop another.
- **Improved stream lifecycle detection**: periodic public-channel confirmation stops a session after
  two offline observations instead of relying on the WebSocket closing.

---

## Known limitations

- **Kick capture depends on an unofficial public realtime interface.** It is not an official Kick API
  and may change or stop working at any time. LiveMemory reports failures explicitly and does not
  bypass access controls.
- **Messages can be missed during a reconnect.** The Kick feed has no replay cursor; LiveMemory does
  not claim a complete chat log.
- **KICKs are not fiat money.** A KICKs quantity is not converted into revenue or a currency amount.
- **Some gifted-subscription events have no stable viewer id.** They are still stored, but they
  cannot be reliably linked to a long-term viewer profile.
- **Follow events are only available through official webhooks**, which need a public receiver; they
  are not part of the local login-free capture path.
- **A full natural cycle of the same Kick channel going offline and live again has not yet been
  observed end-to-end in real use.** The state machine is covered by automated tests, and real
  end-of-stream was observed once during the Kick long test.
- Subscription/renewal, stream-start/end events, hosts/raids and polls have **not** been observed as
  real Kick events (`NOT-OBSERVED`). They are not claimed as supported.

## Upgrade notes

- Replace `LiveMemory.exe`; the data folder (`%LOCALAPPDATA%\LiveMemory`) is unchanged.
- The database schema is unchanged (16); existing sessions, viewers, AI results and backups keep
  working.
- Bilibili, YouTube, Twitch, Douyin and TikTok keep their existing capture paths, identities,
  dedupe and retention rules.

# LiveMemory v0.16.0 — Kick 支持与自动开播监控（中文摘要）

- **新增第六个直播平台 Kick**：粘贴 `https://kick.com/<频道名>` 即可采集公开聊天，不需要 Kick
  登录、Cookie、开发者 API Key 或付费服务。
- **稳定身份**：`kick:<sender.id>`；昵称只展示，不当作身份；缺少稳定 ID 的消息不建长期档案。
- **多频道同时采集**；KICKs 礼物保留交易 ID、发送者 ID 与 KICKs 数量，但不换算法币；赠送订阅
  保留赠送者与每位接收者，接收者没有稳定 ID 时不建档案。
- **开播监控**：可添加未开播频道，低频只读检查公开频道信息；开播自动开始记录；连续两次确认
  下播后结束本次记录并继续等待下一场；手动停止不会被自动重启；重启后恢复监控任务；支持多频道。
- **十语言界面**：Kick 采集与监控在全部十种界面语言中可用。
- **已知限制**：Kick 通信依赖非官方公开实时接口，可能失效；重连期间可能漏消息；KICKs 不是法币
  收入；部分赠订没有稳定观众 ID；关注事件需要官方 Webhook，不在本地免登录采集范围；同一频道
  自然下播后再次开播的完整真实周期尚未在真实使用中观察完成，相关状态机由自动化测试覆盖。
