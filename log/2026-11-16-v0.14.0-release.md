## 3. 版本决策

上一个正式发布是 `v0.13.2-rc.0`（Tag `cb28624`），此后累计 **44 个提交 / 136 文件 / +37,847 −184**，
新增 **Twitch、抖音、TikTok** 三个平台与多房间并发、匿名 TikTok webcast 等能力。

- 用 `0.13.3` 发布这三个平台在 SemVer 上偏小（新增平台属 minor）。
- `0.13.3` 已在开发期使用，且用户建议 `v0.14.0`。
- 结论：**产品版本 `0.14.0`，Tag `v0.14.0`，正式稳定版**。
- 该决定使 `docs/ROADMAP.md` 中 P39–P44 的版本标签需要顺延（v0.14.0 已被占用），已同步修改。

版本号同步位置：`package.json`、`src/shared/app-info.mjs`、`docs/CHANGELOG.md`、`docs/STATUS.md`、
`docs/release-notes/v0.14.0.md`。

### 6.1 一次真实失败与处置（如实记录）

第一次 `verify-exe` 在 `scenarioFreshStart` 超时中止，stderr 显示：

```text
详细信息：no writable application folder
失败步骤：bootstrap
错误代码：ENOENT
  C:\Users\Rong\AppData\Local\LiveMemory\app\17f84b… (EPERM)
  C:\Users\Rong\AppData\Local\Temp\LiveMemory-app\17f84b… (EPERM)
```

根因是本轮执行环境的文件沙箱禁止子进程写入 `%LOCALAPPDATA%`（实测：node 子进程写
`%LOCALAPPDATA%\LiveMemory\_probe` 返回 `EPERM`，写自身 `os.tmpdir()` 成功）。
这是**环境限制，不是产品缺陷**，也没有修改任何产品代码。

处置：把 EXE 的解压根（`LIVE_MEMORY_DATA_DIR`）与临时目录（`TMP`/`TEMP`）重定向到仓库内可写目录，
重跑同一二进制。结果 **10/10 全部通过**，日志中 `app-root` 为
`…\exe-tmp\LiveMemory-app\17f84b1956e1d197afef`（本版资产哈希），说明验收确实作用于新构建。
此外 `--version` 输出 `LiveMemory 0.14.0`、Build ID `17f84b1956e1`、commit `d268cf9`。

第一次成功运行中，两个「解压目录」场景曾读到 `%TEMP%` 里上一轮遗留的日志而指向旧目录
（`e48016f…`）；把 `TMP` 一并重定向后重新运行，二者均指向 `17f84b…`，因此**只采用第二次结果**。
