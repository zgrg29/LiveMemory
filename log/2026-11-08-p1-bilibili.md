# 开发日志 · 2026-11-08 · P1：M3 Bilibili 真实直播接入（第一阶段）

## 1. 目标

在 P0（普通权限启动修复，commit `f8d64c4`）通过后，实现 Bilibili 最小真实闭环：

直播间 ID → 检查房间 → （可选）扫码登录 → 建立连接 → 弹幕/礼物/SC/大航海 → 统一事件模型 → SQLite → 实时控制台 → 断线恢复。

## 2. 参考与约束

- 参考仓库 `.ref/bili-gift-drop`（只读）：扫码登录、WBI、协议编解码、心跳/重连、礼物/SC/大航海字段。
- 发现参考仓库**完全没有 `DANMU_MSG`** 处理，弹幕字段只能靠真实直播间验证。
- 保持零运行时依赖：协议、WBI、二维码登录流程全部用 Node 内置能力（`fetch`、全局 `WebSocket`、`node:zlib`、`node:crypto`）。

## 3. 实现

- `wbi.mjs`：mixin key + 排序编码 + `w_rid`；公开测试向量回归。
- `protocol.mjs`：16 字节头、多包、zlib/brotli 递归解压、op 3 人气值。
- `api.mjs`：`room_init` / `getInfoByRoom` / `getDanmuInfo` / `nav` / QR 生成与轮询；WBI 30 分钟缓存；`buvid3`；**`nav` 未登录返回 -101 但带 WBI 键，必须容忍**（这是第一版失败的原因）。
- `adapter.mjs`：鉴权包、30s 心跳、65s 看门狗、1→30s 退避重连、`host_list` 轮换、generation 防竞态。
- `mapper.mjs`：`DANMU_MSG`（`info` 顶层或 `data.info` 两种布局）、`SEND_GIFT`（含免费礼物）、`SUPER_CHAT_MESSAGE(_JPN)`、`GUARD_BUY` / `USER_TOAST_MSG(_V2)`；`uid=0` 视为无身份，不合并观众。
- 金额：
  - 礼物金瓜子 1000 = 1 元 → 分（不能整除时标 `display`）；
  - SC 以元报价 → ×100 分，`actual`；
  - 大航海金额单位未确认 → **不记金额**（`unknown`），事件保留。
- `cookie-store.mjs` + `login.mjs`：扫码登录、`nav` 校验、AES-256-GCM 保存、`icacls` 限制；API 不返回 Cookie。
- `service.mjs` + 路由：`status` / `login/open` / `login/poll` / `login/logout` / `room` / `connect` / `disconnect`；错误映射为可翻译的 `AppError`。
- `SessionManager.startPlatform()`：真实适配器与模拟器共用同一条 ingest 管线；连接失败会把刚创建的场次关闭，不留下假「记录中」。
- UI：直播页新增「直播来源」（模拟 / Bilibili 直播），包含房间检查、开播状态、主播/人气、可选登录（在浏览器打开扫码页并轮询）、开始/停止记录；三语文案与说明（身份、金额、登录）已补齐。
