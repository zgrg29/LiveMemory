# 开发日志 · 2026-11-08 · P2：Bilibili 扫码登录改为应用内本地二维码

## 1. 问题（用户反馈）

点击「扫码登录」后，应用会打开 `https://account.bilibili.com/h5/account-h5/auth/scan-web?...` 外部页面；在用户的浏览器里表现为「跳到另一个链接」，并且**触发了下载**，完全无法扫码。

旧实现的设计缺陷：把「显示二维码」交给 Bilibili 的外部页面，而该页面并不是为桌面浏览器直接打开设计的；应用的轮询其实只依赖 `qrcode_key`，根本不需要打开浏览器。

## 2. 参考实现

参考项目（完整工程 `D:\哔哩哔哩OBS礼物特效`，只读副本 `.ref/bili-gift-drop`）：

- `src/control/vendor/qrcode.js`：MIT 许可的 QR Code Generator（Kazuhiko Arase），单文件、无 npm 依赖。
- `src/control/control.mjs`：

```js
const qr = qrcode(0, 'M');
qr.addData(url);
qr.make();
box.innerHTML = qr.createSvgTag({cellSize: 5, margin: 8});
```

即：**在页面内生成二维码**，每 2 秒轮询 `login/qr/poll`，状态为 waiting / scanned / expired / success。

## 3. 修改

- 复制 `qrcode.js` 与 `qrcode.LICENSE.txt` 到 `src/web/js/vendor/`（保留原 MIT 许可证），在 `index.html` 中以本地 `<script>` 引入（CSP `script-src 'self'` 允许）。
- 直播页「直播来源 → Bilibili 登录」：
  - 「扫码登录」调用 `POST /api/bilibili/login/qrcode`；
  - 用 vendored QR 库生成矩阵，绘制到 `<canvas>`（白底黑块，约 220px），无 `innerHTML`；
  - 页面内显示二维码 + 状态文字（等待扫码 / 已扫码 / 已过期 / 成功）；
  - 成功后刷新登录状态并重新渲染面板；过期或失败时隐藏二维码。
- **移除** `/api/bilibili/login/open` 与 `BilibiliService.openLoginPage()`：不再打开任何外部页面，避免跳转/下载。
- 三语文案：`loginBrowserHint` 替换为 `loginScanHint`（说明二维码在本地生成，不打开外部页面），新增 `loginQrUnavailable`。
- 新增 `tests/unit/bilibili-qr.test.mjs`：在 `node:vm` 中加载 vendored 库，验证登录 URL（131 字符）能生成矩阵、三个定位图案正确、结果确定、长 URL 仍可编码、许可证存在。
