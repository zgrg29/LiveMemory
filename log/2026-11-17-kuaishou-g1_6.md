# 2026-11-17 · 快手 G1.6：登录态 WebSocket 复测（结论 E）

## 目标

排除 G1.5 的旧 `liveStreamId` 方法缺陷，判断正常扫码登录后能否在不实现签名/设备指纹/
验证码/TLS 伪装的前提下取得 WebSocket token 并收到真实弹幕。

## 执行

1. 真人扫码两次（第一次用于旧方法对照，第二次用新方法）。
2. 第二次登录后重新取 `home/list` 快照，选 8 个最新在播房间。
3. 对每个房间立即调用 `liveroom/websocketinfo`。
4. 记录 HTTP 状态、业务 result、token/URL 是否存在；不打印凭据或聊天原文。
5. 复核官方条款与 `open.kuaishou.com` 弹幕玩法接口的范围。

## 结果

- 登录链路两次均 `result:1`：QR → 扫码 → 确认 → passToken → 直播站换票 → `userLogin=1`。
- 8/8 最新房间 `websocketinfo`：HTTP 200、`result:2`、无 token、无 URL。
- 候选最高 9,427 watching；最低 819；不是“房间已下播”。
- 同一会话 `home/list` 正常返回 48 个房间；G1.5 `gift-list` 曾返回 token → 不是全站限流。
- 结论：干净客户端无法取得 WS token；继续只能依靠被禁止的签名/设备指纹/浏览器风控能力，停止。

## 研究修正

- `home/list` 连续请求返回不同房间，是轮播推荐列表而非完整库存；
  `detectLiveStatus` 未找到目标时改为 `unknown + NOT_IN_RECOMMENDATION_SNAPSHOT`，不再误判 `offline`。
- `scan.html` 直接加载 `.state/qr.png`，修复原先引用不存在的 `qr-large.png` 的问题。
- 新增 `live-probe.mjs`；失败时写脱敏 `ws-token-probe.json`。

**E — 停止正式接入。** 技术上登录可用，但 WebSocket token 端点对干净客户端一致拒绝；
平台书面授权也未取得。等用户提供官方授权/接口范围后再重新评估。
