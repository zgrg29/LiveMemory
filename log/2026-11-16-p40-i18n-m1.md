# 2026-11-16 · P40 / I18N-M1：十语言界面与启动器

本轮：**LiveMemory 从三种界面语言扩展到十种**（新增 `ko` / `es` / `pt-BR` / `zh-TW` / `fr` / `de` / `id`），
并把 Windows 启动器（控制台 + SEA 引导器）一并扩到十语言。**AI 分析输出语言仍是三种**，
这是本轮的明确边界，不是遗漏。

- 起点：分支 `feature/p39-i18n-m0`，HEAD `7c704bd`，工作区 clean。
- 本轮分支：`feature/p40-i18n-m1`（从 `7c704bd` 创建）。
- 未 Push、未 Merge、未 Tag、未 Release。

## 2. 关键决策

### 2.1 字典键数保持 2,265（不新增语言名键）

十语言需要在设置页/选择器里显示十种原生语言名。两条路：

1. 给每份字典新增 `settings.language.ko` … 共 7 个键（→ 2,272 键）；
2. 语言名只来自注册表 `LOCALE_REGISTRY[].nativeName`，字典键集不变。

选择 **2**：P39 已经把原生语言名集中到注册表，设置页与 Header 都是从
`/api/bootstrap.locales.available` 渲染的，字典里的 `settings.language.zh/ja/en` 只是历史遗留文案。
因此十份字典**仍然是 2,265 个叶子键**，键集/占位符零差异，也没有新增「无关键」。
代价是 `tests/unit/locale-registry.test.mjs` 的「每个注册表语言都必须有字典名键」断言必须改写为
「三个历史键保持逐字一致 + `localeDisplayName()` 对十种语言都与注册表一致」，并新增
「`settings.language` 恒为 10 个键」的反向断言，防止有人偷偷塞回 7 个键。

### 2.2 新增注册表字段 `aiOutput`

十语言界面带来一个真实风险：界面语言是 `ko` 时，AI 任务若沿用界面语言就会把没有提示词的
语言发给 Provider。`AI_OUTPUT_LOCALES` 不是第二份语言清单，而是**同一注册表上的能力筛选**：

- `SUPPORTED_LOCALES`（AI）、`SUPPORTED_MEMORY_LOCALES`、翻译目标、结果 Schema `enum` 全部 = `AI_OUTPUT_LOCALES`；
- 新增 `aiOutputLocale(value)`：按语言族优先降级（`zh-TW`→`zh-CN`），否则 `en`；
- `/api/ai/analyze/run` 与 `/api/memory/jobs` 在**路由层**收窄，任务行写入的 `locale` 一定是受支持语言；
- 报告/翻译只读接口的 `locale` 校验同样改用 `AI_OUTPUT_LOCALES`；
- `buildInstructions` / `memoryPromptVersionFor` 的既有 `en` 回退保持不变（双保险）。

P41 之后只需把提示词/ Schema/翻译目标补齐并把 `aiOutput` 改成 `true`，无需改任何调用点。

### 2.3 启动器：扩到十语 + ASCII 安全回退

- `src/launcher/cli-i18n.mjs`：新增 7 套消息（61 键/语言）。
- `--help` 的语言清单改为 `{locales}` 占位符，由 `AVAILABLE_LOCALES.join(' | ')` 填充，
  不再在十种语言里各写一遍语言码（避免第二份清单）。
- `src/launcher/console.mjs`：
  - 控制台无法 UTF-8 时切换为**英文 ASCII 消息集**，非 ASCII 值折叠为 `?`（`asciiFold`）；
  - 所有写入包 try/catch，管道关闭/控制台不可用时停止写入但**继续启动**；
  - `console.ready` 日志新增 `asciiFallback`。
- `scripts/sea-bootstrap.cjs`（解压前运行，不能 import 注册表）：自包含十语言失败消息 +
  族/地区语言解析 + 同样的 ASCII 回退。这是「解压前」的结构限制，测试逐条比对语言码。

### 2.4 翻译流程（术语表 → 分卡 → 分批 → 机器门禁 → 合并）

1. `docs/i18n/GLOSSARY.md`：50 个核心术语 × 10 语言 + 18 个界面动作词 + 10 份风格卡 + 不翻译清单 + 门禁。
2. 以 `en.json` 为源、`zh-CN.json` 为参照，把 2,265 键切成 10 个按章节对齐的批次
   （`b01-shell` … `b10-help`，每批 82–391 键）。
3. 每语言每批一个译者任务：只翻译值、键集不变、占位符不变，写完后**必须**跑
   `check-batch.mjs <locale> <batch>` 并修到 PASS 才算完成。
4. 合并脚本按 `en.json` 的结构与键序写出十份字典；任何缺键/占位符不一致都会拒绝写入。
5. 语言内部再做一轮「原生读者」审校（术语一致性、语气、长文案），改动后再跑一次门禁。

人工审校口径：**机器门禁 + 逐语言审校 + 抽样人工检查**；本轮没有母语签收人，
不声称做过母语人工终审（见 §6 风险）。

### 4.1 真实浏览器暴露并修复的布局缺陷

1. **统计卡标签被截断**（`.stat-label` / `.stat-sub`）：法语 `SPECTATEURS IDENTIFIÉS`、
   韩语 `유료 이벤트, 정확한 합계` 在 118px 卡片里被省略号截断 → 改为换行，卡片行高自然增长。
2. **「＋ 新建记录」按钮被截断**：德语 `Neue Aufzeichnung` 复用了房间标签的 145px 上限 →
   给 `.recording-tab--new .recording-tab-label` 取消限宽（标签条本来就可横向滚动）。
3. **侧栏品牌标语单行省略**：德语 `Lokal zuerst: Livestream-Gedächtnis` 被截断 → 允许两行。
4. **窄屏顶栏标题被截断**：390px 下德语 `Einstellungen`、法语 `Guide d'utilisation` 超出 →
   顶栏保留省略号但补 `title` 全文；同一文案在页面正文 `.page-title` 始终完整显示（不是隐藏内容）。

这四处都是**先有实测、后有修复**，不是凭感觉改 CSS。

### 4.2 审校

七种新语言各一轮「原生读者」审校，合计修正 **284** 键：
ko 44（용어 통일 / 오역）、es 35（Ajustes、análisis con IA、emote）、pt-BR 15（性数一致、badge→distintivo）、
zh-TW 101（大陸用語 → 台灣用語：會話→工作階段、保存→儲存、錄製→記錄、程式、API 金鑰…）、
fr 17（`vous êtes facturé` 语义倒置、ni…ni 缺否定）、de 41（`Verbinde…` 非正式祈使 → `Wird verbunden…`、
Aufnahme/Aufzeichnung 统一）、id 31（术语统一、生硬被动）。
审校后所有门禁重新 PASS。
