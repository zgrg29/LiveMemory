## 2. 设计决定（写进代码注释与 docs/I18N.md §2.8）

### 2.1 提示词：不是机械翻译

- 三套经过真实使用验证的完整指令正文（`zh-CN` / `ja` / `en`）**原样保留**；
- 新增 `src/ai/prompts/language.mjs` 作为**输出语言规则的唯一来源**：每语 `rule`（写什么语言）、
  `guard`（哪些东西绝不能翻译）、`system`（目标语言系统提示词）、`repair`（修复标签）、
  `example`（Compact 记忆示例的散文）；
- 其余七种语言复用**英文正文** + 自己的输出语言规则，并在 intro 后插入 `## Output language` 段；
- 单次请求只发当前语言（测试断言新增语言增长 < 2,000 字符），所以「十语言支持」没有把
  Token 成本乘以十。

### 2.2 六个 prompt 面都要注入（缺一个就会出现mixed-language 输出）

1. 系统提示词（`SYSTEM`，十语各自的目标语言版本）
2. 包内 `instructions.md`（`buildInstructions` + `## 输出语言/出力言語/Output language` 段）
3. 记忆任务（`split.mjs` 的 `memoryRules[0]` + 本地化 Compact 示例）
4. 分批/最终汇总（`OUTPUT LANGUAGE (<code>)` 作为最后一条规则）
5. 分层摘要（同上）
6. 修复请求（目标语言 `repair` 标签）
   额外：人工粘贴记忆说明（`src/memory/prompt.mjs`）也加了 `output_language` 行，并把
   「按原文语言记录」改成「记忆正文用目标语言、引用原文不翻译」。

### 2.3 语言状态分层（用户点名的五种状态不互相覆盖）

| 状态 | 存储 | 何时改变 |
| --- | --- | --- |
| 用户默认 AI 输出偏好 | `settings.aiOutputLocale` | 用户改设置 |
| 新任务确定的输出语言 | 请求/偏好解析结果 | 创建任务时 |
| 已创建任务的语言快照 | `ai_jobs.locale` | **永不**（恢复时以 job 行为准） |
| 历史报告原始生成语言 | `ai_results.locale` + 正文 | **永不**（翻译只写 `ai_translations`） |
| 阅读时的临时翻译语言 | `?locale=` + `ai_translations.target_locale` | 每次阅读 |

### 2.4 方案 B（长期画像）

不加 `locale` 列、不加别名表、不改 `dedupeKeyFor`。不同语言的不同 topic 天然不冲突；
相同字符的 topic（`吉他` 在 zh-CN/zh-TW）仍按同语言规则去重；切换语言不删除/不覆盖/不重译旧事实。

### 4.1 发现并修复的真实问题

1. **汇总/摘要 prompt 在新语言下没有任何规则**：`rules` 用 `[locale] ?? []`，`de`/`ko` 等会拿到
   空数组，等于丢失全部合并与证据约束。改为 fallback 到英文规则 + 追加输出语言行。
2. **记忆 Compact 示例只有三语**：模型会照抄英文示例（P40 文档已记录过同类缺陷）。示例移入语言表。
3. **英文记忆正文里写着 "(English here)"**：新语言复用时会把英文当输出语言。改为语言表生成。
4. **恢复时依赖运行时状态文件里的 locale**：文件缺失就退回 `en`。改为以 job 行快照为准。
5. **`hasNativeInstructions` 最初写成硬编码三语数组**，被仓库既有「禁止第二份三语清单」测试抓到；
   改为注册表 `nativeInstructions` 标记。
6. **`ai-hierarchy` 的模拟响应在批次数量变化后漏引用批次**：产品侧的覆盖率校验正确拒绝，
   是模拟数据不符合 schema 上限。已按 `message_refs ≤ 4/5` 修正模拟答案，并把「至少 64/128 批」
   放宽为 ±4（提示词体积变化会让分批边界自然移动，这不是本轮引入的回归）。

### 4.2 真实 Provider

用户自己的 DeepSeek 配置（`deepseek-flash`，capability 已通过），隔离目录，
`scripts/verify-ai-i18n-live.mjs`。共 12 次请求：

- 单场报告 `ko` / `zh-TW` / `de` / `pt-BR`：4/4 通过（locale、目标文字、协议键、原文、0 未知字段）；
- 长期画像 `ko`：7 条韩语事实；`de`：7 条德语事实；
- 跨语言续写：德语任务在已有韩语事实后复用韩语 topic 做 confirm（方案 B 预期行为）。

**质量口径**：只有机器判据（文字脚本/停用词 + Schema + 存储结果），**没有母语签收**。
未验证：`es`/`fr`/`id`/`en` 真实输出、翻译缓存的真实 Provider 运行。

脚本本身也修了两个 bug（`ai_results` 列名应为 `result_version`；`--reuse` 曾误删数据目录并重跑），
并由 `--reuse` 零成本复验通过。
