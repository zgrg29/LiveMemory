## 关键决策

1. **H5 判 POLICY-BLOCKED**：官方条款明文禁止机器人/蜘蛛监视、复制；数据使用需书面许可；
   `robots.txt` 也拒绝普通 agent。技术可用不代表允许使用；不再发起新的 H5 请求。
2. **扫码登录成功 ≠ 平台授权**：登录只证明用户同意本机程序代表他登录，不证明快手允许自动采集。
3. **`result:2` 不作结论**：调用使用了 7 分钟前的 `liveStreamId`，目标随后下播；可能是旧 ID/下播，
   也可能是签名或风控；必须用“先确认在播、再取 token”的受控实验区分。
4. **身份强制隔离**：`h5:` / `ws:` 命名空间在 normalizer 层就分开；只有显式证据才允许 `link()`。
5. **不把登录设为必需**：即使 WS 复测通过，默认仍应是匿名；匿名不可许可时，宁可不做该平台。

## 遇到并修复的问题

| 问题 | 修复 |
| --- | --- |
| 本机 `git`/`node` 不在 PATH | 用 GitHub Desktop 自带 git；用 Electron-as-node（`ELECTRON_RUN_AS_NODE=1`） |
| `.git/logs` 不可写，`git checkout -b` 失败 | `-c core.logAllRefUpdates=false branch` + 手写 `.git/HEAD` |
| 命令行返回后 Electron 子进程被杀 | PowerShell 保持存活并等待新进程退出 |
| 二维码 125×125、约 58 秒失效，用户看不到 | 生成 500×500 大图 + `scan.html` 每 3 秒自动换码 |
| `home/list` 无顶层 `result` 被误判为错误 | 只有存在 `result` 时才分类；加回归测试 |
| `websocketinfo` 使用旧 live ID | 默认拒绝未确认在播的旧 ID；新增 `--probe` 复测序列 |
| 单测断言把 H5 normalizer 的礼物 ID 写成 `ws:` | 修正为 `h5:`（代码本身正确） |
