## 2. 关键实测（先验证，再写代码）

1. `GET https://kick.com/api/v2/channels/xqc`（Node `fetch`，HTTP/1.1）→
   `403 {"error":"Request blocked by security policy."}`。
2. 同一 URL 用 `node:http2` → `200`，返回 `chatroom.id`、`livestream`。
3. `POST https://web.kick.com/api/v1/realtime/channels/<channelId>/chat/connection`
   → 只返回 `centrifugo`；`POST …/realtime/auth/connection` → 匿名 guest JWT
   （`sub=guest:<uuid>`，2700 秒）。
4. 真实 WebSocket 订阅 `chatrooms.<chatroomId>.v2` → 立即收到真实 `ChatMessageEvent`。
5. 用 `tests/helpers` 之外的临时脚本抓到 68 条/分钟的真实消息，确认字段与 Emote 格式。
6. 读 kixo `realtime.js`（MIT）与 kicksdk `docs/KICK.md`（MIT/Apache-2.0）交叉验证：
   五条 feed、`{}` ping/pong、token TTL、109/3500、旧 Pusher 已失效。

## 3. 实现

| 文件 | 作用 |
| --- | --- |
| `src/platforms/kick/errors.mjs` | `KICK_*` 错误码（未加 i18n 键；G2 一次性补十语） |
| `src/platforms/kick/link.mjs` | `kick.com/<slug>`、`/chat`、裸 slug；拒绝 VOD/category/clips/search |
| `src/platforms/kick/http.mjs` | HTTP/2 JSON 客户端（WAF 需要 h2）、解压、403/429/404 映射、重定向 |
| `src/platforms/kick/messages.mjs` | Centrifugo 帧拆分、publication 解包、chat→canonical（Emote/badge/时间） |
| `src/platforms/kick/transport.mjs` | 房间解析、connection 配置、guest token、五 feed WebSocket、ping/pong、109 |
| `src/platforms/kick/adapter.mjs` | 单房间 adapter：订阅成功才算启动、退避重连、token 提前刷新、停止/失败上限 |
| `scripts/kick-poc.mjs` | 真实采集：双房间、原始 payload + canonical 草稿 + summary、强制断线 |
| `scripts/kick-g1-analyze.mjs` | 身份/字段/唯一性/跨房间统计 |

设计取舍：

- **不引入 npm 依赖**：HTTP/2 与 WebSocket 都用 Node 内置。
- **不复制 kixo**：只借鉴「五条 feed / ping / TTL」等协议事实，代码自行编写。
- **聊天优先**：只有 chat 映射为 canonical event；礼物/订阅仅计数与留证，未验证前不建事件。
- **原文优先**：`content` 永不改写；Emote 只写元数据。
- **身份**：`kick:<sender.id>`；缺 ID 不建档案。

## 4. 真实运行

### 4.1 第一次 16 分钟双房间（主证据）

```
node scripts/kick-poc.mjs --rooms https://kick.com/odablock,gmhikaru \
  --minutes 16 --drop-at 300 --drop-room odablock --out tests/.tmp/kick-g1-run
```

- odablock：1,604 chat / 99.7 每分钟 / 391 stable ID / Emote 48.82% / reply 1.56%
- gmhikaru：332 chat / 20.6 每分钟 / 113 stable ID / Emote 13.25% / reply 19.88%
- 字段：`sender.id`、消息 `id`、`created_at` **100%**；时间全部带 `+00:00`
- 重复消息 ID 0；跨房间 0；Emote 解析失败 0
- 强制断开：5.7 秒恢复，空档 5.338 秒，重连 1 次
- 非聊天：封禁 5、解封 1、删除 5（未映射为产品事件）
- 跨房间同一 ID：1 个（在两个房间各发言，昵称一致）

### 4.2 事件发现运行（五条 feed）

第一次运行只订阅两条 feed，因此订阅/礼物事件必然收不到。补齐五条 feed 后重跑
（odablock + nelkboys，10 分钟，第 180 秒强制断开 nelkboys）：

- odablock：987 chat / 44.68% Emote / 赠送订阅 **1** 条（5 个接收者）/ Pin 3 / 封禁 1
- nelkboys：117 chat / 15.38% Emote / **KICKs 礼物 1** 条 / 删除 2；强制断开 5.3 秒恢复
- 真实形状：`KicksGifted.gift{amount:100,type:BASIC}`、`GiftedSubscriptionsEvent`
  只有 `gifter_username`/`gifted_usernames[]`（无稳定 ID）
- 榜单事件（`GiftsLeaderboardUpdated` / `KicksLeaderboardUpdated`）观测到但**刻意不消费**
- 订阅/续订、上下播、Host、投票仍未观测

## 5. 遇到的问题与处理

| 问题 | 处理 |
| --- | --- |
| `git checkout -b` 被 `.git/logs` 权限拒绝 | 用 Windows 文件权限修复脚本补齐当前用户权限（有备份与回滚命令），再建分支；未改文件内容 |
| `kick.com` HTTP/1.1 被 WAF 403 | 改用 `node:http2`；真实拒绝时 `KICK_BLOCKED`，不重试花招 |
| Centrifugo 推送是 `pub` 不是 `pubs` | 解析两种形状；第一批样本因此为 0，修正后正常 |
| 一门房间下播导致整轮退出 | PoC 改为记录 `startFailures` 并继续其他房间，退出码仍为失败 |
| 只订阅 `chatrooms.<id>.v2` 会漏礼物/订阅 | 订阅五条 feed；聊天仍只接受 `.v2` |
| token 45 分钟到期 | 提前 90 秒主动重连换新 token；同时处理 109/3500；单测覆盖 |
| Node 内置 WebSocket 不发 `Origin` | 实测抓包确认；当前 Kick 接受；列为 G2 风险 |
| 进程内测试 spawn EPERM | 用 `node --test --test-isolation=none`（仓库既有约定） |
