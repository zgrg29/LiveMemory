# P39 / I18N-M0 国际化基础架构整理

日期：2026-11-16
分支：`feature/p39-i18n-m0`（从 `main` / `a70321c` 创建）
版本基线：`0.14.0`（**未改版本号、未发布**）

## 1. 本轮目标与边界

按用户要求，把 LiveMemory 从「三语假设」架构升级为可扩展架构，**不新增任何语言**；
最终用户仍只能选择 `zh-CN` / `ja` / `en`。用户同时确定 P41 长期画像跨语言策略为**方案 B**
（允许混合语言事实、接受跨语言语义重复），本轮只记录，不改代码/DB/AI。

明确未改：五平台采集、AI 任务创建/批次/恢复、长期画像合并/去重/持久化、数据库 Schema、
原始弹幕保存、AI 输出语言设置与语义、翻译缓存业务语义、任何平台适配器。

## 2. 架构修改前后

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 语言清单 | 前端 `i18n.js`、后端 `locale.mjs`、`ai/constants.mjs`、`memory/constants.mjs` 各一份；翻译 `LOCALE_NAME`、`localeDisplayName`、四个下拉各写死三种 | **`src/shared/locales.mjs` 唯一来源**；Node 与浏览器 import 同一文件；AI/记忆/翻译/设置/Header/报告全部派生 |
| 归一化 | `zh*`→`zh-CN`、`ja*`→`ja`、`en*`→`en` 固定映射 | 精确码 → 语言族 region/script 匹配 → 默认语言；`available` 集合驱动 |
| 降级 | 只看语言族前缀；无法表达「未来 zh-TW 优先」 | `zh-HK` 当前 `zh-CN`，有 `zh-TW` 资源时自动 `zh-TW`；`pt-PT`→`pt-BR`；`in`→`id`；未知→`en` |
| 资源缺失 | 可能 404/白屏 | 服务端按真实字典文件收窄可选项；浏览器回退默认字典一次 |
| Header | `LANGUAGE_CHOICES` 固定三项 + `max-width:132px` | 由 `/api/bootstrap` 生成；≤3 短名称保持三段按钮，>3/长名称自动原生下拉；删除固定宽度 |
| AI/设置/报告下拉 | 各写死 `zh-CN/ja/en` | 同一列表生成，当前仍只有三项 |
| 启动器 | 独立三语消息表 | **保持原样**；测试强制语言码与注册表一致，未来统一方案记录在 I18N.md |

## 3. 实现要点

1. **`src/shared/locales.mjs`（新增）**
   - `LOCALE_REGISTRY`：`code` / `nativeName` / `englishName` / `language` / `script` / `regions` / `available`。
   - `DEFAULT_LOCALE='en'`、`AVAILABLE_LOCALES`、语言别名（`in`/`iw`/`ji`）、中文 region→script 提示。
   - `parseLocaleTag()`、`resolveLocaleTag()`、`localeDescriptors()`、`defaultLocaleFor()`、`localeDisplayName()`。
   - 纯 ES module，不依赖 Node API；浏览器路径 `/shared/locales.mjs`。

2. **`src/shared/locale.mjs`**
   - 保留原有导出与函数签名；`SUPPORTED_LOCALES` 改为注册表可用集合。
   - `normalizeLocale()` 校验「声明支持」；`resolveLocale(..., {available})` 负责「实际安装资源」降级；
     `detectSystemLocale()` 支持 `available` 参数。
   - 偏好、系统、资源三者分离；合法偏好不被资源缺失改写。

3. **`src/server/locale-resources.mjs`（新增）**
   - `detectInstalledLocales(webRoot)` 检查 `src/web/i18n/<code>.json`；全缺失时保留默认语言以避免
     语言控件为空。

4. **服务端**
   - `startServer()` 计算 `availableLocales` 并注入 deps；`/api/bootstrap` 增加
     `locales:{available,default,system}`；`effective.locale` 用真实资源解析。
   - `app.mjs` 仅暴露 `/shared/locales.mjs` 一个共享模块，其余 `src/shared` 不公开。

5. **浏览器**
   - `i18n.js` 删除第二份 `SUPPORTED_LOCALES`，直接 import 注册表；`loadDictionary` 缺失回退。
   - `language-control.js`（新增）统一渲染 Header；三种语言保持原视觉/交互，十种自动菜单。
   - `app.js` 从 bootstrap 取 `locales.available`；`initialLocale()` 用共享解析器。
   - 设置页、AI 输出语言、报告阅读语言全部由同一列表生成。

6. **AI / 记忆 / 翻译常量**
   - `src/ai/constants.mjs`：`SUPPORTED_LOCALES` 改为共享注册表；`promptVersionFor` 默认用 `DEFAULT_LOCALE`。
   - `src/memory/constants.mjs`：`SUPPORTED_MEMORY_LOCALES` 改为共享注册表。
   - `src/ai/translation/service.mjs`：`LOCALE_NAME` 由 `LOCALE_REGISTRY.englishName` 生成，
     输出字符串保持 `Simplified Chinese (zh-CN)` 等原格式。

7. **CSS**
   - 删除 `.language-select` 的 `max-width:132px` 与 `@media(max-width:420px)` 的 `112px`；
     `max-width:100%` + `flex:0 0 auto`。
   - 新增 `.language-control[data-mode="menu"]` 规则：十语言时隐藏三段按钮、显示原生下拉。

## 7. 遗留与风险

- 未新增七语言；十语言整体仍未完成。
- AI 输出语言仍是「默认取界面语言」且无独立持久设置（P41）。
- 启动器控制台仍三语独立消息表；本轮只对齐语言码（P40 决策）。
- 其他页面标签的固定宽度（112–260px）仍需 P40 十语言走查。
- 长期画像跨语言重复已由用户接受（方案 B），不是缺陷；P41 需补跨语言集成测试。
- 干净 Windows 账户、真实双击 UAC 仍未验证；EXE 自动化使用 asInvoker 功能副本。
