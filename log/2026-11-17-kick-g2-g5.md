## 1. G2 后台接入

- 新增 `src/platforms/kick/service.mjs`：`KickService` 负责 checkRoom/connect/disconnect/
  status/retention，错误码映射到可译 `errors.kick*` 键。
- `src/server/index.mjs`：构造服务、runtime/deps、shutdown、启动保留清理（platform `kick`）。
- `src/server/routes.mjs`：`/api/kick/{status,room,connect,disconnect,retention/apply}`，
  `/api/bootstrap.capabilities.platforms` 增加 `kick`（`mode=anonymous-centrifugo`、
  `unofficial=true`、`requiresLogin=false`、`requiresApiKey=false`）。
- 事件：`messages.mjs` 新增 KICKs / 赠订 / 订阅映射；adapter 只在非聊天事件上调用 mapper。
  - KICKs：`external_id=gift_transaction_id`、`sender.id` 身份、`amount_minor=NULL`、
    `currency=NULL`、`value_kind=unknown`，KICKs 数量/type/tier 只进 `amount_display`。
  - 赠订：赠送者一条 paid membership（数量=gifted_total），每位接收者一条 free membership；
    没有稳定 ID → 不建观众档案。
- 修复：`status()` 最初直接展开内部 recording，把 adapter/socket 带进 JSON 导致循环引用 500；
  改为只返回公开字段 + capture 摘要（集成测试新增活动房间断言）。

## 3. G4 真实长测

- 新增 `scripts/kick-g4-longrun.mjs`：启动真实产品服务器（独立数据目录），通过
  `/api/kick/connect` 接入真实房间，30 秒采样状态，结束用产品 API 停止并核对数据库。
- 第一次启动时 `status()` 500 导致脚本误判“没有活动房间”并连续接入 6 个房间；
  修复后重启（旧数据目录保留了那次 6 分钟的 5 个短 session，统计时已剔除）。
- 正式长测：70.2 分钟；kinocasinogaming 全程；odablock 下播后自动停止（03:19），
  paymoneywubby 03:19:48 替补接入。
  - 聊天 20,304 + 3,304 + 11,158 = **34,766**；字段 100%（ID/消息 ID/时间）
  - 观众 3,438 个稳定 ID；0 重复 `external_id`
  - 重连 7 次（3/3/1，平台侧断开自动恢复）
  - **真实 token 刷新 1 次**（03:59:37 UTC，`tokenRefreshes=1`，刷新前后均 `connected`，
    30 秒内继续收 17,442→17,587 条）
  - 111 KICKs（全部 sender.id，金额/币种 NULL）、41 membership（18 paid / 23 free，全部无 viewer_uid）
  - 停止后 live sessions 0、recordings 0

  REQUIRED_MODULES 与 embedded marker 加入 Kick 七个模块。
- 构建：`dist/LiveMemory.exe` Build ID `5314bd79a0f3`、99,329,024 B；
  `dist/LiveMemory-asInvoker.exe` 同 Build ID、同源、asInvoker。
- 新增 `scripts/verify-kick-exe.mjs`：真实 EXE 启动 → 会话认证 → bootstrap → 真实房间双开 →
  真实聊天/身份/历史/AI 入口/停止/十语资源/五平台仍在。**19/19**。
- 遇到的问题：
  - `--port 0` 在启动器中不可用 → 改用固定端口 48400；
  - bootstrap token 的参数名是 `lm_bootstrap` 而非 `token`；
  - `top-viewers` 的 `platformUid` 不含 `kick:` 前缀，身份判断改用 `viewerId`；
  - 真实双击 UAC 无法自动化，使用同 Build ID 的 asInvoker 副本并在文档中如实说明。
