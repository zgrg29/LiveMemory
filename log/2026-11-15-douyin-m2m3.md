## 4. 抖音协议验证（先验证，再写适配器）

### 4.1 实测路径

1. `GET https://live.douyin.com/708764876300` → 200，1.4 MB HTML。
   页面含 `roomStore.roomInfo.room.id_str`、`status=2`、`title`、`anchor.id_str/sec_uid/nickname`、
   `web_rid`、`user_unique_id`。
2. 不带 `signature` 直接连 `wss://webcast…/webcast/im/push/v2/` → **close 1006**，确认签名必需。
3. 用 vendored `sign.js`（`node:vm` + `navigator.userAgent`）：
   `signature = get_sign(md5(<逗号参数串>))`，参数串含
   `room_id / user_unique_id / webcast_sdk_version / device_platform=web / identity=audience`。
4. 带 `signature` + `Cookie: ttwid=…` 连接 → **OPEN，31 帧/12 秒**。
5. 帧是 Blob → `arrayBuffer()` → `PushFrame` → 找 `1f 8b` → `gunzip` → `Response` → `Message[]`；
   方法名包含 `WebcastChatMessage`、`WebcastGiftMessage`、`WebcastMemberMessage`、`WebcastLikeMessage` 等。
6. 20 秒真实采集：7 chat（7/7 UID/昵称/消息 ID/CJK、0 重复）、144 member、4 like、2 follow、
   3 room stats、0 gift。

### 4.2 关键实现决定

- **自研 protobuf**：不引入 protobufjs/pako；varint/length/fixed、嵌套消息、未知字段跳过、
  `uint64` 用 BigInt 保留 19 位 ID 精度；编码只用于心跳/ack。
- **gzip**：`node:zlib.gunzipSync`；帧头 `compress_type=gzip` 或魔数兜底。
- **WS 头**：Node 24 内置 `WebSocket` 支持非标准 `{headers}`（本地 handshake 服务器验证 Cookie/UA 确实发出），
  因此不需要 `ws` 依赖，SEA 兼容。
- **签名脚本**：AGPL-3.0，独立 `vendor/` 目录，`node:vm` 无文件/网络/进程能力；失败报
  `DOUYIN_SIGNATURE_FAILED`，不伪造、不降级为未签名。
- **礼物只写最终态**：`repeatEnd=1` 才写一条；`groupId` 合并；数量取最大值；TTL 丢弃未完成连送。
  这避免“每个中间步骤都计费”的重复计算。
- **金额**：`amount_minor=null`、`currency=null`、`value_kind=unknown`；钻石合计只写
  `amount_display="N 抖音币"`；没有钻石数时为 `null`，不写 0。

### 4.3 登录调查

- `GET https://sso.douyin.com/get_qrcode/?aid=6383&service=…` → 200 `text/html`，
  返回带 `gfkadpd` 的验证/风控脚本页，不是 JSON。
- `GET https://www.douyin.com/passport/web/get_qrcode/` → JSON
  `{"data":{"error_code":4031,...},"message":"error"}`（访问被阻止）。
- 2026 年网页登录还涉及 device fingerprint challenge、ticket-guard P-256 密钥交换、
  `sdk_source_info` 与 `a_bogus`/TLS 指纹；纯 HTTP 无法稳定完成，且不能绕过验证码/风控。
- 结论：实现受控扫码流程与错误分类，但**不宣称登录成功**；提供显式的本地 Cookie 备用入口
  （用户主动选择、AES-GCM 本地保存、不上传），并在 UI/文档写明风控限制。

### 4.4 AGPL 决策

- 上游 `saermart/DouyinLiveWebFetcher` 为 AGPL-3.0；dyhub `third_party/douyin-sign` 明确引用。
- Vendored `sign.js` 与 dyhub `main` 逐字节一致：`81fb78a5…`。
- 只随包分发 WebSocket 签名所需的 `sign.js`；上游 `a_bogus.js` **未分发**（本产品不调用），
  以减少不必要的 AGPL 代码面。
- 主项目 `LICENSE` **未改**；`vendor/` 单独 AGPL + 完整许可证 + `THIRD_PARTY_NOTICES.md` +

## 6. 实现过程中发现并修正的缺陷

1. **房间状态解析为 null**：页面有多个序列化 chunk，首个 `roomStore` 不一定是当前房间。
   改为先用 `web_rid` 定位 chunk 取 `roomId`，再用 `"id_str":"<roomId>","status":N` 精确匹配状态/标题/在线数。
2. **`broadcaster_id` 为 null**：`roomView` 返回 `anchorUid`，服务却读 `room.anchorId`。
   统一为 `room.anchorUid ?? room.anchorId ?? room.roomId`。
3. **礼物没有进入 adapter**：`mapDouyinMessage` 对 Gift 返回 unknown，adapter 未单独处理。
   在 `#handleMessage` 中对 `WebcastGiftMessage` 走 `ingestGift`（连送合并）。
4. **测试消息 ID 非数字**：抖音 `msgId` 是 int64，测试不能用 `chat-1`；改为 18 位数字字符串。
5. **AI 包不含 gift 行**：`messages.jsonl` 只含 chat/super_chat；礼物保留在本地支付表。
   测试改为断言“礼物不混入聊天 JSONL + 数据库有 gift 行”。
6. **监控错误被归为 UNKNOWN**：fake client 抛普通 Error；detector 只在 `isAppError` 时映射。
   改为始终按 `error.code` 映射。
7. **EXE API 不返回 `externalId`**：验证脚本错误地断言 API 字段；改为 API 断言 UID/昵称/原文/质量，
   消息 ID 由 SQLite 断言。
